# 接続とエージェントの配置・書き込みの安全の穴を塞ぐ判断

## Context

レビューで、Agent が既存の symlink のリンク先を書き換えること、別の鍵種別でだけ known_hosts に登録されたホストの鍵や承認後の再接続の鍵を確認なしに信頼すること、他人が置き換えられる配置先の Agent のバイナリを実行することが見つかった。
IR は未知のホスト鍵の扱い（[REQ-ssh-001](../../ir/ssh/host-key.md#REQ-ssh-001)、[REQ-ssh-002](../../ir/ssh/host-key.md#REQ-ssh-002)）と Agent を使えないときの扱い（[REQ-ssh-005](../../ir/ssh/fallback.md#REQ-ssh-005)、[REQ-ssh-009](../../ir/ssh/sudo.md#REQ-ssh-009)）しか定めておらず、known_hosts を読めないとき、失効とされた鍵、Agent の配置先の検査を決めていない。
ここでその規則を決め、既存の要件から導かれる選択とあわせて残す。
Agent の配置の安全の制約を IR に書くことと [A31（Agent の方式とデプロイ手順を IR に含めない）](./2026-09-25-spec-migration.md#A31) との関係は A7 で決める。

## Agreements

- A1 known_hosts がないこと以外の理由で known_hosts を読めないとき（UTF-8 として不正な内容、読む権限がないなど）、接続を止め、--yes や strict_host_key_checking=no を指定していても未知のホストとして扱わない。
  - why: 読み込みの失敗を「ファイルがない」と同じにすると、鍵が変わったホストが未知のホストになり、--yes で受け入れられてしまう。
  - decided_by: 利用者（2026-10-05、計画の承認による）
- A2 known_hosts で "@revoked" として失効とされた鍵は、--yes や strict_host_key_checking=no を指定していても受け入れず、接続を止める。対象は今の照合が一致と判定するホストの書き方（平文、カンマ区切り、ハッシュ形式）の行だけで、"*" などのワイルドカードは今の照合と同じく扱わない。同じ鍵が通常の行にもあるときは失効を優先する。
  - why: 失効の印は利用者がその鍵を信頼しないと明示したもので、自動承認の指定で覆すと失効の意味がなくなる。
  - decided_by: 利用者（2026-10-05、計画の承認による）
- A3 Agent の配置先のディレクトリがなければ所有者だけが読み書き・実行できるモード 700 で作る（sudo=true では既存の配置のコマンドと同じく sudo で作る）。配置先のディレクトリが symlink であるとき、所有者が SSH のセッションの "id -u"（sudo=true では 0、つまり root）でないとき、グループかその他が書き込めるときは、版の確認を含めてその中のものを何も実行せず、Agent を起動できない既存の扱いに乗せる（sudo=false では SSH の経路で続け、sudo=true では止まる）。所有者は設定のユーザー名とは比べない。
  - why: 他人が書き込める場所や他人の持ち物の中のバイナリを実行すると、他人の用意したプログラムが利用者の権限で動く。版の確認もそのバイナリを実行するので、検査はそれより前に置く。設定のユーザー名とログイン後の uid は一致するとは限らないため、実際に動くセッションの uid と比べる。
  - decided_by: 利用者（2026-10-05、計画の承認による）
  - superseded_by: [A11（他人が書き込めた自分の配置先は直して置き直す）](#A11)
- A4 配置先のバイナリの版が一致しても、ローカルの Agent のバイナリを解決できたときはそれと SHA-256 を照合し、一致しないとき、またはリモートでハッシュを計算できないときは、置かれたバイナリを実行せず版が違うときと同じ配置の経路で置き直す。ローカルのバイナリを解決できないとき（リモートのターゲット用のバイナリが手元にない、大きさの上限を超えるなど）は照合できないので、A3 の検査を通ったことだけを根拠に今までどおり実行する。拒否したときは A3 と同じく Agent を起動できない既存の扱いに乗せ、新しい文言や終了コードは決めない。
  - why: 版の出力は偽装できるので、版の一致だけでは置かれたバイナリが手元のものと同じだと言えない。解決できないときに実行を止めると、利用者が手で置いた Agent が使えなくなる。
  - decided_by: 利用者（2026-10-05、計画の承認による）
  - superseded_by: [A8（リモートでハッシュを計算できないときは警告して実行する）](#A8)
- A5 同じホストが known_hosts に別の鍵種別でだけ登録されているとき、提示された鍵は known_hosts で確かめられていないので、未知の鍵として扱う。strict_host_key_checking=yes や確認の手段がないときは止まり、--yes や strict_host_key_checking=no では承認できる。
  - why: [REQ-ssh-001](../../ir/ssh/host-key.md#REQ-ssh-001) は確かめられていない鍵を無確認で信頼することを禁じ、[REQ-ssh-002](../../ir/ssh/host-key.md#REQ-ssh-002) は明示した自動承認を認める。別の種別の登録は提示された鍵を確かめる材料にならないので、未知の鍵の扱いがそのまま当てはまる。拒否にすると、正しく鍵を追加したい利用者が承認する道もなくなる。
  - decided_by: 利用者（2026-10-05、計画の承認による）
- A6 Agent は、最後の要素が既存の symlink であるパスへ通常ファイルを書かずエラーにし、リンクもリンク先も変えない。symlink の作り直しはリンクそのものを消して作り、リンク先を消さない。そのエラーで製品側が Agent を使えないものとして扱い、sudo=false では SSH の経路へ移り、sudo=true では止まる既存の扱いを受け入れる。
  - why: リンクを通常ファイルに置き換えるのは [REQ-merge-001](../../ir/merge/symlink.md#REQ-merge-001) が禁じる種類の変更で、リンク先へ書くのは書き込み先の外を変える。残る選択はエラーだけである。symlink の作り直しは [REQ-merge-003](../../ir/merge/symlink.md#REQ-merge-003) のとおりリンクそのものに行う。SSH の経路の書き込みが symlink を辿る問題は別に扱う。
  - decided_by: 利用者（2026-10-05、計画の承認による）
- A7 [A31](./2026-09-25-spec-migration.md#A31) が IR に含めないとしたデプロイ手順から、Agent の配置の安全の制約（配置先でどの条件のときに何を実行しないか、配置先をどう作り直すか）を除き、それらは IR の要件として書く。転送の方式、通信の版、配置のコマンドの並びと形は今までどおり IR に含めない。
  - why: 安全の制約は方式によらず利用者の SSH のセッションで何が動くかを定めるもので、利用者が頼る約束である。手順の一部として IR の外に置くと、守られているかを要件として確かめられない。
  - decided_by: 利用者（2026-10-05、レビュー後の判断 F5）
- A8 配置先のバイナリの版が一致しても、ローカルの Agent のバイナリを解決できたときはそれと SHA-256 を照合し、一致しないときは置かれたバイナリを実行せず版が違うときと同じ配置の経路で置き直す。リモートでハッシュを計算できないとき（sha256sum も shasum もない）は、ローカルのバイナリを解決できないとき（リモートのターゲット用のバイナリが手元にない、大きさの上限を超えるなど）と同じく照合できないので、A3 の検査を通ったことだけを根拠に実行する。ハッシュを計算できないときは、照合せずに実行することを接続ごとに一度、利用者に警告する。拒否したときは A3 と同じく Agent を起動できない既存の扱いに乗せ、新しい文言や終了コードは決めない。
  - why: 版の出力は偽装できるので、ハッシュを取れるときは中身の一致まで求める。ハッシュを取れないサーバで置き直しにすると、接続のたびに Agent を転送し直すうえ置き直した後の照合もできず、安全を増やさずに遅くなるだけである。照合していないことは利用者が知るべきなので警告する。
  - decided_by: 利用者（2026-10-05、レビュー後の判断 F4）
- A9 Agent の配置先のディレクトリの祖先を、書かれたパスと symlink を解決した実際のパスの両方で根まで確かめ、グループかその他が書き込めて sticky bit のない祖先が一つでもあれば、A11 の検査に当たったときと同じく、版の確認を含めて配置先の中のものを何も実行せず、Agent を起動できない既存の扱いに乗せる。祖先の symlink そのもののモードは見ず、その親と解決した先を見る。sticky bit のある祖先（/var/tmp や /tmp など）は書き込めても受け入れる。
  - why: 配置先の親を他人が書き換えられると、検査の後の版の確認・ハッシュの照合・起動の別々の実行の間に配置先を名前ごと差し替えられ、他人の用意したプログラムが利用者の権限で動く。sticky bit のあるディレクトリでは、他人は自分の持ち物でない項目の名前を変えたり消したりできないので差し替えられない。「他人」は A11 の配置先そのものの検査と同じくグループとその他の両方を指す。
  - decided_by: 利用者（2026-10-05、レビュー後の判断 F1。「他人」をグループとその他の両方とする読みはその後の確認による）
  - superseded_by: [A13（辿るすべてのディレクトリの所有者とモードを確かめる）](#A13)
- A10 配置先のディレクトリを作るときに途中の親ディレクトリもなければ、それらも所有者だけが読み書き・実行できるモード 700 で作る。
  - why: 途中の親を umask に任せて作ると、umask が 002 の利用者ではグループが書き込める親ができ、A9 で配置先が二度と使えなくなる。新しく作るものを所有者だけのモードにすれば、A3 の新しく作る配置先と同じ考えで A9 を満たせる。
  - decided_by: 利用者（2026-10-05、レビュー後の判断 G3）
- A11 Agent の配置先のディレクトリがなければ所有者だけが読み書き・実行できるモード 700 で作る（sudo=true では sudo で作る）。配置先のディレクトリが symlink であるとき、または所有者が SSH のセッションの "id -u"（sudo=true では 0、つまり root）でないときは、版の確認を含めてその中のものを何も実行せず、Agent を起動できない既存の扱いに乗せる（sudo=false では SSH の経路で続け、sudo=true では止まる）。所有者は設定のユーザー名とは比べない。所有者が一致してグループかその他が書き込めるとき（A9 の祖先の検査に当たらないときに限る）は、配置先をモード 700 に直し、中にある Agent のバイナリと書き込み途中のファイルを実行せずに除き、版の確認をせずに版が違うときと同じ配置の経路で Agent を置き直し、直した配置先のパスを示す警告を利用者に表示する。
  - why: 前の版が umask 002 のもとで作った配置先はグループが書き込めるため、A3 のままでは Agent が黙って使われなくなる。自分の持ち物なら所有者だけのモードに直せるが、直す前に他人が中身を置き換えられたので、中のものは版の確認も含めて実行せずに置き直す。利用者が知らないうちにモードが変わらないよう警告する。
  - decided_by: 利用者（2026-10-05、レビュー後の判断 F3。置き直す前に Agent のバイナリと書き込み途中のファイルを除くことはその後の確認による）
- A12 sudo=true のサーバでは、配置先のディレクトリの作成と検査、配置済みのバイナリの版の確認とハッシュの計算、書き込み途中のファイルへのバイナリの書き込みと、書き込んだ後の照合を、既存の配置のコマンドと同じく sudo で実行する。
  - why: sudo=true の配置先は root の所有のモード 700 でなければならず（A11）、SSH の利用者の権限ではその中を読むことも書くこともできない。sudo なしでは自動の配置が成功せず、sudo=true では SSH の経路にも移れないので接続が止まる。
  - decided_by: 利用者（2026-10-05、レビュー後の判断 F2）
- A13 Agent の配置先のディレクトリへ辿るすべてのディレクトリを確かめる。対象は、配置先の親から根までの書かれたパスの各段、symlink を解決した実際のパスの各段、途中の各 symlink のリンク先とその各段（リンク先がさらに symlink なら、それも同じく辿る）である。そのどれかが、グループかその他が書き込めて sticky bit のないディレクトリであるとき、または所有者が root でも SSH のセッションの "id -u"（sudo=true では 0、つまり root）でもないディレクトリであるとき、A11 の検査に当たったときと同じく、版の確認を含めて配置先の中のものを何も実行せず、Agent を起動できない既存の扱いに乗せる。symlink そのもののモードと所有者は見ず、それを置いたディレクトリとリンク先を見る。sticky bit のあるディレクトリ（/var/tmp や /tmp など）は書き込めても受け入れる。「他人」はグループとその他の両方を指す。
  - why: 配置先へ辿る途中のディレクトリを他人が書き換えられると、検査の後の版の確認・ハッシュの照合・起動の別々の実行の間に、配置先やその途中を名前ごと差し替えられ、他人の用意したプログラムが利用者の権限で動く。モードで他人が書き込めなくても、ディレクトリの所有者はモードを変えて中の名前を差し替えられるので、所有者も root かセッションの利用者に限る。書かれたパスと最後に解決したパスだけを見ると、symlink の連なりの途中のリンクを置いたディレクトリが見落とされる。
  - decided_by: 利用者（2026-10-05、レビュー後の判断 G1 / G2）
- A14 sudo=false のサーバで、A11 の配置先そのものの検査か A13 の辿るディレクトリの検査に当たって Agent を使わずに SSH の経路で続けるときは、安全でないと判定した配置先のパスを示す警告を利用者に表示する。文言は決めない。sudo=true では今までどおり止まり、その理由をエラーとして示す。
  - why: 黙って SSH の経路に移ると、利用者は Agent が使われない理由に気づけず、配置先を直す機会がない。
  - decided_by: 利用者（2026-10-05、レビュー後の判断 G3）
