# CLI diff に root_dir を指すパスを渡したときの判断

## Context

CLI diff の差分の出し方のテスト整理で、パスに "."・"./"・空の値・"/" を渡すと変更があってもファイルを一つも出さず終了コード 0 を返すと確かめたとして、FLAG-cli-040 に残し、テスト整理の後に直すことにした（[A23](./2026-09-29-adopt-diff-output.md#A23)）。
直す前に確かめ直すと、その確認と同じ製品コードで、execute_diff を呼ぶ契約テストでも、試験 SSH サーバに対して起動した実行ファイルでも、これらのパスはパスなしと同じく root_dir 全体を比べ、変更のあるファイルを出して終了コード 1 を返した。先の確認で違う結果になった原因は分からない。
挙動は正しく、[REQ-cli-052](../../ir/cli/diff-output.md#REQ-cli-052) に書かれていないことだけが残っているため、要件に書き足して FLAG-cli-040 を外す。

## Agreements

- A1 diff は指定したパスに "."・"./"・空の値・"/" のどれかがあるとき、パスを指定しないときと同じく root_dir 全体を比べる。
  - why: 現行実装のとおりで、確かめ直した契約テストと実行ファイルの両方でそうなった。merge・sync の走査の範囲（TBL-scan-001）も "."・"./"・空の値のどれかがあれば root_dir 全体とし、パスの解決も同じ扱いをしているため、diff だけ別の意味にする理由がない。
  - rejected: root_dir を指すパスをエラーにする案。merge・sync と扱いが食い違い、今の挙動を変えることになる。
  - decided_by: 利用者（推奨を採用）

## Undecided

- U1 走査の範囲の要件（docs/ir/scan/limits.md の diff の走査の範囲）に、root_dir を指すパスを渡した diff も root_dir 全体を走査することを書き足すか。
  - decides: 利用者（scan のトピックを次に扱うとき）
