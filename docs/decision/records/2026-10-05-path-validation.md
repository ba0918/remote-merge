# パスの検査を経路と走査方式によらず揃えるときの読み方

## Context

diff・merge・sync の引数の検査と rollback の書き戻す前のパスの検査が、ローカル・SSH・エージェントの経路と走査方式によって違う結果を返していた。
[2026-10-05-quality-cli.md の A1](./2026-10-05-quality-cli.md#A1)、[2026-10-05-quality-merge.md の A1](./2026-10-05-quality-merge.md#A1)、[2026-10-05-quality-backup.md の A2](./2026-10-05-quality-backup.md#A2) で揃える方向は決まったが、実装するには IR が直接決めていない読み方がいくつか要る。
この記録は、それを揃える計画の承認（2026-10-05）で確定した読み方を残す。

## Agreements

- A1 書き戻し先のパスの祖先にリンク切れの symlink があり、その下のパスを検査するときは、[REQ-backup-003](../../ir/backup/rollback-path.md#REQ-backup-003) の「リンク先を辿れない」と読み、どの経路でもセッション全体を "cannot resolve path: " で止める。
  - why: ローカルとエージェントの経路は既にこう振る舞い、書き戻さない安全な側である。[REQ-backup-033](../../ir/backup/rollback-path.md#REQ-backup-033) の「リンク切れの symlink」は、戻す先そのもの（末尾）の symlink の例として書かれている。
  - decided_by: 利用者（計画の承認）
- A2 [2026-10-05-quality-backup.md の A2](./2026-10-05-quality-backup.md#A2) のスキップは、戻す先の検査が失敗し、戻す先より上の祖先（root_dir は除く）のどれかが辿った先で通常ファイルだと分かったときに出す。すぐ上の親が通常ファイルに変わったときのほか、祖父より上の祖先が通常ファイルに変わったときと、親や祖先が通常ファイルを指す symlink になったときも含む。
  - why: どの場合も祖先が通常ファイルか通常ファイルを指す symlink になっており、祖先が消えたときと同じく何も書き戻さない結果になる。スキップはこの二つに限り、祖先がディレクトリでなくなった場合のすべてには広げない。祖先が FIFO・デバイス・ソケットか、それらを指す symlink になったときと、祖先がリンク切れの symlink のとき（A1）は、[REQ-backup-003](../../ir/backup/rollback-path.md#REQ-backup-003) のとおり "cannot resolve path: " で止める。計画の承認（2026-10-05）では、IR が決めていなかった二つの場合（祖父より上の祖先が通常ファイルに変わったとき、親や祖先が通常ファイルを指す symlink になったとき）を "cannot resolve path: " で止める今の振る舞いのまま残し、スキップをすぐ上の親が symlink でない通常ファイルのときに限っていたが、利用者が 2026-10-06 にこの範囲へ広げた。
  - decided_by: 利用者（2026-10-06）
- A3 祖先が通常ファイルかは、ローカルでは辿った先の metadata、SSH では `[ -f パス ]` の答えを出力で返す短いコマンド、エージェントでは既存の StatFiles が返す st_mode の種類のビットで調べる。どの経路でも、調べられなかったときは通常ファイルと分からないものとして扱い、スキップに切り替えない。
  - why: エージェントの crate と通信の型を変えずに三つの経路で同じ判定にできる。StatFiles は、パスが存在するときは root_dir の検証のために辿った先の実パスを求め、その実パスの lstat を返すので、symlink の祖先でも辿った先の種類が返る。調べられないときにスキップにすると、辿れないパスを含むセッションを止める [REQ-backup-003](../../ir/backup/rollback-path.md#REQ-backup-003) を弱める。既知の例外として、StatFiles は辿った先の実パスが root_dir の外にあるパスを拒否する。そのため、root_dir の外を指す symlink の祖先や、その下にある祖先は、エージェントの経路だけ調べられず、ローカルと SSH の経路ではスキップになる場合でも "cannot resolve path: " で止まる。どちらも書き戻さない側である。エージェントのエラーの扱いを直す後の作業（次のリリースの前）で解消するまで、この違いを残す。
  - decided_by: 利用者（計画の承認。調べ方は実装者が計画の範囲で選んだ。既知の例外を残すことは 2026-10-06 に利用者が判断した）
  - superseded_by: [2026-10-06-path-resolution.md の A7](./2026-10-06-path-resolution.md#A7)
- A4 経路ごとの境界の検査は、SSH の経路のパスの組み立てで先頭の "/" を削る読み替えを拒否に変えることと、検査のなかった SSH の経路の子の一覧に同じ検査を足すことに限り、新しい分岐は作らない。
  - why: 引数の検査の後には利用者の入力が境界に届かないため、境界の検査は多層の防御であり、既存の検査を引数と同じ関数に置き換えれば足りる。
  - decided_by: 利用者（計画の承認）

## Revisions

- 2026-10-06: A3 の祖先が通常ファイルかを別に問い合わせる調べ方は、パスの確認の結果に途中の祖先がディレクトリでないことを返す [2026-10-06-path-resolution.md の A7](./2026-10-06-path-resolution.md#A7) に置き換わった。エージェントだけ調べられない既知の例外もなくなる。
