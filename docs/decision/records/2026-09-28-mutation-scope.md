# 変異テストを回す範囲とタイミングを絞る判断

## Context

トピックごとのテスト整理では、[テスト手法の選び方の A5](./2026-09-27-test-method-selection.md#A5) に従い、最初と最後にトピックのファイルに絞って変異テストを回してきた。
一回の実行が 40 分前後かかり、整理前・整理後・回し直しで一つのトピックに 2〜3 回回すため、作業の大半が待ち時間になっていた（merge の取り込みで利用者が指摘した）。
merge の symlink と削除の整理では、利用者の了承のもとで "scripts/mutants.sh" に関数で絞る指定を足し、整理後の実行を決着の対象の関数に絞った（144 件から 57 件、約 36 分から約 14 分）。
その了承を仕様として残し、テストを削除しない整理で最初の実行を省く扱いも決める。

## Agreements

- A1 トピックごとのテスト整理の変異テストは、トピックのファイルの中でも、見逃しを決着させる対象の関数に絞って回してよい。対象外の関数の見逃しは、最後にそのファイルを回したときの記録のまま扱う。
  - why: 対象外の関数の変異は、その整理で書き足すテストでは決着しないため、回しても待ち時間だけが増える。
  - decided_by: user
- A2 テストを削除しない整理では、最初の変異テストを省いてよい。最後の実行の見逃しは、そのファイルを前に回したときの記録と比べる。
  - why: 最初の実行の主な役目は、削除の前後で見逃しが増えないかを比べることで、削除しない整理ではその比較が要らない。
  - decided_by: user
- A3 "scripts/mutants.sh" は、ファイルの前に書いた `--re <正規表現>`（繰り返し可）を cargo-mutants に渡し、変異の名前がその正規表現に一致するものに絞って回す。cargo-mutants 27.1.0 では構造体のフィールドを消す変異がこの絞り込みで除かれないため、絞った実行の結果にはそれらが混ざりうる。
  - why: 関数で絞る手段がスクリプトになければ A1 を実行できない。除かれない変異があることは実行で確かめた事実で、結果を読む人が混ざった変異を見逃しと取り違えないように残す。
  - decided_by: user
