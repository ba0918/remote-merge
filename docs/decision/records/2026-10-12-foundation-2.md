# 土台の段 2: 走査を一つの規則にする

## Context

[土台の作り直し](./2026-10-12-foundation.md) の段 2 である。走査は三つの経路に別々の実装があり、exclude・include・件数・UTF-8 でない名前・循環・root_dir や部分パスがないときの判定を、それぞれが自分で決めていた。IR も、同じ規則を要件ごとに「ローカル・SSH・エージェントのどの経路でも」と繰り返し、経路の差を FLAG（FLAG-config-016・FLAG-scan-002・FLAG-scan-007・FLAG-scan-016）に残していた。[foundation A10](./2026-10-12-foundation.md#A10) のとおり、実装の前に IR を経路によらない文に書き直す。

Position: 段 2 は終わった（C1〜C15）。走査で見つけた範囲外の二つは後の段で扱う。FIFO・ソケットなどの特殊なファイルを通常ファイルとして一覧に載せる件は、比べる流れで読みに行く段 4 で、BusyBox の find だけのサーバで SSH の走査が動かない件は、どのサーバで動くかを要件にする段 3 で決める。

## Agreements

- C1 走査の結果（一覧・不完全の報告・エラー）が経路によらないことを、一つの要件にまとめる。個々の要件からは「ローカル・SSH・エージェントのどの経路でも」を外す。経路で変わりうることは、道具の限界で揃えられないと確かめたものだけを FLAG に残す（今は FLAG-scan-015 の秒しか出さない find の更新時刻だけ）。
  - why: 同じ規則を要件ごとに繰り返す書き方は、経路ごとに実装を書く構造を写していた。
  - decided_by: 利用者（[foundation A10](./2026-10-12-foundation.md#A10) から導いた。自走の指示により書き下ろした）
- C2 走査は、起点（root_dir 全体、または指定したパス）が何であっても、exclude と include を root_dir からの相対パスに当てる。merge・sync のパスの指定で親ディレクトリの下だけを走査するときも同じにする。[FLAG-scan-007](../../ir/scan/FLAGS.md#FLAG-scan-007) はこれで閉じる。
  - why: [REQ-config-021](../../ir/config/filters.md#REQ-config-021)・[REQ-config-022](../../ir/config/filters.md#REQ-config-022) は root_dir からのパスに当てると決めており、走査の範囲で当て方が変わるのは誤りだった（include の外や除外したディレクトリの下に書き込む）。
  - decided_by: 利用者（[foundation A3](./2026-10-12-foundation.md#A3) と 2026-10-05 の品質の基準から導いた。自走の指示により書き下ろした）

- C6 走査の規則（exclude・include・件数・UTF-8 でない名前・循環・辿るか・読めないときに止めるか）は一つの純粋な関数群に置き、経路は生の項目（名前のバイト列・種類・大きさ・更新時刻・権限・リンク文字列・デバイス番号と inode 番号）を集めるだけにする。ローカルとエージェントは同じ集め方を使う（エージェントはリモートのマシンの上のローカルである）。SSH は find の出力を同じ生の項目に訳す。
  - why: 規則を一か所に置けば、経路の差は生の項目の集め方にしか生まれず、そこは生の項目の比較で確かめられる。

  - why: 項目ごと・ディレクトリごとに尋ねると SSH の往復で使えない速さになる。

- C14 SSH の経路の集め方は、ディレクトリを読めるか・検索できるかを find の知らせから推し量らない。走査の find が出会ったディレクトリ（起点と、リンクを辿った回の起点を含む。刈り込んだものは除く）を、find 自身の `-type d -exec sh -c … {} +` でシェルの `[ -r ]`・`[ -x ]` に確かめさせ、読めて検索できないディレクトリはその場で glob で子の名前を集める。glob が当たらずにパターンの文字列が返ったときは、一文字を [] で囲んだ glob でその名前の子があるかを確かめて見分ける。exclude を当てて扱いを決めるのは規則の側である。find の知らせは、確かめた結果と照らし合わせるためだけに使い、合わない知らせと読み取れない知らせは走査の誤りにする。
  - why: findutils 4.4.2 は読めて検索できないディレクトリに子があっても何も知らせず、知らせに頼ると子のないディレクトリとして載せて握りつぶし、経路で結果が変わっていた。知らせを受けたディレクトリをまとめて別に確かめる形は、引数の長さの上限で失敗していた。find の `-exec … {} +` なら、まとめる単位の分け方を find が受け持ち、数に上限がない。
  - decided_by: 利用者（2026-10-13、段 2 の 2 回目のレビューの直し方の方針）
  - 確かめは、項目を一覧にする find と同じ 1 回の find の中で行う（`\( -type d -printf … -exec sh -c … {} + \) -o -printf …`）。部分木を 2 回たどらない。確かめた結果は標準エラーに、NUL で区切った目印付きの記録（目印・自分のパス・読めるか検索できるか・子の名前・終わりの目印）で出す。find の知らせは NUL を含まないので見分けられ、出る順には頼らない。形の壊れた記録は走査の誤りにする。
  - 一覧に出したディレクトリ（起点を含み、刈り込んだものは除く）は、どれも確かめた結果を一つずつ持たなければならない。結果が欠けたディレクトリ・二度出たディレクトリ・一覧にない結果は、どれも走査の誤りにする。確かめの sh が途中で失敗しても、確かめていないディレクトリを読めて検索できるものとして扱わない。
  - find の終了コードと標準エラーを読み、/dev/null に捨てない。`-exec … {} +` で動かした sh が失敗すると、find の終了コードは 0 でなくなる（findutils 4.2.27・4.4.2・4.9.0 で確かめた）。終了コードが 0 でなく、確かめた結果で説明できる知らせが一つもないときは、走査の誤りにする。説明できない知らせは、終了コードによらず走査の誤りにする。
  - why: 1 回目の形は、確かめを部分木を 2 回目にたどる find で行い、その標準エラーを捨てて終了コードを読んでいなかった。確かめが途中で失敗すると、結果のないディレクトリを読めて検索できるものとして載せていた。2 回たどる分、部分木の走査も最大で約 3 倍遅かった。
  - decided_by: 利用者（2026-10-13、段 2 の 3 回目のレビューの直し方の方針）
  - 一覧に載せたディレクトリを読みに行ったら、もうない、あるいはディレクトリでなくなっていたときは、どの経路でも走査の途中で変わったもの（ChangedDuringScan）にする。集め方はその事実を答え（Subtree の changed）で返し、走査の途中で変わったと決めるのは規則の側である。SSH の確かめの記録は `[ -d ]` が偽なら "G" を返し、ローカルとエージェントの集め方は読みに行って NotFound か NotADirectory が返ったものをこの答えにする。
  - why: 確かめの間にディレクトリが消えると、SSH は読めない（PermissionDenied）、ローカルは読めない（Other）として止まり、理由を取り違えたうえ経路で誤りが違った（REQ-scan-017）。
  - decided_by: 利用者（2026-10-13、段 2 の 4 回目のレビューの直し方の方針）
  - find が子を一つも出さなかったのに、確かめで読めて検索できると答えたディレクトリは、本当に空かを、リンクを辿る回と同じくまとめてもう一度尋ねる（find の版では分けない）。尋ね方は確かめと同じ glob の方式で、`.` で始まる名前も含めて子の名前を集める。exclude に当たらない子が見つかった・もうないか読めないか検索できないときは、走査の途中で変わったものにし、空と確かめられたら空のまま載せる。もう一度の答えも、尋ねたディレクトリと一つずつ対応しなければならず、欠け・二度・尋ねていない答え・知らせ・0 でない終了コードは走査の誤りにする。空に見えるディレクトリがあるときだけ一往復増え、コマンド行が長くなるときは問いと同じ分け方で分ける。
  - why: findutils 4.4.2 は検索できないディレクトリの子を知らせずに出さないので、find が通った後で確かめの前に検索できるようになると、子のあるディレクトリが空として載り、`sync --delete` が反対側を消しうる。find の中で `-readable` などで判定しても、判定と降りるあいだに同じ窓が残る。
  - decided_by: 利用者（2026-10-13、段 2 の 4 回目のレビューの直し方の方針）
  - 一覧に出た項目の情報を取りに行ったら、もうなかったときも、ディレクトリのときと同じく、どの経路でも走査の途中で変わったものにする（exclude の下は見ない）。集め方はその項目のパスを changed で返す。ローカルとエージェントは lstat の NotFound を、SSH は find がその項目について出す "No such file or directory" の知らせ（[docs/remote-tools.md](../../remote-tools.md)）を、この答えにする。読み分けられない知らせは今までどおり走査の誤りにする。
  - why: 今までは、ローカルはそれを入れているディレクトリを読めない（Other）とし、SSH は説明できない知らせとして誤りにしていた。経路で誤りが違い、理由も取り違えていた（REQ-scan-017）。
  - decided_by: 利用者（2026-10-13、段 2 の 4 回目のレビューの後の直し方の方針）
  - root_dir そのものがなくなったかディレクトリでなくなったときは、root_dir の誤りの一つ（RootChanged）にし、利用者には root_dir の実際のパスを添えて "root_dir changed during the scan: <パス>" と出す。リモートでは、root_dir がないときと同じくサーバ名を添えて "<サーバ名>:<パス>" とする。
  - root_dir が消えたかは、sh や find の知らせを読み分けずに事実で決める。集め方は、集め始めにはディレクトリだった root_dir が集め終わったときにもうないかディレクトリでなければ、答えの代わりにそのこと（CollectError::RootGone）を返し、規則はほかの答えや知らせによらず RootChanged にする。SSH のスクリプトは、root_dir に移った先の絶対パスを終わりに `[ -d ]` で確かめて目印を出し、尋ね直しの回も同じにする。尋ね直しの回で root_dir にもう入れないときも同じ扱いにする。root_dir があるのに説明できない知らせが出たときは、今までどおり走査の誤りにする。
  - 尋ね直しをコマンド行の長さで分けたときは、各回の答えをその回に尋ねたディレクトリと一つずつ突き合わせる。
  - why: 走査の途中で変わったパスとして空のパスを出すと、誤りの文から何が変わったか読めなかった。root_dir が消えると、SSH だけ sh の getcwd の知らせが説明できない知らせになり、ローカルは RootChanged になって、経路で誤りが違った（REQ-scan-017）。尋ね直しの答えを全体でまとめてから突き合わせると、ある回の答えがほかの回の問いの答えにすり替わっても気づけなかった。

- C15 C13 の「走査全体を止める誤り」の範囲を、走査の失敗の種類ごとに決める。走査の途中で項目が変わったこと（ChangedDuringScan）は、読めないディレクトリと同じくその名前の部分木についての事実なので、指定したパス全体を一覧を取れなかったものにする。答えが問いと合わないこと（InconsistentAnswer）と集め方そのものの失敗（CollectFailed）は、集め方や経路の失敗でその名前の性質ではないので、diff 全体を走査の誤りにして終了コード 2 で止める。接続断は今までどおり REQ-ssh-003・REQ-ssh-023 で扱う。diff の展開は種類をすべて挙げて扱いを決め、種類を足したら決め直さないと組み立てが通らない形にする。
  - why: C13 は「など」で範囲を残しており、新しく足した種類が決めないまま diff 全体を止める側に落ちていた。
