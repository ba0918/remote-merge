# 書き込み・symlink の作成・削除で新しくエラーにする判断

## Context

品質の確認で、SSH の経路（Agent を使わない経路）がリモートの削除と symlink の作成の失敗を成功として扱い、一括読み込みで読めないファイルを空の中身にすることが見つかった。
これを直すときに、IR の要件の文が直接は決めていない四つの扱いが残った。
一つ目は、[A6](./2026-10-05-harden-security.md#A6) が Agent について決め、SSH の経路は別に扱うとした、最後の要素が既存の symlink である書き込み先への書き込みである。
二つ目は SSH の経路で symlink の作成先が既存のディレクトリのとき、三つ目はローカルの経路の同じ書き込み、四つ目は --delete が消そうとした書き込み先が比べた後に消えていたときである。
ローカル・SSH・Agent の経路の間で、同じ状況の扱いが食い違っていた。
その後の確認で、SSH の経路の確認と書き込み・削除・作成が別の操作で間に差し替えられること、`-` で始まるリンク先が ln のオプションとして読まれること、ログインシェルが POSIX の sh でないサーバでコマンドが動かないこと、作成先に既にある項目を symlink の作成が置き換えること、これらの扱いが IR にないことが見つかり、A5〜A10 で決めた。
さらに、A8 の付け替えの一時ファイルを他のユーザーが差し替えられること、fish での確認が CI で一度も実行されていないこと、保証するログインシェルの範囲が確かめた範囲より広いこと、A1〜A10 の要件の確かめ方が実在のテストを指していないことが見つかり、A11〜A14 で決めた。

## Agreements

- A1 SSH の経路は、最後の要素が既存の symlink であるパスへ通常ファイルを書かずエラーにし、リンクもリンク先も変えない。
  - why: リンクを通常ファイルに置き換えるのは [REQ-merge-001](../../ir/merge/symlink.md#REQ-merge-001) が禁じる種類の変更で、リンク先へ書くのは書き込み先の外を変える。この根拠は経路によらないので、Agent について決めた [A6](./2026-10-05-harden-security.md#A6) と同じ扱いにする。シェルには O_NOFOLLOW がないので、同じコマンドの中で書き込みの直前に確かめる。A6 が別に扱うとした SSH の経路を、利用者がこの修正の範囲に足した。
  - decided_by: 利用者（2026-10-05）
- A2 SSH の経路の symlink の作成は、作成先が symlink でない既存のディレクトリならエラーにして何も変えず、作成先が既存の symlink ならリンクそのものを置き換えリンク先を変えない。
  - why: ディレクトリの中にリンクを作ると、書き込み先の種類の違う対象を変えることになり [REQ-merge-001](../../ir/merge/symlink.md#REQ-merge-001) に反する。既存の symlink の置き換えは [REQ-merge-003](../../ir/merge/symlink.md#REQ-merge-003) のとおりリンクそのものに行う。ローカルの経路はディレクトリの作成先で失敗するので、それと揃える。
  - decided_by: 利用者（2026-10-05）
  - superseded_by: [A7](./2026-10-05-ssh-strict-exec.md#A7)
- A3 ローカルの経路も、最後の要素が既存の symlink であるパスへ通常ファイルを書かずエラーにし、リンクもリンク先も変えない。書き込み先の途中の symlink は [REQ-merge-004](../../ir/merge/symlink.md#REQ-merge-004) のとおり辿る。ローカルの symlink の作成は A2 と同じ扱いをすでにしている。
  - why: A1 と同じ根拠で、ローカル・SSH・Agent の三つの経路の扱いを揃える。
  - decided_by: 利用者（2026-10-05）
- A4 --delete が消そうとした書き込み先が比べた後に消えていたときは、どの経路でもそのファイルを failed に出し、他のファイルの処理は続ける。SSH の経路は、ないパスの削除を成功とする扱いをやめる。リモートの削除を使う symlink の更新でも、消えていた書き込み先は failed になる。failed の原因の文は経路ごとの既存のエラーのままにする。
  - why: 比べたときから書き込み先が変わったものを failed に出すのは、[REQ-merge-033](../../ir/merge/concurrency.md#REQ-merge-033) が書き込みについて決めているのと同じ理由である。[REQ-merge-034](../../ir/merge/deletion.md#REQ-merge-034) は削除に失敗したファイルを failed に出すと決めており、ローカルの経路はすでにないパスの削除を失敗にしている。
  - decided_by: 利用者（2026-10-05）
- A5 SSH の経路は、リモートのログインシェルが POSIX の sh でなくても（fish でも）同じに動く。リモートで実行するすべてのコマンドを、スクリプトを一つの引数にした `sh -c` として送る。引数は単一引用符で囲み、単一引用符とバックスラッシュは引用符の外に出して前にバックスラッシュを置く。
  - why: SSH の exec はコマンドをリモートのログインシェルに渡すので、ログインシェルが fish のサーバでは、Agent を使わない書き込みと一括読み込みのコマンド（Bourne の構文）が失敗していた。コマンドごとに書き分けず、すべてを同じ形で sh に渡すと、どのログインシェルからも同じスクリプトが動く。fish は単一引用符の中でも `\'` と `\\` を解釈するので、POSIX の `'\''` の書き方だけではバックスラッシュを含むスクリプトが変わる。csh と tcsh では確かめていない。
  - decided_by: 利用者（2026-10-05、確認後の判断 H1）
- A6 A1〜A5、A7 と、A8〜A10 の書き込み・削除・symlink の作成の扱いを IR の要件と例に書き、決定記録だけにある状態をやめる。
  - why: 決定記録だけにある扱いは、IR を読む人からもテストの印からも辿れない。
  - decided_by: 利用者（2026-10-05、確認後の判断 H2）
- A7 ローカル・SSH・Agent のどの経路でも、symlink の作成は、作成先に既存の項目（通常ファイル・ディレクトリ・symlink のどれでも）があれば置き換えずにエラーにし、何も変えない。merge・sync と rollback の symlink の更新は、比べたときにあった書き込み先を先に消してから作るので、[REQ-merge-003](../../ir/merge/symlink.md#REQ-merge-003) のとおり更新できる。A2 の「既存の symlink ならリンクそのものを置き換える」と、[harden-security の A6](./2026-10-05-harden-security.md#A6) の「symlink の作り直しはリンクそのものを消して作る」を置き換える。
  - why: 作成のときに作成先にある項目は、比べた後に現れたものに限られる（比べたときにあった書き込み先は呼び出し元が先に消す）。それを置き換えると、[REQ-merge-033](../../ir/merge/concurrency.md#REQ-merge-033) が書き込みで failed に出すのと同じ、比べた後に変わった対象を黙って変えることになる。ディレクトリの中にリンクを作るのは [REQ-merge-001](../../ir/merge/symlink.md#REQ-merge-001) に反する。
  - decided_by: 利用者（2026-10-05、確認後の判断 H3）
- A8 SSH の経路の書き込みは、書き込み先と同じディレクトリに新しく作った一時ファイルに中身を書き、書き込み先の名前に付け替えて置き換える。一時ファイルは既存のものを上書きせずに作り、既存の書き込み先のモードを引き継ぎ、失敗したときは消す。書き込み先が symlink（A1）か symlink でないディレクトリなら書かずにエラーにする。付け替えは、書き込み先がディレクトリになっていてもその中に入れない GNU の `mv -T` で行い、それが使えないときだけ直前にディレクトリでないことを確かめてから `mv` で行う。
  - why: A1 の確認と書き込みが別の操作なので、その間に書き込み先を symlink に替えられるとリンク先へ書いていた。付け替えは名前そのものを置き換えるので、その間に symlink に替わってもリンク先は変わらない。付け替えは新しいファイルを作るため、書き込み先のディレクトリに書き込めることが要るようになり、書き込んだファイルの所有者は SSH のログインユーザーになる（ファイルにだけ書き込めてディレクトリに書き込めない書き込み先は失敗し、他人の持つファイルは所有者が変わる）。モードは引き継ぐ。
  - decided_by: 利用者（2026-10-05、承認）
  - superseded_by: [A11](./2026-10-05-ssh-strict-exec.md#A11)
- A9 SSH の経路の削除は、存在を確かめずに `-f` のない `rm --` で消し、ないパスは rm の失敗としてエラーにする。
  - why: 存在の確認と `rm -f` が別の操作なので、その間に消えた書き込み先を消したと報告していた（A4 に反する）。SSH の exec には端末がないので、`-f` がなくても書き込めないファイルで確認を求めない。
  - decided_by: 利用者（2026-10-05、承認）
- A10 SSH の経路の symlink の作成は、リンク先の文字列の前に `--` を置き、`-` で始まるリンク先を ln のオプションとして読ませない。既存の項目を置き換えない作成（A7）は、作成先がディレクトリでもその中に作らない GNU の `ln -T` で行い、それが使えないときだけ直前に作成先に何もないことを確かめてから作る。
  - why: リンク先は読み込み元の symlink の文字列で、`--target-directory=` で始まるとリンクを別の場所に作っていた。
  - decided_by: 利用者（2026-10-05、承認）

- A11 SSH の経路の通常ファイルの書き込みは、一時ファイルを作らず、書き込み先をその場で開いて書く。書き込み先は `dd` の `oflag=nofollow` で最後の要素の symlink を辿らずに開き、既存の中身を切り詰めてから、標準入力を `cat` か `openssl base64 -d -A` に通した中身を書く。書き込み元と dd の両方の終了ステータスを確かめ、どちらかが失敗すれば失敗にする。dd が `oflag=nofollow` を受け付けないリモートでだけ、直前に書き込み先が symlink でないことを確かめてからその場で書く。このときは確認と書き込みの間に書き込み先を symlink に替えられるとリンク先へ書く競合が残る。書き込み先のファイルそのものに書くので、所有者・権限・ハードリンク・ACL は変わらない。開いた後で書き込み先の名前が差し替えられても、書き込みは開いたファイルに行われ、差し替えたものもリンク先も変えない。途中で失敗したときは途中までの中身が書き込み先に残る。A8 を置き換える。
  - why: A8 の一時ファイルは予測できる名前で、書き込みと付け替えのたびに名前で開き直すので、同じディレクトリに書き込める他のユーザーがそれを symlink や FIFO に差し替えると、書き込み先の外へ書いたり書き込み先を別のものに置き換えたりできた。付け替えは所有者とハードリンクを変え、[REQ-merge-013](../../ir/merge/permissions.md#REQ-merge-013) と [REQ-backup-029](../../ir/backup/rollback-path.md#REQ-backup-029) と食い違い、書き込めないファイルも黙って置き換え、長い名前では一時ファイルの名前が上限を超えていた。最後の要素を O_NOFOLLOW で開いてその場で書くのは、ローカルとエージェントの経路と同じ形になる。POSIX の sh には pipefail がないので、書き込み元の終了ステータスはパイプの外へ取り出して確かめる。
  - decided_by: 利用者（2026-10-05、確認後の判断 J1）
- A12 CI のテストのジョブに fish を入れ、ログインシェルが fish のときを確かめるテストは、CI が置く環境変数があるとき fish がなければ飛ばさずに失敗する。
  - why: fish がない環境ではそのテストがメモを出して抜け、CI にも fish がなかったので、A5 の fish での動作が一度も確かめられていなかった。
  - decided_by: 利用者（2026-10-05、確認後の判断 J2）
- A13 SSH の経路がログインシェルによらず動くと保証するのは、Bourne 系のシェル（POSIX の sh の文法でコマンドを解釈するシェルで、sh・bash・dash がこれにあたる）と fish に限る。csh と tcsh は保証しない。
  - why: 単一引用符の中の改行を csh と tcsh は受け付けず、A5 の包み方で送ったスクリプトがそこで壊れる。確かめていないシェルを保証の範囲に入れない。
  - decided_by: 利用者（2026-10-05、確認後の判断 J3）
- A14 [REQ-merge-038](../../ir/merge/concurrency.md#REQ-merge-038)〜[REQ-merge-041](../../ir/merge/concurrency.md#REQ-merge-041) は、それを実行して確かめる既存の単体テストから辿れるようにする。単体テストが kotowari の検査するテストファイルの外にあり、そのファイルを検査対象に足すと印のない多数の既存テストが新しい検査の失敗になるときは、`verification: review` のままにし、how_to_verify に実在するテストの場所と名前を書く。
  - why: 四つの要件の how_to_verify が、テストのないファイルを指していた。印は検査対象のテストファイルにあるときだけ数えられ、単体テストはどれもソースのファイルの中にある。それらのファイルを足すと、印のない既存のテスト 212 件が新しく検査の失敗になる。
  - decided_by: 利用者（2026-10-05、確認後の判断 J4）
