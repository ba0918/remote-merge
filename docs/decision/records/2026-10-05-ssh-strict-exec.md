# 書き込み・symlink の作成・削除で新しくエラーにする判断

## Context

品質の確認で、SSH の経路（Agent を使わない経路）がリモートの削除と symlink の作成の失敗を成功として扱い、一括読み込みで読めないファイルを空の中身にすることが見つかった。
これを直すときに、IR の要件の文が直接は決めていない四つの扱いが残った。
一つ目は、[A6](./2026-10-05-harden-security.md#A6) が Agent について決め、SSH の経路は別に扱うとした、最後の要素が既存の symlink である書き込み先への書き込みである。
二つ目は SSH の経路で symlink の作成先が既存のディレクトリのとき、三つ目はローカルの経路の同じ書き込み、四つ目は --delete が消そうとした書き込み先が比べた後に消えていたときである。
ローカル・SSH・Agent の経路の間で、同じ状況の扱いが食い違っていた。

## Agreements

- A1 SSH の経路は、最後の要素が既存の symlink であるパスへ通常ファイルを書かずエラーにし、リンクもリンク先も変えない。
  - why: リンクを通常ファイルに置き換えるのは [REQ-merge-001](../../ir/merge/symlink.md#REQ-merge-001) が禁じる種類の変更で、リンク先へ書くのは書き込み先の外を変える。この根拠は経路によらないので、Agent について決めた [A6](./2026-10-05-harden-security.md#A6) と同じ扱いにする。シェルには O_NOFOLLOW がないので、同じコマンドの中で書き込みの直前に確かめる。A6 が別に扱うとした SSH の経路を、利用者がこの修正の範囲に足した。
  - decided_by: 利用者（2026-10-05）
- A2 SSH の経路の symlink の作成は、作成先が symlink でない既存のディレクトリならエラーにして何も変えず、作成先が既存の symlink ならリンクそのものを置き換えリンク先を変えない。
  - why: ディレクトリの中にリンクを作ると、書き込み先の種類の違う対象を変えることになり [REQ-merge-001](../../ir/merge/symlink.md#REQ-merge-001) に反する。既存の symlink の置き換えは [REQ-merge-003](../../ir/merge/symlink.md#REQ-merge-003) のとおりリンクそのものに行う。ローカルの経路はディレクトリの作成先で失敗するので、それと揃える。
  - decided_by: 利用者（2026-10-05）
- A3 ローカルの経路も、最後の要素が既存の symlink であるパスへ通常ファイルを書かずエラーにし、リンクもリンク先も変えない。書き込み先の途中の symlink は [REQ-merge-004](../../ir/merge/symlink.md#REQ-merge-004) のとおり辿る。ローカルの symlink の作成は A2 と同じ扱いをすでにしている。
  - why: A1 と同じ根拠で、ローカル・SSH・Agent の三つの経路の扱いを揃える。
  - decided_by: 利用者（2026-10-05）
- A4 --delete が消そうとした書き込み先が比べた後に消えていたときは、どの経路でもそのファイルを failed に出し、他のファイルの処理は続ける。SSH の経路は、ないパスの削除を成功とする扱いをやめる。リモートの削除を使う symlink の更新でも、消えていた書き込み先は failed になる。failed の原因の文は経路ごとの既存のエラーのままにする。
  - why: 比べたときから書き込み先が変わったものを failed に出すのは、[REQ-merge-033](../../ir/merge/concurrency.md#REQ-merge-033) が書き込みについて決めているのと同じ理由である。[REQ-merge-034](../../ir/merge/deletion.md#REQ-merge-034) は削除に失敗したファイルを failed に出すと決めており、ローカルの経路はすでにないパスの削除を失敗にしている。
  - decided_by: 利用者（2026-10-05）
