# 品質レビュー 1 回目の判断のうち設定の読み方に関わるもの

## Context

2026-10-05 の品質レビュー 1 回目（main c90cc54）で、設定の書き間違いや無効な値が黙って範囲や安全を変え、include と exclude の値が経路によって違う意味になることが分かった。
利用者は 2026-10-05 に判断 D1〜D32 をすべて推奨どおり採用した（「推奨ではじめて」）。D6 の symlink の名前と D16 の移行は利用者と詰めた答えを採った。
この記録はそのうち設定の値・キー・include と exclude・ローカルの root_dir の判断を扱う。D7 は承認済みの [REQ-config-018](../../ir/config/values.md#REQ-config-018) を書き換える。
ローカルの root_dir の基準を変えるとバックアップの書き込み先の識別も変わるため、その移行は [2026-10-05-quality-backup.md](./2026-10-05-quality-backup.md) に置く。

## Agreements

- A1 include の値は、どの経路でも次のように扱う。走査する側にない値は "Include path does not exist, skipping: 値" の警告を出して飛ばし、エージェントの経路の警告も利用者に見せる。root_dir の外へ解決される値は警告を出して使わない。ファイルを指す値はそのファイル 1 件を対象にする。"." の要素と続いた区切り（"a/./b"・"a//b"）は正規化する。ディレクトリを指す symlink の値は、リンク先を走査し、配下を設定に書いた名前（リンクの名前）の下に載せる（D6）。
  - why: SSH だけ存在しない値で走査全体が失敗し、symlink の値をリンクの名前で root_dir の外まで辿り、ファイルの値はどの経路も何も載せず、正規化していない値は経路ごとに違う一覧になっていた（指摘 status_scan-9・status_scan-10・config_cli-3・config_cli-4）。FLAG-scan-006 を閉じるため、利用者は載せる名前を設定に書いた名前に決めた。利用者が書いた名前と一覧が一致し、両側で同じ名前になる。root_dir の外の値の「拒否」は、今のローカルとエージェントと同じく警告して使わないことと読んだ。正規化で空になる値（"." だけの値）の扱いは [A9](#A9) で決めた。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D6 を推奨どおり採用。symlink の値を載せる名前は利用者が詰めた答え）
- A2 strict_host_key_checking に ask・yes・true・no・false 以外の値を書いた設定は、設定のエラーで止め、終了コード 2 を返す。承認済みの [REQ-config-018](../../ir/config/values.md#REQ-config-018) の「警告を出して ask として扱う」をこの扱いに書き換える（D7）。
  - why: 不明な値が ask に落ち、--yes と組み合わさると未知のホスト鍵を自動で受け入れていた（指摘 config_cli-6）。今まで警告だけで動いていた設定は動かなくなる。エラーの文言は [A10](#A10) で実装者に委ねた。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D7 を推奨どおり採用。承認済みの REQ-config-018 の書き換えとして利用者が決めた）
- A3 設定ファイルの知らないキーとセクションはエラーで止め、終了コード 2 を返す。廃止した [filter] の sensitive と badge_scan_max_files は今までどおり警告を出して受け付ける（D14）。
  - why: include や sudo のようなキーの誤記で、対象の範囲や安全が黙って変わっていた（指摘 config_cli-1）。古い版の設定や他の版向けのキーを書いた設定は動かなくなる。エラーの文言は [A10](#A10) で実装者に委ねた。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D14 を推奨どおり採用）
  - superseded_by: [drop-compat A3](./2026-10-11-drop-compat.md#A3)
- A4 include に値を書き、その値がすべて無効で使えないときは、include を空として全体に広げず、エラーで止める（D15）。
  - why: 全体が走査と書き込みの対象に広がっていた（指摘 config_cli-2）。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D15 を推奨どおり採用）
- A5 相対パスの [local] の root_dir は、その root_dir を書いた設定ファイルのあるディレクトリを基準に解決する。空の [local] の root_dir は、サーバと同じく理由 "root_dir must not be empty" で拒否する（D16）。
  - why: --config やサブディレクトリからの実行で、別のディレクトリを比較し書き込んでいた（指摘 config_cli-5・config_cli-13）。旧台帳の推奨はカレントディレクトリ（現状維持）だった。基準を変えるとバックアップの書き込み先の識別が変わるため、[2026-10-05-quality-backup.md の A1](./2026-10-05-quality-backup.md#A1) で移行と一緒に決めた。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D16 を推奨どおり採用。D24 と一緒に決めた）
- A6 使われない [agent] の timeout_secs・tree_chunk_size・max_file_chunk_bytes は、badge_scan_max_files と同じく使われないことを示す警告を出して無視する。省いたキーの既定値の表からこの三つを除く（D17）。
  - why: 読むだけで効かず、警告もなかった（指摘 config_cli-8）。エージェントは固定の上限で動いている。警告の文言は [A10](#A10) で実装者に委ねた。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D17 を推奨どおり採用）
  - superseded_by: [drop-compat A2](./2026-10-11-drop-compat.md#A2)
- A7 "/" を含む exclude のパターンがディレクトリに当たったときは、名前のパターンの [REQ-config-021](../../ir/config/filters.md#REQ-config-021) と同じく、その配下も除く（D21）。
  - why: ローカルとエージェントは配下を除き、SSH だけ残していた。SSH は除外した配下も辿るため、件数の上限に当たったり失敗したりしていた（指摘 status_scan-2）。パスそのものだけを除く使い方はできなくなるが、"a/b/*" のように書けば配下だけも選べる。SSH は find の -prune で枝刈りする。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D21 を推奨どおり採用）
- A8 "../" を含む exclude のパターンは、設定の読み込み時に "Skipping suspicious exclude pattern containing '../': パターン" の警告を一度だけ出して捨てる（D22）。
  - why: include の [REQ-config-024](../../ir/config/filters.md#REQ-config-024) と同じ扱いにする。ローカルと SSH はパスを調べるたびに警告し、エージェントは何も出していなかった（指摘 status_scan-15）。文言は今のものを使う。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D22 を推奨どおり採用）
- A9 include の値 "." は root_dir 全体を指し、include の制限がないのと同じに扱う。無効な値ではないので、[A4](#A4) のエラーの対象にしない（E4）。
  - why: [A1](#A1) の正規化で "." の要素を除くと空になり、その扱いが決まっていなかった。root_dir 全体を指すと読むのが書いた人の意図に合い、A4 のエラーで止めると全体を対象にしたい設定が書けなくなる。
  - decided_by: 利用者（2026-10-05、詳細 E4 を推奨どおり採用）
- A10 strict_host_key_checking の不明な値のエラー（[A2](#A2)）、知らないキーとセクションのエラー（[A3](#A3)）、使われない [agent] のキーの警告（[A6](#A6)）の文言は IR で決めない。実装者が分かる英語の文言を書き、テストはその文言を固定しない（E8）。
  - why: これらの判断は文言を決めていなかった。利用者は、決めていない文言を IR に固定せず、実装に委ねることにした。
  - decided_by: 利用者（2026-10-05、詳細 E8 を推奨どおり採用）
