# 走査の上限と不完全な一覧を kotowari に取り込む際の判断

## Context

走査の一覧に載るもの（[取り込みの記録](./2026-09-29-adopt-scan-listing.md)）に続き、status・diff・merge・sync の走査の件数の上限、上限の超過・循環・読めないディレクトリで一覧が不完全になるときの扱い、find のタイムアウト、パスを指定したときの走査の範囲を取り込む。
旧資料（[旧総合仕様](../../archive/spec.md) の大量ファイルのハンドリングの節、既存要件 [REQ-scan-003](../../ir/scan/limits.md#REQ-scan-003) から [REQ-scan-005](../../ir/scan/limits.md#REQ-scan-005) と [REQ-scan-002](../../ir/scan/directory-links.md#REQ-scan-002) の循環と上限の部分）とローカル・SSH・エージェントの三経路の実装・テストを突き合わせ、読んで確信の持てない点は試験 SSH サーバに対する実行で確かめた。一致するものは現状を仕様として追認し、食い違い・欠落は FLAG として未決のまま残す。
既存要件は実装と食い違う経路があるものも変更せず FLAG を付ける。旧総合仕様の 1 ディレクトリ 10,000 件の上限とステータスバーの表示は TUI の走査の話で、凍結中の TUI で扱う。merge の --hunks が --max-entries を使わないことは既存の [FLAG-merge-018](../../ir/merge/FLAGS.md#FLAG-merge-018) のまま、存在しないディレクトリを指定した sync の扱いは sync の話題、diff のディレクトリ symlink の走査の上限は [REQ-cli-021](../../ir/cli/symlink-diff.md#REQ-cli-021) で扱う。
要件は新しく 2 件と判定表 1 件で、既存の文書と同じく上限と走査の範囲を扱うため既存の文書に足す。
テストの内訳（対象 63 件）: 要件の根拠 47 件、FLAG の挙動のテスト 7 件、実装詳細をなぞるだけ 0 件、残す 9 件。

## Agreements

- A1 現行実装をレビューなしで仕様とする。status・diff・merge・sync の走査が件数の上限を超えたとき、実装は "Tree scan truncated at 上限 entries." で始まり、--max-entries で上限を上げること、設定の max_scan_entries を設定すること、全体を走査せずにファイルのパスを指定することを案内するエラーを出す（status の実行で確かめた）。
  - why: 利用者に見える挙動をテストが確かめており、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A2 現行実装をレビューなしで仕様とする。status はパスを取らず常に root_dir 全体を走査し、diff・merge・sync は指定したパスによって走査の範囲を選ぶ。実装は、パスを指定しないとき、"."・"./"・空の値のパスがあるとき、glob 文字（"*"・"?"・"["）を含むパスがあるとき、パスが 21 個以上のとき、末尾が "/" のパスとそうでないパスが混ざるとき、merge・sync に --delete を付けたときは root_dir 全体を走査し、全てのパスの末尾が "/" のときはそれぞれのディレクトリの下だけを走査して件数の上限をディレクトリごとの走査に当て、merge・sync で全てのパスの末尾が "/" でないときは各パスの親ディレクトリの下だけを走査し、root_dir の直下のファイルが含まれれば root_dir 全体を走査する。
  - why: 利用者に見える挙動（上限の超過が起きる範囲）をテストが確かめており、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A3 未決の FLAG として残す。既存要件 [REQ-scan-003](../../ir/scan/limits.md#REQ-scan-003) はファイル件数の上限とするが、ローカルと SSH の走査はディレクトリも一件として数え（ファイル 2 件とディレクトリ 1 件で上限 2 のとき打ち切ることを status の実行で確かめた）、エージェントの走査はファイルと symlink だけを数えるため、同じツリーでも経路によって打ち切られる件数が違う。
  - why: 既存要件と実装が経路によって食い違い、どちらに合わせるかは次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A4 未決の FLAG として残す。既存要件 [REQ-scan-004](../../ir/scan/limits.md#REQ-scan-004) の例 EX-scan-009 は上限以下のファイル数なら件数の上限を理由に打ち切らないとするが、エージェントの走査は数えた件数が上限とちょうど同じときも、それ以上の項目がなくても打ち切ったと報告する。これは実装を読んで分かったことで未実行。
  - why: 既存要件と実装が食い違い、どちらに合わせるかは次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A5 未決の FLAG として残す。[旧総合仕様](../../archive/spec.md) の大量ファイルのハンドリングの節は find の実行時間の上限を 30 秒とするが、実装の SSH の経路の走査は 120 秒で固定し、設定では変えられず、超えたときは接続のタイムアウトと読める "SSH connection timed out (120s): サーバ名" のエラーを出す。これは実装を読んで分かったことで未実行。
  - why: 旧資料と実装が食い違い、どちらに合わせるかは次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A6 未決の FLAG として残す。走査の途中に読めないディレクトリがあるとき、ローカルの走査は "Directory scan incomplete:" で始まるエラー、SSH の走査は "SSH command execution failed:" で始まるエラーで止まり、status は終了コード 2 を返す（status の実行で確かめた）が、エージェントの走査はそのディレクトリを飛ばし、欠けた一覧を完全な一覧として返す（実装を読んで分かったことと単体テスト）。既存要件 [REQ-scan-005](../../ir/scan/limits.md#REQ-scan-005) は件数の上限とリンクの循環による不完全な一覧だけを挙げ、読めないディレクトリについて述べない。
  - why: 利用者に見える挙動が経路によって違い、仕様が欠けているため、次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A7 未決の FLAG として残す。sync に同じ最上位のディレクトリの下のディレクトリを二つ以上指定すると（例 "a/x/" と "a/y/"）、後のディレクトリの配下が一覧から落ち、そのディレクトリのパスが "IO error: Is a directory" の失敗になって書き込み先の status は "partial"、終了コードは 2 になり、--dry-run ではそのディレクトリのパスを merged に status "would merge" で出す（sync の実行で確かめた）。同じ指定の merge と diff は両方の配下を扱う。旧資料に記述がなく、確かめるテストもない。
  - why: 利用者に見える挙動に仕様とテストが欠けており、次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A8 A2 のうち diff の走査の範囲の記述を正し、判定表 TBL-scan-001 を merge・sync の走査の範囲に限る。diff はパスを指定しないとき root_dir 全体を走査するが、指定したパスの末尾の "/" を範囲を選ぶ前に取り除くため、A2 の末尾が "/" のパスの規則（それぞれのディレクトリの下だけを走査し件数の上限をディレクトリごとに当てること、混在で root_dir 全体を走査すること）は diff には当たらず、パスを指定した diff の範囲と上限は cli diff の話題（[REQ-cli-021](../../ir/cli/symlink-diff.md#REQ-cli-021) など）として扱う。merge・sync はパスを一つ以上必須とするため、A2 の「パスを指定しないとき」は status と diff にだけ当たる。これらは実装を読んで分かったことで未実行。
  - why: テスト整理の計画のレビューで、diff が末尾の "/" を取り除くことと merge・sync がパスなしを拒否することを指摘され、コードで確かめた。承認済みの A2 は書き換えず、この決定で正す。
  - decided_by: 利用者（推奨を採用）
- A9 merge・sync で全てのパスの末尾が "/" でないとき、件数の上限は各パスの親ディレクトリごとの走査に当て、親ディレクトリを合わせた件数には当てない。これは現行実装のとおりで（親ディレクトリごとに上限を渡して走査することを実装で読み、テストで確かめた）、全てのパスの末尾が "/" のときの上限の当て方と揃える。
  - why: テスト整理のレビューで、テストがこの当て方を前提にしているのに判定表のファイルのパスの行に書かれていないと指摘され、利用者が判定表に書き足すことを選んだ。
  - decided_by: 利用者（推奨を採用）
