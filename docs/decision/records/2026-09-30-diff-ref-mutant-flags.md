# diff の参照先と競合のテスト整理で残った問題を FLAG として残す判断

## Context

diff の --ref の参照先と競合のテスト整理（[取り込みの記録](./2026-09-30-adopt-diff-ref.md)の後）で、変異テストの見逃しはテストの追加・同等変異の登録・FLAG の記録のどれかで決着させる。
整理後に残った見逃しのうち、src/diff/conflict.rs の detect_conflicts と merge_overlapping_regions の 3 件は、用語「競合」と [REQ-cli-065](../../ir/cli/conflicts.md#REQ-cli-065) からはどちらが正しいかを決められず、テストを足すとどちらかの扱いを固定することになる。
これを仕様として決めずに、次にこのトピックを扱うときの論点として残す。経緯は "docs/testing/diff-ref-test-cleanup.md" にある。

## Agreements

- A1 未決の FLAG として残す。用語「競合」は同じ箇所を参照先からの変更の行の範囲が重なることとするが、行を足すだけの変更は参照先の行の範囲が空で、空の範囲が重なるかを定めていない。diff は、左右が同じ位置に行を足したとき、一方が足した位置が他方の変えた範囲の中にあるとき、他方の変えた範囲の先頭の行の前に足したときを競合として示す。変異テストの見逃し 2 件（src/diff/conflict.rs の detect_conflicts の挿入の重なりの条件の `&&` を `||` にするものと、merge_overlapping_regions の `<` を `<=` にするもの）は、この扱いでしか検知できない。
  - why: 利用者の判断。取り込みとテスト整理の中では仕様を決めず、次にこの機能を扱うときに決める。今の実装を仕様にすると、行の挿入の扱いという意味の判断を急いで固めることになる。
  - decided_by: 利用者（推奨を採用）
- A2 未決の FLAG として残す。diff は一方の一つの変更が他方の複数の変更と重なるとき（例 参照先 "a\nb\nc" に対して左が三行を全て変え、右が 1 行目と 3 行目を別々に変える）、重なる組を一つにまとめて "conflict_count" を 1 とするが、[REQ-cli-065](../../ir/cli/conflicts.md#REQ-cli-065) の競合の数がこの場合に 1 か 2 かは定めていない。変異テストの見逃し 1 件（src/diff/conflict.rs の merge_overlapping_regions の `<` を `==` にするもの）は、この数でしか検知できない。
  - why: 利用者の判断。取り込みとテスト整理の中では仕様を決めず、次にこの機能を扱うときに決める。
  - decided_by: 利用者（推奨を採用）
