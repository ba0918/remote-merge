# テストのない要件と例にテストを付けて IR と違う動きを直すときに、実装者が決めたこと

## Context

テストのない要件と例に契約テストを付け、IR と違う動きを IR のとおりに直す単位（計画 untested-items）で、直した振る舞いと既存のテストの前提が食い違うところや、IR が実装者に委ねたところがあった。
どれも IR の意味を変えず、直さないという選択肢が実質ないものとして、実装者が決めた。
この記録は、その決めたことと理由を残す。

## Agreements

- A1 REQ-backup-045 のとおり集約先の準備の失敗でコマンド全体を止めるようにしたので、集約先の場所をファイルでふさいで merge と sync のファイルごとの "backup failed" を確かめていた二つのテストは、コマンド全体が止まることを確かめる REQ-backup-045 のテストに改めた。REQ-backup-017 のテストは、--delete で読めない書き込み先のファイルの保存に失敗する場合（ローカル）と、エージェントの読み込みが切れる既存の場合に残した。
  - why: 集約先を作れないことは REQ-backup-045 の場合で、ファイルごとの失敗（REQ-backup-017）の作り方として使えなくなった。merge と sync は書き込み先の中身を楽観ロックのために書き込みの前に読むので、ローカルの契約テストでは書き込み先を読めなくしても比べる段階の失敗になり、バックアップの保存だけを失敗させる作り方がない。
  - decided_by: 実装者（利用者の包括的な許可による）
- A2 片側にだけある 0 バイトのファイルを --max-files で数えない前提の REQ-cli-055 の二つのテストは、そのファイルを変更のあるファイルとして数えて打ち切る確かめ方に改めた。
  - why: REQ-cli-086 は片側にだけある 0 バイトのファイルを差分ありと数えると決めており、REQ-cli-055 は変更のあるファイルを数える。テストの前提だけが古い振る舞いのままだった。
  - decided_by: 実装者（利用者の包括的な許可による）
- A3 diff の件数の上限の超過は、ディレクトリを展開して比べるときも REQ-scan-008 の "Tree scan truncated at 上限 entries." で始まる文で errors に載せ、それまでの "directory comparison incomplete (entry limit exceeded)" を固定していた EX-cli-045 のテストをその文に改めた。パスを指定しない diff の上限の超過をエラーとして確かめていた REQ-scan-008・REQ-scan-009 のテストは、diff の errors の文を読む形に改めた。
  - why: REQ-cli-084 は走査方式によらず読めた差分を残し、上限の超過の理由を REQ-scan-008 の文にすると決めている。
  - decided_by: 実装者（利用者の包括的な許可による）
- A4 SSH の経路の走査の時間切れは接続の時間切れと別の文言のエラーにしたが、再接続と一度の再試行の扱いは接続の時間切れと同じにした。
  - why: REQ-scan-013 は文言を区別することだけを求めている。走査のコマンドの終わりの状態を受け取れなかったことは用語集の `接続断` に当たり、これまでの再試行の振る舞いを変える理由がない。
  - decided_by: 実装者（利用者の包括的な許可による）
- A5 UTF-8 として読めない名前は、読めない部分のバイトを "\xNN" と書いたパスで報告する。報告するのはツリーの走査で見つけたファイルだけとし、diff のディレクトリの展開や merge の子の一覧はこれまでどおりとした。merge と sync は指定したパスの範囲にあるもの（パスがないか root_dir 全体や glob を指すときは全て）を failed に出し、status は全てを errors に出す。エージェントの走査の応答にその名前を足したので、通信の版を 8 から 9 に上げた。
  - why: REQ-scan-012 は報告の文言と表し方を実装者に委ね、ツリーの走査を対象にしている。置換文字を使わずに元のバイトを示せる表し方にした。子の一覧は走査ではなく、別の単位で扱う。
  - decided_by: 実装者（利用者の包括的な許可による）
