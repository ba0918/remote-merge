## Context

設定の IR は旧仕様の移行時に、グローバル設定とプロジェクト設定の優先（[REQ-config-001](../../ir/config/precedence.md#REQ-config-001)、[REQ-config-002](../../ir/config/precedence.md#REQ-config-002)）とフィルターの適用範囲だけが作られ、設定ファイルの場所・--config・読み込みの失敗・セクションごとの合成・既定値と既存テストの大半が仕分けられていなかった。
設定は大きいため、読み込みと合成（この記録）、値の検査、フィルターの 3 回に分けて取り込む。
旧資料（[旧総合仕様](../../archive/spec.md) の設定ファイル・設定のマージ戦略・root_dir が存在しない場合の節と --config の行、README の Configuration、利用者向けの手引き "skills/remote-merge/SKILL.md" の Configuration と Global CLI Options、その参照資料 "skills/remote-merge/references/json-schemas.md"、既存要件）と、設定を読む全コマンドの起動時の読み込みと --config から見える現行実装・テストを突き合わせ、一致するものは現状を仕様として追認し、食い違い・欠落・曖昧さは FLAG として未決のまま残す。
既存要件 REQ-config-001 と REQ-config-002 は実装と一致したため変更しない。値の検査は次の回、フィルターの一致の規則は最後の回で扱う。
要件は 9 件で limits.requirements を超えないが、責任ごとに場所と読み込み・合成・既定値の文書に分ける。
テストの内訳（対象 47 件）: 要件の根拠 26 件、FLAG の挙動のテスト 10 件、実装詳細をなぞるだけ 8 件、残す 3 件。
