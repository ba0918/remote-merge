# 旧仕様を IR に移す際の判断

## Context

旧総合仕様と個別仕様を kotowari の IR に移し、既存の Rust テストと対応付ける。
旧文書には実装済みの動作と未実装の設計が混在する。既存テストは 2,821 件が ID 未付与の状態。
現行コードと旧文書が異なるところを自動的に「仕様」または「不具合」と扱うと、誤った契約を固定する。
確認済みの食い違いと採用方針を決めてから、要件とテストの対応を確定する。
既存テストは以前の「テスト必須」方針で増えたもので、利用者の要求を検証できているとは限らない（ユーザーからの指摘）。

## Agreements

- A1 旧個別仕様を要求の候補として読み、利用者が期待する結果から IR を作る。実装と食い違う箇所は個別に判断する。
  - why: 既存テストは以前のテスト必須方針で増えており、望んだ動作を検証できているとは限らない。
  - decided_by: user
- A2 既存テストは要件に対する証拠として審査し、結果を十分に確かめるものだけ紐づける。不十分なものは修正または追加し、実装詳細をなぞるだけのものは紐づけない。
  - why: ID を機械的に付けると、弱いテストを仕様の証拠として誤認する。
  - decided_by: user
- A3 マージと削除では、通常ファイル・ディレクトリ・末尾 symlink の種類が異なる対象を置き換えず、理由を示してスキップする。削除対象の末尾 symlink も残す。同じ種類の symlink 同士はリンク先を更新する。
  - why: 意図しないリンクの破壊や種類の変更を防ぐ。現行実装に置き換え経路があるため、実装とテストを変更する。
  - decided_by: user (took the recommendation)
- A4 書き込み先の root_dir 外を指す途中の symlink 越しの書き込みは、ローカル・SSH・エージェントの全経路で拒否する。
  - why: 同じ操作が経路次第で書けたり拒否されたりする現状をなくし、書き込み先の範囲を保証する。
  - decided_by: user (took the recommendation)
  - superseded_by: [A6（既存リンクを辿る）](./2026-09-25-spec-migration.md#A6)
- A5 ファイル指定の merge・sync は内容を比較する。ディレクトリ指定の merge・sync には `--checksum` を提供し、指定時に内容を比較する。
  - why: サイズと更新時刻が一致するだけで内容の違いを見落とすことを防ぐ。ディレクトリでは利用者が内容比較のコストを選べる。
  - decided_by: user (took the recommendation)
- A6 root_dir 内のパスから到達する既存の途中の symlink は、そのリンク先が root_dir 外でもローカル・SSH・エージェントの全経路で辿り、更新前にバックアップする。引数としての絶対パスと `..` を含むパスは拒否する。
  - why: サーバが共有ディレクトリへのリンクを意図して設置している場合、一律拒否では一部のファイル更新が失敗する。経路による結果の違いをなくす。
  - rejected: [A4（全経路で拒否）](./2026-09-25-spec-migration.md#A4)
  - decided_by: user (took the recommendation)
- A7 ディレクトリを指す symlink の配下は、TUI ではそのリンクを展開したときだけ直下を取得し、CLI status では既存の件数上限内で再帰列挙する。循環と上限超過は明示し、取得できた一部だけを完全な一覧として扱わない。TUI の凍結方針には、このリンク展開の対応に限る例外を設ける。
  - why: 個別パス指定だけでは利用者にファイルが欠けているように見え、起動時の全リンク再帰では共有領域へのアクセスが重くなる。
  - decided_by: user (took the recommendation)
- A8 IR 化の対象は利用者が使う機能全体とする。旧総合仕様の配布手順や実装メモをそのまま要件にしない。
  - why: 既存の長文仕様に混在する構想や古い内部構造を、利用者に保証する動作と取り違えないため。
  - decided_by: user (took the recommendation)
- A9 マージ・同期・復元の書き換え前の内容は利用者マシンの専用領域に集約し、書き込み先の root_dir にバックアップを作らない。
  - why: 書き込み先に平文のバックアップを残さず、復元に使う保存場所を一か所に定める。
  - decided_by: user (took the recommendation)
- A10 バックアップが有効でファイルの書き換え前の内容を保存できない場合、そのファイルには書き込まず失敗を報告し、他のファイルの処理を続ける。
  - why: 失敗したファイルを取り戻せない上書きから守りつつ、独立したファイルの更新を妨げない。
  - decided_by: user (took the recommendation)
- A11 rollback は書き戻す前にセッション内の全ファイルのリンク先を確認し、バックアップ時と異なる場所を指すものが一件でもあれば、そのセッションを一件も書き戻さず理由を報告する。
  - why: 既知のリンク先変更による部分復元と、意図しない別の場所への書き込みを防ぐ。実行中に新たに起きる I/O 失敗まで原子的に戻す保証はここには含まない。
  - rejected: 安全と判定されたファイルだけを先に復元する案は部分復元を生む。
  - decided_by: user (took the recommendation)
- A12 バックアップ集約先は絶対パスの XDG_DATA_HOME があるときはその下の remote-merge/backups/、未設定・空・相対値のときはホームの .local/share/remote-merge/backups/ とする。
  - why: 利用者が場所を予測でき、相対パスや空値による意図しない保存先を避けられる。
  - decided_by: user (took the recommendation)
- A13 バックアップが明示的に無効のときは復元可能なコピーを作らずに merge・sync してよい。
  - why: 利用者の既存の選択肢を維持し、バックアップ失敗による書き込み拒否も行わない。
  - decided_by: user (took the recommendation)
- A14 グローバル設定とプロジェクト設定が衝突するとき、同名サーバ・ローカル root・SSH 設定はプロジェクト側を優先し、衝突しないグローバルのサーバは残す。除外・機密・対象フィルターは両方を結合する。
  - why: プロジェクト固有の設定を優先しつつ、グローバル側のフィルターを失わない。
  - decided_by: user (took the recommendation)
- A15 diff はディレクトリ指定でも JSON 形式で配下の複数ファイルの差分を出せるようにする。
  - why: 一回の呼び出しで機械的に処理できる差分の範囲を、旧資料の単一ファイル制限より広く保つ。
  - decided_by: user (took the recommendation)
- A16 ツリー走査には利用者が変更可能な件数上限を設け、上限を超えたら結果が不完全であることを知らせる。現行の具体的な初期数値は IR の契約に固定しない。
  - why: 大規模サーバで無制限の走査を防ぎつつ、既定値の調整を互換性問題にしない。
  - decided_by: user (took the recommendation)
- A17 書き込み CLI の merge・sync は書き込み元と先を明示させ、リモート間または機密ファイルの書き込みには追加確認または明示的な強制指定を求める。dry-run は変更予定を報告し書き込まない。
  - why: 書き込み先の取り違えと意図しない更新を防ぐ。
  - decided_by: user (took the recommendation)
- A18 merge・sync で書き込み先にだけある通常ファイルは既定では残し、--delete を明示した時だけ削除する。末尾の symlink は [A3（種類違いの保護）](./2026-09-25-spec-migration.md#A3) に従って残す。
  - why: 既定の操作で書き込み先固有のファイルを失わないため。
  - decided_by: user (took the recommendation)
- A19 diff で機密ファイルの中身を既定で隠し、利用者が --force を指定した場合だけ内容を表示する。
  - why: 差分出力やエージェント連携への機密内容の意図しない露出を防ぐ。
  - decided_by: user (took the recommendation)
- A20 未知の SSH ホスト鍵は利用者に確認できない実行で無言のまま信頼せず、接続を止める。確認可能な場合でも利用者が拒否したら接続を止める。
  - why: 知らない接続先を黙って信頼してファイルを読み書きしない。
  - decided_by: user (took the recommendation)
- A21 status は左右だけにあるファイルと変更されたファイルを既定で列挙し、同じファイルは省略する。--all で同じファイルも列挙し、--checksum で内容による再比較を指定できる。
  - why: 日常の差分確認を簡潔にし、必要なときだけ全件表示や精密比較の負荷を払う。
  - decided_by: user (took the recommendation)
- A22 TUI の主要操作（ツリー選択・展開、左右差分、マージ前確認）を利用者向け仕様に含める。旧文書の画面レイアウトやキー名は検証せずに移さない。
  - why: 操作結果を保証し、古い画面案や誤ったキー名を契約化しない。
  - decided_by: user (took the recommendation)
- A23 利用者が --yes または strict_host_key_checking=no を明示した場合は未知の SSH ホスト鍵を承認できる。既定の確認不能時は [A20（未知の鍵を拒否）](./2026-09-25-spec-migration.md#A20) に従う。
  - why: 無人実行の明示的な例外を残しつつ、暗黙の信頼だけを禁止する。
  - decided_by: user (took the recommendation)
- A24 バイナリファイルは SHA-256 による一致判定とハッシュを差分に示し、マージでは元のバイト列を保つ。
  - why: テキスト化によるデータ欠落を避け、差分の有無を利用者が確認できる。
  - decided_by: user (took the recommendation)
- A25 --ref で指定した三者比較の参照先は読み取り専用とし、明示した左右の書き込み先だけを更新する。
  - why: 比較の補助として参照したサーバを意図せず変更しない。
  - decided_by: user (took the recommendation)
- A26 SSH の読み取り中の接続断は一回だけ再接続して読み直し、再び失敗したら失敗を報告する。結果が不明な書き込み失敗では失敗を報告し、同じ更新を自動再実行しない。
  - why: 一時的な読み取り断を回復しつつ、書き込みの重複や予期しない上書きを防ぐ。
  - decided_by: user (took the recommendation)
- A27 バックアップを一回の書き込み操作ごとのセッションでまとめ、rollback --list から選べるようにする。期限切れは通常の復元候補から外し、明示的な強制指定のときだけ復元可能とする。
  - why: 複数ファイルを一操作として識別し、古い履歴の誤復元を防ぐ。
  - decided_by: user (took the recommendation)
- A28 除外パターンと include 指定はツリー・status・merge・sync の対象に共通して適用し、include 指定があるときは一致するパスだけを対象にする。
  - why: 表示と実際の書き込み対象が食い違わないようにする。
  - decided_by: user (took the recommendation)
- A29 テキスト差分の選択された hunk だけを適用でき、選択していない変更は書き込み先に残す。適用前に衝突と書き込みを確認する。
  - why: ファイル全体を置き換えずに必要な変更だけ取り込めるようにする。
  - decided_by: user (took the recommendation)
- A30 kotowari の検査対象は仕様を検証する専用のテストファイルとし、既存の内部実装テストは cargo test に残して ID を義務付けない。既存テストから行動を確認できたものを専用の場所へ移す。
  - why: 約 2,800 件のテスト全てを内部実装の契約に見立てず、証拠になるテストを選び直すため。
  - decided_by: user (took the recommendation)
- A31 リモート操作の Agent は転送の内部方式とし、使えない場合でも SSH 経路で比較・マージできることを利用者へ保証する。通信プロトコルのバージョンやデプロイ手順は IR に含めない。
  - why: 方式を変更しても利用者の操作結果を保てるようにする。旧文書の v2 と現在の v4 を混同しない。
  - decided_by: user (took the recommendation)
- A32 rollback の dry-run は選択したセッションの復元予定とリンク先変更などのブロック理由を報告し、ファイルを変更しない。
  - why: 復元前に影響を確認でき、実行せずに部分復元の原因を知ることができる。
  - decided_by: user (took the recommendation)
- A33 init はプロジェクト設定のひな形を生成するが、既存の設定ファイルを無断で上書きしない。
  - why: 再実行で接続設定やフィルターを失わないため。
  - decided_by: user (took the recommendation)
- A34 CLI の logs と events は障害調査用の閲覧操作とし、記録にファイル内容や認証情報を含めない。内部形式と件数上限は利用者の契約にしない。
  - why: 問題の原因を見られるようにしつつ、ログへの機密漏洩を防ぐ。
  - decided_by: user (took the recommendation)
- A35 差分確認から書き込みまでに対象が別の操作で更新された場合は検知してマージを止める。
  - why: 読み込み後に変わったファイルを古い内容で上書きしない。
  - decided_by: user (took the recommendation)
- A36 古い SSH サーバ向けの暗号方式はサーバ単位で設定可能な範囲を使い、接続失敗時は理由と設定のヒントを示す。旧資料が列挙した全アルゴリズムの対応は約束しない。
  - why: 実装されていない方式を利用者への保証として記さず、診断可能な接続を保つ。
  - decided_by: user (took the recommendation)
- A37 期限切れバックアップを自動整理するときは現在設定された書き込み先のものだけを対象とし、設定されていない履歴は消さない。
  - why: 別プロジェクトや現在は設定されていないサーバの復元履歴を不用意に失わない。
  - decided_by: user (took the recommendation)
- A38 書き込み先の中身が差分確認後に変わったなら、サイズと更新時刻が以前と同じでもマージを止める。
  - why: 時刻だけの再確認では検出できない外部変更を古い差分で上書きしないため。書き込み前の内容確認のコストは受け入れる。
  - decided_by: user (took the recommendation)
- A39 三者比較で参照先に対して左右が別々に変更されたときは競合を表示し、自動で一方を選んで上書きしない。
  - why: 参照先をもとにした相反する編集を利用者の判断なしに失わないため。
  - decided_by: user (took the recommendation)
- A40 新しいファイルやディレクトリは設定された権限で作り、既存ファイルは所有者と権限を維持する。書き込み元の権限は --with-permissions が明示されたときだけ反映する。
  - why: サーバ固有の権限を無断で変えず、権限の同期は利用者の選択に委ねる。
  - decided_by: user (took the recommendation)
- A41 TUI でファイル名を検索でき、サーバ切替時にも選択とツリー展開を可能な範囲で維持する。
  - why: 大きなツリーや複数サーバで見ている場所を見失わないため。
  - decided_by: user (took the recommendation)
- A42 sync は複数の書き込み先を一回で指定でき、一つが失敗しても他の対象を処理し、対象ごとの結果と部分失敗を報告する。
  - why: 一部のサーバだけが利用できない場合にも、成功できる更新と失敗した更新を区別するため。
  - decided_by: user (took the recommendation)
- A43 非対話 CLI の --format json は成功とエラーのどちらでも機械が読める JSON を返し、部分成功は完全成功と異なる非ゼロの終了コードを返す。
  - why: 自動操作の呼び出し元が人向け文字列の解析なしに失敗を検知できるようにする。
  - decided_by: user (took the recommendation)
- A44 TUI は参照先と左右との差を区別して示し、三者の状態を概観するサマリーを提供する。色やキー名は契約に固定しない。
  - why: 三者の食い違いと競合の位置を対話画面でも判断できるようにする。
  - decided_by: user (took the recommendation)
- A45 元または先のディレクトリ走査が循環・件数上限などで不完全なときは、そのディレクトリの merge・sync と --delete を開始せず、理由を報告する。
  - why: 未取得のファイルを存在しないと誤認して削除したり、不完全な一覧から一部だけ更新したりしないため。
  - decided_by: user (took the recommendation)
- A46 同じ種類の末尾 symlink 同士のマージでは変更前のリンク文字列を保存し、rollback で元の文字列に戻す。マージ後に第三者が再度リンクを付け替えた場合は [A11（復元前の全件確認）](./2026-09-25-spec-migration.md#A11) を適用する。
  - why: 意図したリンクの更新は取り消せるようにし、後から行われた別の変更を復元で壊さないため。
  - decided_by: user (took the recommendation)
- A47 バックアップが有効なら --delete で通常ファイルを消す前に内容を集約先へ保存し、保存できなければ削除しない。保存したファイルは rollback で再作成する。
  - why: 明示的な削除も取り戻せるようにする。バックアップを無効化した操作は [A13（無効化時の書き込み）](./2026-09-25-spec-migration.md#A13) に従う。
  - decided_by: user (took the recommendation)
- A48 期限切れセッションの --force 復元は保存データが残っている間だけ可能とする。現在設定された書き込み先の期限切れデータは自動整理で削除され得る。
  - why: 強制復元できるとの約束と、期限切れデータを整理する運用が矛盾しないようにする。
  - decided_by: user (took the recommendation)
- A49 sudo=true をサーバごとに明示したときだけ権限を上げ、非対話の sudo が利用できないなら接続・書き込みを止めて、通常権限の SSH には切り替えない。
  - why: 権限不足を黙った経路変更で隠さず、意図しない権限昇格も避ける。
  - decided_by: user (took the recommendation)
- A50 TUI で選択中の差分をクリップボードへコピーし、確認した差分と集計をレポートへ出力できるようにする。機密ファイルの内容は既定で含めず、利用者が明示したときだけ含める。
  - why: 外部へ差分を持ち出す際にも機密ファイルの表示方針を維持する。
  - decided_by: user (took the recommendation)
- A51 merge・sync の内容比較で片側の読み取りが失敗したファイルは、同一や空の内容と扱わず、そのファイルの失敗として報告し、書き込みをしない。他のファイルは処理を続ける。
  - why: 読み取り不能を誤判定してデータを消さず、他のファイルの処理は続けられるようにする。
  - decided_by: user (took the recommendation)
- A52 機密ファイルを TUI のクリップボードまたはレポートへ含める場合は出力直前に対象と出力先を示して確認し、拒否されたら本文を出力しない。TUI の凍結にはこの確認操作の例外を設ける。
  - why: 持ち出し先を見せた上で利用者が内容の出力を選べるようにする。
  - decided_by: user (took the recommendation)
- A53 左右と書き込み先を明示し、対象の読み取りと必要な確認・バックアップが成功し、競合や外部更新がない通常ファイルの merge は、指定した先だけを元の内容に更新する。
  - why: 安全条件だけでなく、条件を満たした通常のマージの結果を明文化する。
  - decided_by: user (took the recommendation)
- A54 マージ後に末尾 symlink のリンク文字列を第三者が変えた場合、実際の到達先が同じでも rollback はセッション内の全件を書き戻さない。
  - why: 別表記への編集も第三者の変更として守り、復元で上書きしない。
