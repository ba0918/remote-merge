# CLI diff の root_dir の外かどうかの判定の基準の判断

## Context

CLI diff の symlink とディレクトリの取り込みで、設定の root_dir が symlink を経由するとき、diff が root_dir の中の通常のファイルまで "content not compared (outside root_dir; use --follow-external-links)" のエラーにして終了コード 2 を返すと確かめ、FLAG-cli-043 に残して、テスト整理の後に直すことにした（[A1](./2026-09-30-adopt-diff-links.md#A1)）。
実装は、ファイルの symlink を辿った後の実パスと、設定に書いた root_dir の文字列をそのまま前方一致で比べており、root_dir 自体を実パスに直していないことが原因と読める。
[REQ-cli-026](../../ir/cli/symlink-diff.md#REQ-cli-026) は root_dir 内の symlink を通常どおり辿り、root_dir の外へ出る参照先だけを --follow-external-links のときに辿るとしており、要件は変えずに判定の基準を決めて FLAG-cli-043 を外す。

## Agreements

- A1 diff がパスを root_dir の外かどうか判定するときは、root_dir をローカル・SSH・エージェントのどの経路でもファイルと同じ方法で実パスに直した場所を基準にし、設定に書いた root_dir の文字列と比べない。そのため、root_dir が symlink を経由していても、root_dir の中のファイルは root_dir の中として扱う。
  - why: ファイルの実パスと root_dir の書いたままの文字列を比べると、root_dir が symlink を経由するよくある配置で diff が使えなくなる。ファイルの実パスを調べる仕組みは三つの経路に共通のため、root_dir も同じ仕組みで直すと経路ごとの食い違いが出にくい。
  - rejected: ローカルの root_dir だけを実パスに直す案。リモートの経路で同じ食い違いが残る。
  - decided_by: 利用者（推奨を採用）
- A2 A1 の結果、root_dir が祖先のディレクトリを指す symlink（例 root_dir が "/srv" や "/" を指す）のとき、設定に書いた root_dir の外にあるファイルも実パスに直した root_dir の中として扱い、--follow-external-links なしで辿る。機密ファイルの内容を隠す処理はこれとは別に働く。
  - why: root_dir が実際に指す場所を root_dir とするのが A1 の考え方で、書いた文字列の外かどうかを別に判定すると判定が二重になり、root_dir が symlink を経由する配置で A1 と同じ食い違いが戻る。修正のレビューでこの帰結が決定に書かれていないと指摘された。
  - rejected: 設定に書いた root_dir の外も外として扱う案。判定が二重になり複雑になる。
  - decided_by: 利用者（推奨を採用）
- A3 root_dir 自体が存在しないときは、root_dir の外かどうかの判定の基準に設定に書いた root_dir の文字列を使う。
  - why: 実パスに直せないときの基準で、修正の前後で出力が変わらないことを実行で確かめた（ローカルは "No such file or directory"、SSH は root_dir の外のエラーで、どちらも終了コード 2）。存在しない root_dir の扱いそのものは既存の FLAG-config-005・006 で扱う。
  - decided_by: 利用者（推奨を採用）
- A4 diff が symlink の連鎖の各段のリンク文字列を root_dir の下に字面で辿れなくなったとき（例 リンク文字列が "../<root_dir の実ディレクトリ名>/mid" の形、または root_dir を指す別の名前の symlink を通る絶対パス）、その項目の実パスが root_dir の中にあれば、途中の段が機密パターンに当たるかを確かめられないため、機密ファイルと同じく --force なしでは内容を表示しない。連鎖が実際に root_dir の外へ出る場合は既存の FLAG-cli-051 のまま扱う。
  - why: 字面で辿れない段を機密でないとみなすと、実際には root_dir の中にとどまる連鎖の途中の機密の名前を見ないまま内容を表示し、REQ-cli-023 に反する。修正のレビューで指摘され、確かめられないときは隠す側に倒すことを選んだ。機密でないリンクも隠れる場合があるが、--force で表示できる。
  - rejected: 各段を実パスで辿り直す案。リモートの経路で段ごとに解決する仕組みが要り大きいため、別に扱う。字面で辿れない段を機密でないとみなしたまま FLAG に残す案。symlink を経由する root_dir では今回の修正で漏れが新たに表に出る。
  - decided_by: 利用者（推奨を採用）
- A5 未決の FLAG として残す。[REQ-cli-023](../../ir/cli/symlink-diff.md#REQ-cli-023) は入れ子の各段階のリンク文字列が機密パターンに当たれば root_dir の内外を問わず --force なしでは内容を表示しないとするが、diff の機密の連鎖の判定はリンク文字列を字面で結んで次の段を求めるため、OS が途中のディレクトリ symlink を先に解決してから ".." を当てる場合（例 ディレクトリ symlink "linkdir" の中の "a.txt" が "../mid" を指す）に別のファイルを指したと判定し、途中の段の機密パターンに当たる名前を見ないまま、root_dir の中の最終参照先の内容を --force なしで表示しうる。また連鎖の最初の項目の実パスが root_dir の外にあるときは、root_dir の外へ出る前の root_dir の中の段も字面で辿れなければ見ない。これらは修正の前からある経路で、実装を読んで分かったことで未実行。直し方は、各段を OS が解決した実パスで辿る判定への作り直しとして次に扱う。
  - why: 字面で辿る判定に継ぎ足して直すと、レビューのたびに別の迂回が見つかり収束しないため、判定の作り直しとして区切って扱う。REQ-cli-023 と食い違い、機密の内容の表示に関わる。
  - decided_by: 利用者（推奨を採用）
- A6 未決の FLAG として残す。A4 の結果、機密パターンに当たる名前を含まない連鎖でも、リンク文字列が "../<root_dir の実ディレクトリ名>/target.txt" や root_dir の別名を通る絶対パスの形で字面で辿れず実パスが root_dir の中にあると、--force なしでは参照先の内容差を表示しない。[REQ-cli-020](../../ir/cli/symlink-diff.md#REQ-cli-020) と例 EX-cli-040 は参照先の内容差を示すとする。
  - why: 漏れを防ぐために隠す側に倒した結果で、各段を実パスで辿る判定に作り直せば字面で辿れない場合がなくなり解消する見込みのため、作り直しのときに合わせて決める。
  - decided_by: 利用者（推奨を採用）
