# merge の書き込みの中身を kotowari に取り込む際の判断

## Context

merge を 4 回に分けて取り込むうちの 2 回目で、書き込みの中身（比べ方、読めないファイル、書き込み直前の更新確認、権限、指定先だけの更新、バイナリの転送）を扱う。
これらの要件（[REQ-merge-005](../../ir/merge/comparison.md#REQ-merge-005)、[REQ-merge-006](../../ir/merge/comparison.md#REQ-merge-006)、[REQ-merge-011](../../ir/merge/concurrency.md#REQ-merge-011)〜[REQ-merge-014](../../ir/merge/permissions.md#REQ-merge-014)、[REQ-merge-017](../../ir/merge/read-failure.md#REQ-merge-017)、[REQ-merge-018](../../ir/merge/basic.md#REQ-merge-018)、[REQ-cli-010](../../ir/cli/binary.md#REQ-cli-010)）は旧仕様の移行時に作られたが、実装・旧資料・テストとの突き合わせが済んでいなかった。
旧資料（[旧総合仕様](../../archive/spec.md) のディレクトリマージ時の削除セマンティクス・楽観的ロック・sudo 対応とファイルパーミッション管理・設定のパーミッションの項目、[旧個別仕様 symlink-merge](../../archive/spec/symlink-merge.md) の 3.8〜3.11、既存要件）と、入口 `merge` と `sync`（パス、--checksum、--with-permissions）から見える現行実装・テストを突き合わせ、一致するものは現状を仕様として追認し、食い違い・欠落・曖昧さは FLAG として未決のまま残す。
既存要件 REQ-merge-005、REQ-merge-006、REQ-merge-011、REQ-merge-013、REQ-merge-017、REQ-merge-018、REQ-cli-010 は実装と一致したため変更しない。REQ-merge-012 と REQ-merge-014 は書き換えず、食い違いと曖昧さを FLAG に残す。symlink 同士の比べ方と削除は symlink と削除の回、sudo のときの所有者の復元は SSH、ハッシュで中身を比べる経路は status の話題で扱う。
要件は各文書で 3 件以下のため、既存の文書に足す。
テストの内訳（対象 26 件）: 要件の根拠 26 件、FLAG の挙動のテスト 0 件、実装詳細をなぞるだけ 0 件、残す 0 件。

## Agreements

- A1 旧資料と現行実装が一致するため、レビューなしで仕様とする。旧資料は merge・sync の中身の読み比べでどちらか片側でも読み取りに失敗したファイルを failed に出し error を "read failed: <原因>" とするとし、実装は error を "read failed: " に続けて、読めなかった側ごとの "left: 原因" と "right: 原因" を "; " でつないだものとする。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A2 旧資料と現行実装が一致するため、レビューなしで仕様とする。旧資料は --checksum のないディレクトリ指定の merge と sync を status の既定と同じくサイズと更新日時で判定し、サイズと更新日時で変更ありと判定した組のうちサイズが同じものだけ中身を読み比べ、同じサイズ・同じ更新日時で中身が違うファイルは書かないとし、実装も同じように判定し、読み比べて中身が同じ組は書かない。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A3 旧資料と現行実装が一致するため、レビューなしで仕様とする。旧資料はディレクトリ単位のマージで、中身の違うファイルを上書きし、マージ元にだけあるファイルをマージ先に作り、中身が同じファイルは書かないとし、実装もディレクトリを指定した merge でそのとおりに書き込む。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A4 現行実装をレビューなしで仕様とする。実装は複数のパスを指定した merge で指定したそれぞれのパスを書き込み、同じパスを重ねて指定しても一度だけ書き込む。
  - why: 旧資料に記述はないが利用者に見える挙動をテストが確かめており、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A5 未決の FLAG として残す。[旧個別仕様 symlink-merge の 3.9](../../archive/spec/symlink-merge.md) は中身まで同じファイルを明示した merge で書かずに skipped に reason "identical" を出すとするが、実装は skipped を空にし、テキストでは "no files to merge in the specified path(s)" を出す。
  - why: 旧資料と実装が食い違い、どちらに合わせるかは次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A6 未決の FLAG として残す。REQ-merge-014 は --with-permissions を指定したとき読み込み元のファイル権限を書き込み先に反映するとするが、実装は読み込み元がローカルのときだけ権限を写し、読み込み元がリモートのときは何も知らせずに写さず、新しく作るファイルには設定された権限も付けない。
  - why: 既存要件と実装が食い違い、どちらに合わせるかは次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A7 未決の FLAG として残す。--with-permissions を指定して新しいファイルを作るとき、実装は書き込み先に設定された権限ではなく読み込み元の権限を付ける。新規作成は設定された権限にするという REQ-merge-012 と、読み込み元の権限を反映するという REQ-merge-014 のどちらを優先するかを IR は決めていない。
  - why: 読んだ後も既存要件と一致するか食い違うかの確信が持てず、次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）

  - why: 利用者に見える挙動に仕様とテストが欠けており、次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）

  - why: 利用者に見える挙動に仕様とテストが欠けており、次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）

  - why: 読んだ後も旧資料と実装が一致するか食い違うかの確信が持てず、次にこの機能を扱うときに決める。
