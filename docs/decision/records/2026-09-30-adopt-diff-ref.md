# CLI diff の --ref の参照先と競合を kotowari に取り込む際の判断

## Context

CLI diff の差分の出し方と symlink の取り込みに続き、--ref で参照先を加えた三者比較の diff（参照先との差、競合の数と場所、参照先が左右と同じときの扱い）を取り込む。
旧資料（[旧総合仕様](../../archive/spec.md) の使い方の例と diff の JSON の例、利用者向けの手引き "skills/remote-merge/SKILL.md" の --ref、"skills/remote-merge/references/json-schemas.md" の diff の節、既存の要件 [REQ-cli-011](../../ir/cli/reference.md#REQ-cli-011)・[REQ-cli-016](../../ir/cli/conflicts.md#REQ-cli-016)・[REQ-cli-017](../../ir/cli/conflicts.md#REQ-cli-017) と用語「参照先」「競合」）と実装・テストを突き合わせ、一覧を出す前に別の文脈で各行を実装と照らし合わせた。一致するものは現状を仕様として追認し、食い違い・欠落は FLAG として未決のまま残す。
既存の要件は diff から見える部分で実装と一致するため変えない。REQ-cli-011 と REQ-cli-017 の merge・sync の部分は merge と sync の取り込みで扱い済み、status の --ref は status の取り込みで扱い済み、TUI の三者比較は凍結中の TUI で扱う。
CLI の FLAGS.md は limits.lines を超えたままになるが、[差分の出し方の記録](./2026-09-29-adopt-diff-output.md)と同じく、中身は CLI の一つの責務（コマンドの振る舞いの未決事項）に揃っているため分けない。
テストの内訳（対象 57 件）: 要件の根拠 39 件、FLAG の挙動のテスト 3 件、実装詳細をなぞるだけ 0 件、残す 15 件。ref_guard の単体テスト 4 件は status と merge の取り込みでも要件の根拠に数えている。

## Agreements

- A1 旧資料と現行実装が一致するため、レビューなしで仕様とする。旧総合仕様は diff に --ref を付けた例を 3way diff とし、利用者向けの手引きは --ref を三者比較の参照先のサーバとする。実装は --ref に設定のサーバ名か "local" を指定すると参照先を加えた三者比較をし、設定にないサーバ名なら "Server '<名前>' not found in config" のエラーで終了コード 2 を返す。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A2 旧資料と現行実装が一致するため、レビューなしで仕様とする。旧総合仕様は diff の JSON の ref_hunks を 3way 比較時のみ出すとする。実装は --ref のとき各ファイルに "ref"（参照先の label と root）と、左から参照先への差 "ref_hunks"（左と同じなら空の配列）を出し、参照先のファイルを読めないときは "ref" だけを出し、--ref がなければどちらも出さない。"ref" の欄は旧資料の diff の例になく、実装とテストから追認する。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A3 現行実装をレビューなしで仕様とする。diff のテキストは、参照先との差が空でなければ、左右の差の後に "--- ref:<参照先>:<パス> (reference diff vs left)" の見出しと、左から参照先への差の hunk を出す。
  - why: 旧資料に記述はないが利用者に見える振る舞いでテストがあり、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A4 旧資料と現行実装が一致するため、レビューなしで仕様とする。旧総合仕様は diff の JSON の conflict_count を 0 のとき省略し、conflict_regions を 3way 比較時のみ出すとする。実装は競合があるファイルに JSON で "conflict_count"（競合の数）と "conflict_regions" を出し、テキストで "Conflicts: N region(s) where both sides changed the same lines differently" を出し、複数のファイルのテキストの末尾に "N conflict(s) detected across files" を出す。競合がなければどれも出さない。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）

  - why: 旧資料に記述はないが利用者に見える振る舞いでテストがあり（status の REQ-cli-037 と同じ振る舞い）、利用者が一覧から外さなかった。
