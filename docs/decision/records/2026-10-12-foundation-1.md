# 土台の段 1: root_dir からの相対パスを型にする

## Context

[土台の作り直し](./2026-10-12-foundation.md) の段 1 である。土台の監査では、root_dir からのパスの検査が 8 か所以上にあり、意味が 3 通りに割れていた。入力の形を拒むもの（絶対パスと ".."）、".." を字面で畳んで root の外だけを拒むもの、実パスを求めて root の外を拒むもの（エージェントだけ）である。そのため、同じ "a/../b" をローカルの確認は拒み、読み込みは畳んで読む。エージェントだけが root_dir の外を指す途中の symlink 越しの読み書きと、".." や絶対パスをリンク先に持つ symlink の作成を拒む（FLAG-merge-012）。

Position: 段 1 は終わった（B1〜B9）。

## Agreements

- B1 root_dir からの相対パスは、入力の形を検査して作る一つの型だけで受け渡す。検査はコマンドの入口（[REQ-cli-078](../../ir/cli/diff-output.md#REQ-cli-078)・[REQ-merge-007](../../ir/merge/symlink.md#REQ-merge-007)）と、エージェントが通信で受け取る入口の二か所だけで、同じ関数で行う。経路の操作はこの型を受け取り、自分では入力の形を検査しない。
  - why: 型で受け取れば、検査をし忘れた経路も、検査を別の意味で書き直した経路も作れない。
  - decided_by: 利用者（[foundation A4](./2026-10-12-foundation.md#A4) から導いた。自走の指示により書き下ろした）
- B2 経路は、root_dir の外かどうかを字面でも実パスでも判定しない。パスを辿る必要があるところは、[REQ-paths-001](../../ir/paths/resolution.md#REQ-paths-001) のパスの確認を使う。
  - why: [REQ-merge-004](../../ir/merge/symlink.md#REQ-merge-004) は root_dir の外の共有ディレクトリへの途中の symlink 越しの書き込みを求め、入力に ".." がないことは B1 の型が保証する。字面で畳む判定と実パスの判定は、どちらも IR にない第三・第四の規則だった。
  - decided_by: 利用者（[foundation A3](./2026-10-12-foundation.md#A3) から導いた。自走の指示により書き下ろした）
- B3 エージェントは、root_dir の外を指す途中の symlink 越しの読み書きと、".." や絶対パスをリンク先に持つ symlink の作成を拒まず、ローカルと SSH と同じ結果にする。FLAG-merge-012 はこれで閉じる。
  - why: 利用者の基準（経路で挙動を変えない）と、旧仕様の symlink-merge 3.4・3.5 が同じ向きを指す。今はエージェントだけが拒み、sudo のサーバではその書き込みが失敗する。
  - decided_by: 利用者（2026-10-05 の品質の基準「経路によって挙動が変わるのは絶対に直す」から導いた。自走の指示により書き下ろした）
- B4 パスを辿る手順そのもの（ローカルとエージェントが同じ関数を呼ぶもの）は段 1 では作り直さない。SSH の経路の辿り方は段 3 で、同じ純粋な手順にまとめて尋ねた事実を渡す形に替える。
  - why: 監査で、この手順はすでに一つの関数で IR の例どおりに書かれていると分かった。手を入れる価値は SSH の経路が別の言語（POSIX sh）で同じ手順を書き直していることにあり、それは段 3 の範囲である。
  - decided_by: 利用者（[foundation A7](./2026-10-12-foundation.md#A7) から導いた。自走の指示により書き下ろした）
- B5 エージェントの単体テストのうち、root_dir の外を指す途中の symlink 越しのパスを拒むこと（file_io の `symlink_escaping_root_rejected`）と、".." や絶対パスをリンク先に持つ symlink の作成を拒むこと（file_io の `symlink_target_traversal_rejected`・`symlink_absolute_target_rejected`、dispatch の `symlink_traversal_returns_error`）を確かめていたものは、拒まないことを確かめるテストに置き換える。今後も、IR と違う動きを固めたテストに当たったら、同じ扱いで IR に合わせて直し、この記録に B 番号で残す。
  - why: テストが [REQ-merge-004](../../ir/merge/symlink.md#REQ-merge-004)・[REQ-merge-023](../../ir/merge/symlink.md#REQ-merge-023) と違う動きを固めていたので IR に合わせた（[foundation A6](./2026-10-12-foundation.md#A6)）。
  - decided_by: 利用者（foundation A6 から導いた。自走の指示により書き下ろした）
- B6 CoreRuntime の Side 単位の API（製品の runtime の side_io）が文字列のパスを受け取り、同じ検査の関数で RelPath（一つの項目への操作では EntryPath）にしているのは、入口の検査ではなく、呼び出し側が持つ内部の文字列（引数から作った値と走査の結果）を型にする変換として扱う。段 4・5 で呼び出し側を作り直し、パスを RelPath のまま渡すようにしたときに消す。バックアップの記録の読み込みは、コマンドの入口・エージェントの受け取り口と並ぶ受け取り口の一つとする（記録は集約先の外から書き換えられうるデータなので）。
  - why: B1 は検査を二か所に置くとするが、段 1 では呼び出し側の cli と service は文字列のパスで動き続ける。それを今作り直すと段 4・5 の範囲を先取りするので、変換として残し、消す時期を決めておく。
  - decided_by: 利用者（[foundation A7](./2026-10-12-foundation.md#A7) から導いた。自走の指示により書き下ろした）
- B7 段 1 で上げた通信の版 10 が運ぶのは、受け取ったパスを入力の形の検査で拒んだこと（項目の操作の要求で root_dir 全体を項目として拒んだ理由を含む）だけである。[foundation A9](./2026-10-12-foundation.md#A9) の失敗の種類（A2）は、段 3 で経路の操作に失敗の型を入れるときに運び、そのとき通信の版を 11 に上げる。
  - why: 段 1 で失敗の型を先に通信に載せると、経路の操作の失敗の型（段 3）より前に通信の形を決めることになる。版は通信の形が変わるたびに上げる。
  - decided_by: 利用者（[foundation A7](./2026-10-12-foundation.md#A7) から導いた。自走の指示により書き下ろした）
- B8 root_dir 全体を表す値と root_dir の下の項目を別の型にし、項目の操作は項目の型（EntryPath）だけを受け取る。範囲の値が項目の操作に届く誤りを型で起きなくする。項目の型は、RelPath から変換して root_dir 全体なら型の理由（"root_dir itself is not an entry: 値"）で拒むものと、文字列から直接作るもの（RelPath の検査に root_dir 全体の拒否を足したもの）の二つだけで作れる。ローカル・SSH・エージェントの経路で、書き込み・削除・権限の変更・symlink の作成・読み込み・stat・ハッシュ・項目のリンク先・大きさは項目の型を、走査・子の一覧・パスの確認は RelPath を受け取る。エージェントの受け取り口は項目の操作の要求のパスを項目として検査して型の理由で拒み、バックアップの記録の読み込みも root_dir 全体を指す記録を解析できない記録にする。段 1 で "/" を絶対パスとして拒んでいたテスト（core の operations で chmod に "/" を渡していたもの）を代わりなしに消していたので、その代わりは次のテストとする。ローカルの経路で root_dir 全体を指す値（"/"・"."・""・"//"・"./"）を項目の操作に渡しても root_dir の権限と中身が変わらないことを確かめるテスト。SSH とエージェントの CoreRuntime の経路で、同じ値が経路に届く前に型にするところで止まることを確かめるテスト（エージェントには要求が届かない）。起動したエージェントの受け取り口が要求の種類ごとに root_dir 全体を拒み、root_dir の権限と中身を変えないことを確かめるテスト。項目の型が root_dir とつないで root_dir 自身にならないことを任意の入力で確かめるテスト。
  - why: RelPath::parse は "/"・"//"・"."・"./"・空の値を root_dir 全体として通すが、経路の操作（削除・権限の変更・書き込み・symlink の作成）には root_dir 全体を拒む関門がなかった。そのため権限の変更は root_dir そのものの権限を変え（どの形でも 755 から 700 に変わることをレビュー役が確かめた）、エージェントも通信で root_dir 全体を指す権限の変更を受けるとそのまま行い、バックアップの記録の読み込みも root_dir 全体を指すパスを通していた。操作ごとに root_dir 全体の判定を足す形では、足し忘れた操作から同じ誤りが再び起きる。
  - decided_by: 利用者（2026-10-12、『直して。根本的に再発しない作りにする』）
- B9 テストは利用者のファイル（~/.ssh/known_hosts など）に触れない。SSH の接続に使う known_hosts の場所は接続の設定（SshConfig の known_hosts）で差し込めるようにし、製品の既定は今のまま利用者の ~/.ssh/known_hosts とする。プロセスの中で偽の SSH サーバにつなぐテストは一時ディレクトリの known_hosts を差し込み、CLI を動かすテストは HOME を一時ディレクトリにした子プロセスで動かす。テスト用の機能を有効にした組み立てでは、差し込まずに利用者本人の known_hosts（アカウントのホームディレクトリの下のもの）を使おうとすると panic する。本物のファイルを読み書きするテストは書かない。これはテストの規則なので IR には入れず、この記録とテストの補助のコメントに書く。
  - why: プロセスの中で偽の SSH サーバにつなぐテストが、利用者の ~/.ssh/known_hosts に `[127.0.0.1]:<ポート>` の行を書き足し（1751 行たまり、利用者が手で消した）、ポートが使い回されるとそのファイルを読み書きして行を消すテストもあった。並行に走るテストで環境変数 HOME を書き換えると、ほかのテストの HOME も変わる。
  - decided_by: 利用者（2026-10-13、テストの隔離の指摘）
