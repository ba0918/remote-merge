# merge の書き込みの中身のテスト整理で残った問題を FLAG として残す判断

## Context

merge の書き込みの中身のテスト整理（[計画](../../plans/merge-write-test-cleanup.md)）で、変異テストの見逃しは [テスト手法の選び方の A8](./2026-09-27-test-method-selection.md#A8) に従い、テストの追加・同等変異の登録・FLAG の記録のどれかで決着させる。
整理後に残った見逃しのうち、読み込み元の権限の値が 0 のときに書き込み先の権限を変えるかを変える 2 件は、IR がその場合の振る舞いを決めておらず、落とせるテストは読み込み元の権限が読み込みの後に変わる競合と実装の読み取りの回数に依存する。
これを仕様として決めずに、次にこのトピックを扱うときの論点として残す。経緯は "docs/testing/merge-write-test-cleanup.md" にある。

## Agreements

- A1 未決の FLAG として残す。--with-permissions の merge で読み込み元がローカルのとき、実装は読み込み元の権限の値が 0（mode 000）なら書き込み先の権限を変えずに残す。REQ-merge-014 は読み込み元のファイル権限を書き込み先に反映するとし、字のとおり読むと 0 も反映することになるが、IR はこの場合を決めていない。読み込み元は中身を読んだ後に権限を読むため、この違いは読み込みと権限の読み取りの間に読み込み元の権限が 0 に変わったときにだけ起きる。変異テストの見逃し 2 件（src/service/merge_flow.rs の copy_permissions で権限の値が 0 より大きいかの条件を変えるもの）はこの違いでしか検知できない。
  - why: 利用者の判断。権限 0 を反映するかは仕様の判断で、テスト整理の中では決めない。
  - decided_by: user (took the recommendation)
