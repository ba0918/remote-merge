# 品質レビュー 1 回目の判断のうち merge と sync の書き込みに関わるもの

## Context

2026-10-05 の品質レビュー 1 回目（main c90cc54）で、merge と sync のパスの検査・更新時刻の判定・両側にないパス・権限の複製が、経路や dry-run かどうかで違う結果になることが分かった。
利用者は 2026-10-05 に判断 D1〜D32 をすべて推奨どおり採用した（「推奨ではじめて」）。D2 の拒否の単位と D8 の精度は利用者と詰めた答えを採った。
この記録はそのうち merge と sync の書き込みに関わる判断を扱う。diff 側と CLI の終了コードは [2026-10-05-quality-cli.md](./2026-10-05-quality-cli.md) に置く。

## Agreements

- A1 merge と sync は、パスの引数が絶対パスか ".." の要素を含むとき、どの経路でも、走査や書き込みの前の引数の段階でコマンド全体を今の文言 "absolute subpath not allowed: パス" か "path traversal not allowed: パス" のエラーで止め、終了コード 2 を返し、どのファイルも書き込まない。root_dir 全体を指す "/" の指定は従来どおり受け付ける（D2）。
  - why: 絶対パスと ".." の引数がローカル・SSH・エージェントで 3 通りの意味になっていた（指摘 routes-11・merge_sync-10）。FLAG-merge-011 を閉じるため、利用者は拒否の単位をコマンド全体とし、文言を今のままにした。旧資料のように 1 ファイルだけ failed にする案より、引数の誤りは他のファイルを処理する前に止めるほうが安全で、今の merge とも合う。承認済みの [REQ-merge-007](../../ir/merge/symlink.md#REQ-merge-007) の「そのパスの書き込みを拒否」をこの意味に書き直す。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D2 を推奨どおり採用。拒否の単位は利用者が詰めた答え）
- A2 --checksum のないディレクトリ指定の merge と sync が、サイズと更新時刻が同じとして中身を読まずに書かないのは、両側がともに秒より細かい精度の更新時刻を持ち、両側に共通する最も細かい精度で比べて同じときに限る。片側でも更新時刻が秒の精度しかなく秒が同じときは中身を読み比べ、中身が違えば書く（D8）。
  - why: 更新時刻の精度が経路で違い、同じ組でも経路によって判定が変わっていた（指摘 routes-9・status_scan-12）。利用者は各側が出せる最も細かい精度で比べ、秒しかない側で秒が同じなら中身で比べることにした。status 側は [2026-10-05-quality-cli.md の A3](./2026-10-05-quality-cli.md#A3) に置く。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D8 を推奨どおり採用。比べる精度は利用者が詰めた答え）
- A3 merge と sync は、指定したパスが左右のどちらにもないとき、diff と同じくパスごとに警告を出してそのパスを failed に入れ、指定したパスがすべてないときはエラーで止める。--dry-run でも同じにする（D12）。
  - why: dry-run は "Would merge" と終了コード 0 を出し、実行時は経路ごとの読み込みエラーになっていた（指摘 merge_sync-16）。diff の既存の [REQ-cli-057](../../ir/cli/diff-output.md#REQ-cli-057) に合わせる。failed の error の文言は [A5](#A5) で実装者に委ねた。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D12 を推奨どおり採用）
- A4 --with-permissions の merge と sync は、新しく作るファイルにも読み込み元の権限を付ける（[REQ-merge-014](../../ir/merge/permissions.md#REQ-merge-014) を [REQ-merge-012](../../ir/merge/permissions.md#REQ-merge-012) より優先する）。読み込み元の権限は、ローカルとリモートのどちらでも走査したツリーの値を使う。書き込み先の権限の変更に失敗したら、そのファイルを中身は書いたことが分かる error で failed に出し、終了コード 2 を返す（D25）。
  - why: 明示した指定を優先する。今はリモートの読み込み元では何もせず、権限の変更の失敗も "ok" のままだった（指摘 merge_sync-7）。中身は書けたのに failed になるため、再実行で同じ中身を書き直すことになる。error の文言は [A5](#A5) で実装者に委ねた。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D25 を推奨どおり採用）
- A5 指定したパスが両側にないときの警告と failed の error（[A3](#A3)）、権限の変更に失敗したときの中身は書いたことが分かる error（[A4](#A4)）の文言は IR で決めない。実装者が分かる英語の文言を書き、テストはその文言を固定しない（E8）。
  - why: これらの判断は文言を決めていなかった。利用者は、決めていない文言を IR に固定せず、実装に委ねることにした。A4 の error が中身を書いたことを示すこと自体は求める。
  - decided_by: 利用者（2026-10-05、詳細 E8 を推奨どおり採用）
