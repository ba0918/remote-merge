# 品質レビュー 1 回目の判断のうち SSH とエージェントの経路に関わるもの

## Context

2026-10-05 の品質レビュー 1 回目（main c90cc54）で、sudo=true のサーバでもエージェントにない操作（削除・権限の変更・子の一覧）が通常権限の SSH で行われ、[REQ-ssh-009](../../ir/ssh/sudo.md#REQ-ssh-009) の「通常権限の経路に切り替えない」を迂回していることが分かった。
また接続が切れたときに一度だけ再試行する読み取りが、ファイルの読み込みの一部に限られていた。
利用者は 2026-10-05 に判断 D1〜D32 をすべて推奨どおり採用した（「推奨ではじめて」）。D31 は承認済みの [REQ-ssh-003](../../ir/ssh/reconnect.md#REQ-ssh-003) の範囲を書き換える。
この記録はそのうち SSH とエージェントの経路の判断を扱う。

## Agreements

- A1 sudo=true のサーバへの削除・権限の変更・子の一覧はエージェントで行う。そのためにエージェントの通信の操作に Remove・Chmod・ListDir を足し、通信の版を上げる（D1）。
  - why: sudo=true でも通常権限の SSH で動き、REQ-ssh-009 を迂回していた（指摘 routes-4・ssh_agent-8・merge_sync-1・merge_sync-6）。通信の版を上げるので、リリースと、配置済みの全サーバのエージェントの再配置が要る。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D1 を推奨どおり採用）
  - superseded_by: [A1 (agent-operations)](./2026-10-11-agent-operations.md#A1)
- A2 [A1](#A1) の操作がエージェントに入るまで、A1 の要件は後回しにする。その間、sudo=true のサーバで SSH 側の実装に落ちる操作は、REQ-ssh-009 と同じく通常権限の SSH 経路で行わずに明示的なエラーにする（D1）。
  - why: D1 の推奨は、操作を足すまでの間を暫定のエラーで埋めることまでを含む。暫定のエラーだけなら通信の版は変わらないが、sudo=true の削除と --with-permissions はその間使えなくなる。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D1 を推奨どおり採用）
  - superseded_by: [A1 (agent-operations)](./2026-10-11-agent-operations.md#A1)
- A3 SSH の読み取りだけのリモート操作は、ファイルの読み込みに限らず、走査・stat・種類の調べ・子の一覧・ハッシュ・書き込み前の確認を含めて、接続が切れたら一度だけ再接続して再試行する。書き込みは [REQ-ssh-004](../../ir/ssh/reconnect.md#REQ-ssh-004) どおり繰り返さない。承認済みの REQ-ssh-003 の「読み取り」をこの範囲に書き換える（D31）。
  - why: 今はファイルの読み込みの 4 関数だけが再試行し、走査は接続断でそのまま失敗していた（指摘 ssh_agent-20）。接続断が続く環境では失敗までの時間が延びる。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D31 を推奨どおり採用。承認済みの REQ-ssh-003 の書き換えとして利用者が決めた）
