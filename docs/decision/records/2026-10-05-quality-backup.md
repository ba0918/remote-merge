# 品質レビュー 1 回目の判断のうちバックアップと rollback に関わるもの

## Context

2026-10-05 の品質レビュー 1 回目（main c90cc54）で、バックアップの書き込み先の識別が root_dir の書き方で分かれ、壊れた集約先を黙って飛ばし、同じ種類の入出力エラーが段階によって違う扱いになることが分かった。
利用者は 2026-10-05 に判断 D1〜D32 をすべて推奨どおり採用した（「推奨ではじめて」）。
相対の [local] の root_dir の基準を設定ファイルの場所に変える判断（[2026-10-05-quality-config.md の A5](./2026-10-05-quality-config.md#A5)）は書き込み先の識別を変え、既存のセッションが一覧から消えるため、利用者は書き込み先のキーの正規化（D24）と一緒に移行を決めた。
この記録はそのうちバックアップと rollback の判断を扱う。

## Agreements

- A1 書き込み先のキーの root_dir は、ローカルとリモートのどちらでも字面で正規化して決める。"." の要素と末尾の区切りを除き、続いた区切りを一つにし、symlink は辿らない。ローカルの root_dir は、相対パスならその root_dir を書いた設定ファイルのあるディレクトリを基準にした絶対パスにしてから正規化する。今の書き込み先のセッションを一覧し rollback するときは、正規化したキーに加えて、正規化する前の字面のキーと、ローカルなら設定読み込み時のカレントディレクトリを基準にした以前のキーでも探し、見つかったセッションを今の書き込み先のセッションに含める（D16・D24）。
  - why: "/srv/app/" と "/srv/app"、"./proj" と "proj" が別の書き込み先になり、設定を書き換えると rollback --list に出なくなっていた（指摘 backup_rollback-11）。相対の基準を変えるとキーがもう一度変わるので、同じ移行で扱う。利用者は既存のセッションが見えなくならないことを条件に、承認済みの [REQ-backup-021](../../ir/backup/sessions.md#REQ-backup-021) を書き換えることにした。古いキーを探す処理を残す期間と、古いキーのセッションを期限切れの整理の対象にするかは [A5](#A5) で決めた。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D16 と D24 を推奨どおり採用。二つを一緒に決め、移行を条件にした）
- A2 rollback で戻す先にファイルがなく、親のパスが通常ファイルに変わっているときは、親ディレクトリがないときと同じく、そのファイルを書き戻さずスキップ理由 "parent directory no longer exists" を報告する（D13）。
  - why: どの経路もこのスキップを出さなかった（指摘 backup_rollback-2）。[REQ-backup-003](../../ir/backup/rollback-path.md#REQ-backup-003) の「辿れない」としてセッション全体を止める案もあるが、ディレクトリがもうない状況なので [REQ-backup-031](../../ir/backup/rollback-path.md#REQ-backup-031) が自然である。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D13 を推奨どおり採用）
- A3 集約先のセッションの記録がない（NotFound）ときだけを、記録を消されたセッションとして [REQ-backup-041](../../ir/backup/rollback-cli.md#REQ-backup-041) のとおりセッションなしとして扱う。集約先の中身の読み込みか解析に失敗したときは隠さず、そのパスと理由を示すエラーで止める（D23）。
  - why: 読めないセッションを黙って落とし、rollback が古いセッションを戻しうる（指摘 backup_rollback-4）。手で壊した集約先があると rollback --list まで失敗する。壊れたセッションだけを除いて一覧する案は、--session なしの rollback が古いセッションを選ぶ危険が残る。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D23 を推奨どおり採用）
- A4 セッション ID の予約、集約先や書き込み先ごとの領域や一時的な保存場所の作成、予約の読み取りが入出力エラーで失敗したときは、どの段階でも、書き込む前にコマンド全体をエラーで止める。ファイルの書き換え前の内容を保存できないときの [REQ-backup-002](../../ir/backup/storage.md#REQ-backup-002)（そのファイルを書かず他を続ける）は変えない（D26）。
  - why: 集約先や予約の作成の失敗は各ファイルの "backup failed" になり、予約の読み取りや作成の失敗はコマンドを止める、と同じ種類のエラーが 2 通りに扱われていた（指摘 backup_rollback-14）。集約先そのものが使えないときは全ファイルが保存できないので、最初に止めるほうが分かりやすい。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D26 を推奨どおり採用）
- A5 [A1](#A1) の以前のキーでセッションを探す処理は期限を設けずに残す。以前のキーで保存したセッションも、今の書き込み先のセッションとして [REQ-backup-009](../../ir/backup/sessions.md#REQ-backup-009) の期限切れの自動整理の対象にする（E5）。
  - why: A1 は探す処理を残す期間と整理の対象にするかを決めていなかった。期限を設けると、それより古い版で作ったセッションが一覧から消える。整理の対象にしないと、以前のキーのセッションがいつまでも残る。
  - decided_by: 利用者（2026-10-05、詳細 E5 を推奨どおり採用）
