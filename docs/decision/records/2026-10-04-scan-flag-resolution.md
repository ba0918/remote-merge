# 走査の FLAG のうち判断のいらない三件を直す判断

## Context

2026-10-04 に利用者は、未決の FLAG を仕分けし、利用者の判断がいらないものを全て対処するよう指示した。
読み取りだけの仕分けで、走査の FLAG のうち FLAG-scan-008・011・014 の三件は、承認済みの要件が一意に読め、実装がそれに反しているだけと分類された。
三件ともエージェントの経路または sync の部分走査の実装の欠陥で、要件の文は変えずに実装を要件に合わせる。
通信の形（エージェントの応答の項目）は変えない。

## Agreements

- A1 FLAG-scan-008 を閉じる。root_dir がディレクトリへの symlink で include を設定したとき、エージェントの経路の走査も include の配下を一覧に載せるよう実装を直す。
  - why: [REQ-scan-007](../../ir/scan/listing.md#REQ-scan-007) は root_dir 自体がディレクトリへの symlink のとき配下を列挙すると定め、include の有無で例外を設けていない。実装は include の起点を正規化した実パスにする一方で一覧の相対パスを正規化していない root_dir から求め、全項目を捨てていた。ローカルの経路は正規化した root_dir を基準にして載せている。
  - decided_by: AI（2026-10-04 の利用者の指示「判断がいらないものは全て対処」による委任。仕分けの推奨を採用）
- A2 FLAG-scan-011 を閉じる。エージェントの経路の走査は、件数が上限とちょうど同じで次の項目がないとき打ち切りを報告しないよう実装を直す。
  - why: [EX-scan-009](../../ir/scan/limits.md#EX-scan-009) はファイル数が上限以下なら件数の上限を理由に一覧を打ち切らないと定める。実装は上限に達した時点で残りの有無を見ずに打ち切りと報告していた。ローカルと SSH の経路は次の項目が来たときだけ打ち切る。何を一件と数えるかは FLAG-scan-010 として未決のまま変えない。
  - decided_by: AI（2026-10-04 の利用者の指示「判断がいらないものは全て対処」による委任。仕分けの推奨を採用）
- A3 FLAG-scan-014 を閉じる。同じ最上位のディレクトリの下のディレクトリを二つ以上指定した sync も、それぞれのディレクトリの配下を走査して扱うよう実装を直す。
  - why: [TBL-scan-001](../../ir/scan/limits.md#TBL-scan-001) は全て末尾が "/" のときそれぞれのディレクトリの下を走査すると定め、[REQ-cli-045](../../ir/cli/sync.md#REQ-cli-045) は dry-run が書き込む予定のファイルを merged に並べると定める。実装は後のディレクトリの配下を一覧から落とし、ディレクトリのパスを書き込みの失敗や予定として出していた。同じ指定の merge は両方の配下を扱っている。
  - decided_by: AI（2026-10-04 の利用者の指示「判断がいらないものは全て対処」による委任。仕分けの推奨を採用）
