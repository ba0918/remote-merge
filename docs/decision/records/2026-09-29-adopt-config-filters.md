# 設定のフィルターを kotowari に取り込む際の判断

## Context

設定の読み込みと合成、値の検査に続き、exclude・include・sensitive のパターンがどのパスに当たるかを取り込む。
フィルターの IR は旧仕様の移行時に、除外が表示と操作の両方に効くこと（[REQ-config-003](../../ir/config/filters.md#REQ-config-003)）と include が対象を限定すること（[REQ-config-004](../../ir/config/filters.md#REQ-config-004)）だけが作られ、パターンの当て方と既存テストの大半が仕分けられていなかった。
旧資料（[旧総合仕様](../../archive/spec.md) の設定ファイルの例のコメント・センシティブファイル警告・除外フィルターの節と実装状況の「パス全体マッチ対応 exclude パターン」、利用者向けの手引き "skills/remote-merge/SKILL.md" の Filter semantics、既存要件と用語「機密ファイル」）と、status・diff・merge・sync の走査と機密ファイルの判定から見える現行実装・テストを突き合わせ、一致するものは現状を仕様として追認し、食い違い・欠落は FLAG として未決のまま残す。
既存要件 REQ-config-003、REQ-config-004 と用語「機密ファイル」は実装と一致したため変更しない。バックアップの領域を常に除外することは [REQ-backup-016](../../ir/backup/storage.md#REQ-backup-016) で扱う。SSH とエージェントの走査が同じ規則で絞り込むこと、存在しない include と root_dir の外を指す include は scan の話題、TUI のツリーの祖先ディレクトリの表示は凍結中の TUI で扱う。
要件は既存の 2 件と合わせて 8 件で limits.requirements を超えないため、既存の文書に足す。
テストの内訳（対象 52 件）: 要件の根拠 38 件、FLAG の挙動のテスト 3 件、実装詳細をなぞるだけ 1 件、残す 10 件。

## Agreements

- A1 旧資料と現行実装が一致するため、レビューなしで仕様とする。利用者向けの手引きは "/" を含まない exclude のパターンをファイル名・ディレクトリ名に当てるとし、実装は "/" を含まない exclude のパターンが root_dir からの相対パスのいずれかの要素（ファイル名かディレクトリ名）に glob で当たるとき、そのパスを除外し、ディレクトリ名に当たればその下のパスも全て除外する。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A2 旧資料と現行実装が一致するため、レビューなしで仕様とする。利用者向けの手引きと旧総合仕様は "/" を含む exclude のパターン（"config/*.toml"、"vendor/legacy/**" など）をパス全体に当てるとし、実装は "/" を含む exclude のパターンが root_dir からの相対パス全体に glob で当たるとき、そのパスを除外する。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A3 旧資料と現行実装が一致するため、レビューなしで仕様とする。利用者向けの手引きは include を glob ではなくディレクトリの前方一致とし、実装は include に書いた root_dir からの相対パスそのものと、その下のパス（"/" の区切りの単位で続くもの）だけを対象にし、"src" に対して "srcx" のように区切りの途中で続くパスは対象にしない。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A4 旧資料と現行実装が一致するため、レビューなしで仕様とする。利用者向けの手引きは include に glob を使えないとし、実装は include の値の先頭の "./" と末尾の "/" を取り除き、空の値を無視し、絶対パスの値は "Absolute path is not allowed in include filter: 値"、".." を含む値は "Path traversal is not allowed in include filter: 値"、"*"・"?"・"[" を含む値は "Glob patterns are not supported in include filter: 値" の警告を出して無視する。先頭の "./" と末尾の "/"、空の値、絶対パス、".." の扱いは旧資料に記述がなく、実装とテストから追認する。
  - why: 旧資料と実装の一致を確認し、旧資料にない部分は利用者に見える挙動をテストが確かめており、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A5 旧資料と現行実装が一致するため、レビューなしで仕様とする。利用者向けの手引きは include と exclude を併せたとき両方を満たすものだけを対象にするとし、実装は include の対象のうち exclude に当たらないパスだけを対象にする。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A6 旧資料と現行実装が一致するため、レビューなしで仕様とする。旧総合仕様は既定の sensitive のパターンを ".env"・".env.*"・"*.pem"・"*.key"・"credentials.*"・"*secret*" とし、設定で追加できるとする。実装はこの六つを常に sensitive のパターンとし、設定の sensitive に書いたパターンをそれに足す。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A7 未決の FLAG として残す。[旧総合仕様](../../archive/spec.md) の設定ファイルの例は include を指定したとき一致するパスだけを走査するとするが、実装は include の値が全て無効（絶対パス、".." を含む、glob 文字を含む）なとき警告を出して include を空として扱うため、全てのパスが走査の対象になる。これは実装を読んで分かったことで、実行しての確認はしていない。
  - why: 旧資料と実装が食い違い、どちらに合わせるかは次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A8 未決の FLAG として残す。[旧総合仕様](../../archive/spec.md) のセンシティブファイル警告の節は既定の sensitive のパターンを設定で追加・上書きできるとするが、実装は設定のパターンを既定のパターンに足すだけで、既定のパターンを外す方法がない。
  - why: 旧資料と実装が食い違い、どちらに合わせるかは次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A9 未決の FLAG として残す。実装は "../" を含む exclude のパターンを無視し、パスを一つ調べるたびに "Skipping suspicious exclude pattern containing '../': パターン" の警告を出す。旧資料に記述がなく、警告を確かめるテストもない。
  - why: 利用者に見える挙動に仕様とテストが欠けており、次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
