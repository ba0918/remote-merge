# 走査の一覧に載るものを kotowari に取り込む際の判断

## Context

status・diff・merge・sync がツリーを走査したとき一覧に何が載るかを取り込む。走査にはローカル・SSH（find）・エージェントの三つの経路があり、同じ設定で同じ一覧を返すかが仕分けられていなかった。
旧資料（[旧総合仕様](../../archive/spec.md) のシンボリックリンクの扱いの節、[旧個別仕様 symlink-merge](../../archive/spec/symlink-merge.md) の 3.6・3.7、既存要件 [REQ-scan-002](../../ir/scan/directory-links.md#REQ-scan-002)）と三経路の実装・テストを突き合わせ、読んで確信の持てない点は試験 SSH サーバに対する実行とエージェントの走査関数の直接の呼び出しで確かめた。一致するものは現状を仕様として追認し、食い違い・欠落は FLAG として未決のまま残す。
旧資料の「途中のディレクトリ symlink は辿らない」のうち、status は [A7 (旧仕様の移行)](./2026-09-25-spec-migration.md#A7) と REQ-scan-002 で、diff は [REQ-cli-021](../../ir/cli/symlink-diff.md#REQ-cli-021) で既に決まっているため FLAG にせず、merge・sync の部分だけを A4 の FLAG にする。
件数の上限・循環・読めないディレクトリなど一覧が不完全になる場合と find のタイムアウトは scan の次の回、TUI の走査は凍結中の TUI で扱う。パスを指定したときの部分走査は次の回に置く予定だったが、絞り込みの当て方の食い違い（A9）だけは利用者の了承を得て今回に含めた。
既存要件 REQ-scan-002 は実装と食い違う経路があるため変更せず A3 の FLAG を付ける。要件は新しく 2 件で、既存の文書とは扱うものが違うため新しい文書に置く。
テストの内訳（対象 129 件）: 要件の根拠 16 件（うち config のフィルターの要件の根拠 12 件）、FLAG の挙動のテスト 10 件、実装詳細をなぞるだけ 6 件、残す 97 件。

## Agreements

- A1 旧資料と現行実装が一致するため、レビューなしで仕様とする。旧総合仕様は symlink についてリンク自体の情報を表示するとし、実装はローカル・SSH・エージェントのどの経路でも symlink 自体を一覧の一つの項目としてリンク先の文字列とともに載せ、リンク先がない symlink も載せる。リンク先がない symlink を載せることは旧資料に記述がなく、実装とテストから追認する。ローカルと SSH は status の実行で、エージェントは走査関数の呼び出しで確かめた。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A2 旧資料と現行実装が一致するため、レビューなしで仕様とする。旧個別仕様 symlink-merge の 3.6 は root_dir 自体がディレクトリへの symlink のとき status・diff・merge・sync のツリーの取得がリンク先の配下を列挙し、設定の root_dir の末尾の "/" の有無で結果が変わらないとし、実装はローカルと SSH の走査で root_dir の symlink を辿って配下を列挙する（status の実行で確かめた）。エージェントの走査は root_dir を実パスに直してから走査する（実装を読んで分かったことで未実行）。
  - why: 旧資料と実装の一致を確認し、利用者が一覧から外さなかった。
  - decided_by: 利用者（現状追認の一覧を承認）
- A3 未決の FLAG として残す。既存要件 [REQ-scan-002](../../ir/scan/directory-links.md#REQ-scan-002) は CLI status がディレクトリを指す symlink の配下も再帰列挙するとし、ローカルと SSH の走査はそのとおり配下を列挙するが、エージェントの走査はディレクトリを指す symlink を辿らず、リンク自体だけを一覧に載せる。エージェントの走査関数の呼び出しで確かめたが、エージェントを有効にした status の実行はしていない。
  - why: 既存要件と実装が経路によって食い違い、どちらに合わせるかは次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A4 未決の FLAG として残す。[旧総合仕様](../../archive/spec.md) のシンボリックリンクの扱いの節はリンク先を辿らないとし、[旧個別仕様 symlink-merge](../../archive/spec/symlink-merge.md) の 3.7 は途中のディレクトリ symlink の配下をツリーの取得で列挙しないとするが、merge と sync のツリーの取得は status と同じ走査を使うため、ローカルと SSH の経路では途中のディレクトリ symlink を辿って配下を列挙する。これは実装を読んで分かったことで、merge と sync での実行はしていない。
  - why: 旧資料と実装が食い違い、merge と sync について辿ることを決めた記録がないため、次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A5 未決の FLAG として残す。"/" を含む exclude のパターンがディレクトリに当たったとき、ローカルとエージェントの走査はその配下も一覧から除くが、SSH の走査は配下を一覧に残す（"a/b" と "a/*" で status の実行により確かめた）。名前のパターンについては [REQ-config-021](../../ir/config/filters.md#REQ-config-021) がディレクトリに当たれば配下も除くとするが、[REQ-config-022](../../ir/config/filters.md#REQ-config-022) はパス全体に当たるときそのパスを除くとだけ述べ、配下を除くかが読み分けられない。
  - why: 要件の読みが割れ、経路によって実装も違うため、次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A6 未決の FLAG として残す。[REQ-config-023](../../ir/config/filters.md#REQ-config-023) は include に書いた相対パスそのものを対象にするとするが、include にファイルのパスを書くと、ローカル・SSH・エージェントのどの経路の走査もそのファイルを一覧に載せない（ローカルと SSH は status の実行で、エージェントは走査関数の呼び出しで確かめた）。
  - why: 既存要件と実装が食い違い、どちらに合わせるかは次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A7 未決の FLAG として残す。存在しないパスを include に書いたとき、ローカルとエージェントの走査は "Include path does not exist, skipping: 値" で始まる警告を出してそのパスを飛ばし、残りの include を走査するが、SSH の走査は "SSH command execution failed:" に実行した find のコマンドが続くエラーで走査全体が失敗し、status は終了コード 2 を返す（status の実行で確かめた）。旧資料に記述がなく、ローカルとエージェントの飛ばし方には単体テストがあるが、SSH の失敗を確かめるテストはない。
  - why: 利用者に見える挙動が経路によって違い、仕様が欠けているため、次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A8 未決の FLAG として残す。include にディレクトリを指す symlink を書いたとき、ローカルとエージェントの走査はリンク先の実パスを走査し、リンク先が root_dir の中なら実パスの名前で配下を一覧に載せ、root_dir の外なら警告を出して飛ばす（ローカルの警告は "Include path escapes root directory: 値 -> 実パス"）。SSH の走査はリンクの名前の下に配下を載せ、リンク先が root_dir の外でも辿る（status の実行で確かめた）。旧資料に記述がない。
  - why: 利用者に見える挙動が経路によって違い、SSH の経路だけ root_dir の外を走査するため、次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A9 未決の FLAG として残す。[REQ-config-003](../../ir/config/filters.md#REQ-config-003) と [REQ-config-004](../../ir/config/filters.md#REQ-config-004) は exclude と include が merge と sync の走査の対象にも効くとし、[REQ-config-022](../../ir/config/filters.md#REQ-config-022) は "/" を含む exclude のパターンを root_dir からの相対パスに当てるとするが、ディレクトリのパスを指定した merge と sync はそのディレクトリだけを走査し、include を当てず、"/" を含む exclude のパターンを指定したディレクトリからの相対パスに当てる。そのため include の外のファイルや "a/x.txt" のようなパスのパターンで除外したファイルも書き込みの対象になる（merge と sync の --dry-run で確かめた）。同じ指定の diff はそれらを除く。
  - why: 既存要件と実装が食い違い、どちらに合わせるかは次にこの機能を扱うときに決める。
  - decided_by: 利用者（現状追認の一覧を承認）
- A10 A2 のうちエージェントの経路の記述を正す。status のようにパスを指定しない走査では、エージェントは root_dir を実パスに直さず、root_dir をそのまま起点にしてディレクトリを読むため、読む時点で root_dir の symlink を辿る。これは実装を読んで分かったことで未実行。REQ-scan-007 の文は変えない。
  - why: テスト整理の計画のレビューで、root_dir を実パスに直す処理は走査の起点のパスが空でないときだけ動くと指摘され、コードで確かめた。承認済みの A2 は書き換えず、この決定で正す。
  - decided_by: 利用者（推奨を採用）
- A11 未決の FLAG として残す。[旧個別仕様 symlink-merge](../../archive/spec/symlink-merge.md) の 3.6 はエージェントの経路のツリーの取得が include の指定の有無にかかわらず root_dir の symlink を辿って配下を列挙するとし、[REQ-scan-007](../../ir/scan/listing.md#REQ-scan-007) は root_dir 自体がディレクトリへの symlink のとき配下を列挙するとするが、root_dir がディレクトリへの symlink で include を書いたとき、エージェントの経路の走査は一覧に何も載せない（status の実行で確かめた。ローカルの経路は載せる）。走査の起点を symlink のパスのまま使い、include の起点は実パスに直すため、各項目を root_dir からの相対パスに直せずに捨てていると実装からは読める。

  - decided_by: 利用者（推奨を採用）

  - why: 利用者に見える挙動に仕様とテストが欠けており、次にこの機能を扱うときに決める。
