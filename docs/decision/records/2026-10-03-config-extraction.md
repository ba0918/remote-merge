# 設定の読み込みとパースの内部crateへの抽出

## Context

接続設定の五つの型は既に標準ライブラリだけに依存するsettingsに所属している。
既存config全体を89単体テストと共に独立させ、製品の公開パスと振る舞いを維持する。
小さい機械的移動として扱い、正式な計画や新しいIRは作らない。

Position: 利用者の自律的な移行の委任を受け、呼び出し側が以下の設計と閉じた範囲を確定した。実装者の照合後、独立した担当がレビューと記録を行う。

## Agreements

- A1 振る舞いを維持する移行の設計・継続的レビュー・ローカル統合と後片付けは確認なしに進める委任を受けた。今回の実装者は確定したconfig抽出だけを行い、独立した品質・変更照合の検査と統合は呼び出し側が行う。
  - why: 意味を変えない移行を継続できるようにし、実装と独立レビューの責任を分ける。
  - decided_by: user
- A2 新しいIR・要件・テスト、外部依存更新、既存製品版0.2.13・通信版v4の変更は行わない。読み込み・認証・既定値・値・検証・エラーと既存契約を保つ。
  - why: 所属変更を製品の振る舞いや検査方針の変更と混ぜない。
  - decided_by: user

## Delegated

- D1 新しいremote-merge-configを内部版0.1.0・edition 2021・publish=falseの通常member/default-memberとし、既存config全体を採用する。settingsはstd-onlyのまま同じ五型を再公開する。coreのerror/filterはprivateなroot別名で既存参照を保つ。バックアップ名の定数と元の説明を下位configへ移し、製品backupは同じ定数を再公開してconfigからbackupへの循環を避ける。expand_tildeだけは新ownerでpubにし、製品facetではpub(crate)の明示的再公開に保つ。
  - why: 既存ソースと型をコードベース探索の段階で再利用し、Rust再公開とCargo path依存で既存参照を保てる。新しいshim・型・ロジックは不要で、下位の設定crateは製品やSSH・backupに依存しない。
  - decided_by: caller（A1の設計委任に基づく確定設計）
- D2 製品configの全既存公開項目を明示的に再公開し、helperとバックアップ定数を新たに製品configから公開しない。移す89テストだけのowner/binaryとconfig接頭辞を対応付け、他の3020件はそのまま保つ。三つのwarnにはremote_merge::configの旧targetを明記する。指定した別名・定数・単一参照・helper可視性・三つのtarget追加だけを逆変換して元の本文とGit modeを比較する。
  - why: 公開範囲の拡大や検査漏れを防ぎ、既存ログフィルターとテスト本文を保つ。ファイル名・行番号・module_pathは配置変更に伴い変わり得るがtargetの変更として扱わない。
  - decided_by: caller（A1・A2の具体化と検証方法）
- D3 ブランチ全体の比較元を9870c96ea2102414e5da06ce72b1d6750388aa88に固定し、旧両記録を除いて実装者と独立担当が現在の比較を記録する。既存の順序付き検査・本文比較・公開APIのローカル確認と配布前後比較を行う。必須の変異検査は設けない。
  - why: 前回の移動を今回の根拠とせず、挙動を維持する移動を既存検査と限定した比較で確かめる。未実行のログ経路や環境を検証済みと扱わない。
  - decided_by: caller（PROJECT.mdの照合とA2に従う）
- D4 残るSSH・Agent・engineなど将来の移動は今回行わず、利用側・設定型・core・他のテスト・スクリプト・フックとCIは変更しない。
  - why: 設定全体の所属変更を超える境界や責務の判断を混ぜない。
  - decided_by: caller（閉じた実装範囲）
