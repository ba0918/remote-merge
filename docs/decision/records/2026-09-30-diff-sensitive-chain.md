# CLI diff の機密の連鎖を実パスで辿る判定への作り直しの判断

## Context

CLI diff は symlink の連鎖の途中の段が機密パターンに当たると内容を隠す（[REQ-cli-023](../../ir/cli/symlink-diff.md#REQ-cli-023)）が、今の判定はリンク文字列を字面で親パスと結んで次の段を求めるため、OS の解決と食い違う書き方で迂回が残る（[FLAG-cli-056](../../ir/cli/FLAGS.md#FLAG-cli-056)）。
字面で辿れないときに隠す側へ倒した結果、機密でない連鎖の内容差も隠れている（[FLAG-cli-057](../../ir/cli/FLAGS.md#FLAG-cli-057)）。root_dir の外へ出た先の段を調べない点（[FLAG-cli-051](../../ir/cli/FLAGS.md#FLAG-cli-051)）も同じ判定にある。
[root_dir の symlink の修正の記録](./2026-09-30-diff-root-symlink.md#A5)で、継ぎ足しでは収束しないため各段を OS が解決した実パスで辿る判定への作り直しとして区切ったので、その作り直しの中身を決める。
CLI の FLAGS.md は limits.lines を超えたままになるが、[差分の出し方の記録](./2026-09-29-adopt-diff-output.md)と同じく、中身は CLI の一つの責務（コマンドの振る舞いの未決事項）に揃っているため分けない。

Position: 第 3 ラウンドまで決定（A1・A3・A4 は A6・A7 で置き換え）。IR と FLAG の反映、check と照合の後に承認。

## Agreements

- A1 機密の判定で連鎖の段として見る symlink は、diff が項目のパスを開くときに OS が通る symlink の全てとする。最後の名前が次々リンクになる連鎖の各段に加えて、リンク文字列の途中の要素にあるディレクトリ symlink と、指定したパスや走査で出た子パスの途中の要素にあるディレクトリ symlink も段に含める。
  - why: OS の解決と別の辿り方をすると、その差が迂回になる（[FLAG-cli-056](../../ir/cli/FLAGS.md#FLAG-cli-056)）。途中の要素のディレクトリ symlink を除くと、"linkdir/a.txt" を直接指定したときや走査で子として出たときに linkdir のリンク文字列を見ない経路が残る。判定は symlink の項目だけでなく、途中の要素に symlink を含むパスの項目全てで走る。
  - rejected: 最後の名前の連鎖とリンク文字列の途中の要素だけを段とし、指定したパスの途中の要素は別の FLAG に残す案。最後の名前の連鎖だけを段とする今の読みのままにする案。どちらも迂回が残る。
  - decided_by: 利用者（推奨を採用）
  - superseded_by: [A6](#A6)
- A2 各段では、その段のリンク文字列と、その段を OS が解決した実パスの両方を機密パターンに当てる。実パスは root_dir からの相対に直さず、OS が解決した絶対パスのまま当てる。当て方（名前か、パス全体か）は今の機密パターンの判定と同じ。
  - why: 今の判定と同じ対象を保つ。root_dir の外を通る段は root_dir からの相対に直せないため、実パスは全ての段で絶対パスに揃える。既定のパターンは "/" を含まず名前だけで決まるため、既定の設定では結果が変わらない。
  - rejected: 実パスを root_dir からの相対に直せる段だけ相対で当てる案。段によって当て方が変わる。リンク文字列だけに当てる案。今の判定より見る対象が減る。
  - decided_by: 利用者（推奨を採用）
- A3 連鎖が root_dir の外を通るときも、--follow-external-links の有無によらず、機密の判定のためだけに外の段のリンク文字列と実パスを読んで辿る。外の段の内容は読まない。
  - why: 外の段を見ないと、root_dir の外で機密の名前を通ってから root_dir の中へ戻る連鎖の内容を、--follow-external-links なしで表示しうる（[FLAG-cli-051](../../ir/cli/FLAGS.md#FLAG-cli-051)）。読むのはリンクの情報だけで、root_dir の外の内容を辿らない [REQ-cli-026](../../ir/cli/symlink-diff.md#REQ-cli-026) とぶつからない。
  - rejected: root_dir の外へ出る連鎖は確かめられないとして隠す案。外へ出て機密でない連鎖の内容まで隠れる。外の段を見ないままにする案。FLAG-cli-051 が残る。
  - decided_by: 利用者（推奨を採用）
  - superseded_by: [A6](#A6)
- A4 段の解決に失敗したとき（途中の要素を読む権限がない、読み取りのエラー、段数の上限）は、確かめられない段があるとして、機密と同じく --force なしでは内容を表示しない。段数の上限は Linux がリンクを辿る上限（40 段）以上にし、OS より先に辿るのを止めない。最終参照先が存在しないことは失敗ではなく連鎖の終わりとし、今どおり読めない参照先として扱う。
  - why: OS と同じ辿り方なら、辿れないときは内容も読めないことがほとんどで、隠しすぎはまれ。辿れない段を機密でないとみなすと迂回が残る。
  - rejected: 解決できない段を機密でないとみなす案。迂回が残る。その項目をエラーにして終了コード 2 にする案。内容を読める場合まで比較が失敗扱いになる。
  - decided_by: 利用者（推奨を採用）
  - superseded_by: [A7](#A7)
- A5 今回の作り直しの対象は CLI diff の機密の連鎖の判定（[REQ-cli-023](../../ir/cli/symlink-diff.md#REQ-cli-023)）に限り、status・merge・sync・TUI の機密の扱いは変えない。
  - why: FLAG-cli-051・056・057 はどれも diff の判定の話で、他のコマンドに同じ迂回があるかはそのコマンドを取り込むときに扱う。
  - decided_by: 利用者（推奨を採用）
- A6 diff の機密の連鎖の判定は、リンク文字列を字面で結んで辿れる段の範囲で行い、OS の解決と字面がずれる書き方や root_dir の外を通る連鎖による迂回は塞がない。そうした書き方で機密の内容が表示されることは、利用者が置いたリンクの結果として受け入れる。普通の書き方の機密の連鎖（例 "link.txt" が ".env" を指す）は今どおり --force なしでは内容を表示しない。
  - why: 利用者の方針は、diff・merge が途中で止まらず完遂できることを最優先とし、機密のデータの置き方は利用者の責任とする。迂回を必ず塞ぐには、diff が項目ごとに使うパスの検査をローカル・SSH・エージェントの三つの経路で作り直す必要があり、機密と関係のない比較まで失敗しうる危険を負う。
  - rejected: 各段を OS が解決した実パスで辿って迂回を塞ぐ案（A1・A3）。三つの経路の検査とエージェントのプロトコルの作り直しが要り、完遂の方針に対して危険が大きい。
  - decided_by: 利用者（推奨を採用）
- A7 機密かどうかを確かめられない段があるとき（字面で辿れない、途中の段を読めない）は、機密でないとみなして内容差を表示し、比較をエラーにも隠す扱いにもしない。
  - why: 確かめられないことを理由に隠すと比較の結果が欠け（[FLAG-cli-057](../../ir/cli/FLAGS.md#FLAG-cli-057)）、完遂を最優先とする利用者の方針に合わない。
  - rejected: 確かめられない段があれば隠す案（A4）。機密でない連鎖の内容差まで隠れる。
  - decided_by: 利用者（推奨を採用）
- A8 [root_dir の symlink の修正の記録の A4](./2026-09-30-diff-root-symlink.md#A4)（字面で辿れない連鎖は root_dir の中なら隠す）を撤回し、A7 で置き換える。FLAG-cli-057 は解消したものとして外す。
  - why: A7 と正反対の決定で、両方を残すと判定が決まらない。
  - decided_by: 利用者（推奨を採用）
- A9 [REQ-cli-023](../../ir/cli/symlink-diff.md#REQ-cli-023) の文に判定の範囲を書き足し、入れ子の段はリンク文字列を字面で結んで root_dir の中に辿れる範囲で見るとする。入口の名前と最終参照先のパスは今どおり root_dir の内外を問わず見る。FLAG-cli-051 と FLAG-cli-056 は要件との食い違いがなくなるため外す。
  - why: 受け入れた限界を要件に書かずに FLAG だけを外すと、要件と実装の食い違いが見えないまま残る。
  - decided_by: 利用者（推奨を採用）
- A10 字面で辿る規則は今の実装のままとする。相対のリンク文字列はリンクの親と結んで "." と ".." を畳み、root_dir より上に出たら辿るのを止める。絶対パスのリンク文字列は、実パスに直した root_dir か設定に書いた root_dir の下にあれば続け、それ以外なら止める。
  - why: [root_dir の symlink の修正](./2026-09-30-diff-root-symlink.md#A1)とそのレビューで固めた規則で、変えると別の書き方で結果が変わる。
  - decided_by: 利用者（推奨を採用）
- A11 指定したパスや走査で出た子パスの途中の要素にあるディレクトリ symlink（例 "linkdir/a.txt" の linkdir）は、その子の機密の判定の段に含めない。
  - why: ディレクトリ symlink を一つの項目として比べるときは今どおり判定され、機密なら配下を展開しない。子のパスを直接指定するのは利用者がそのファイルを選んだことで、A6 の範囲（項目から先の連鎖）の外として受け入れる。
  - decided_by: 利用者（推奨を採用）
- A12 撤回した決定を確かめるテスト（字面で辿れず root_dir の中にとどまる、機密の名前を含む連鎖の内容を隠すことを確かめる 6 本）は消し、同じ形で機密の名前を含まない連鎖（"../<root_dir の実ディレクトリ名>/target.txt" と root_dir の別名を通る絶対パス）で参照先の内容差を表示することを、[REQ-cli-020](../../ir/cli/symlink-diff.md#REQ-cli-020) の例とテストとしてローカルと SSH の両方に足す。機密の名前を含む連鎖が字面で辿れないときに内容を表示することはテストで固定しない。
  - why: 6 本は撤回した決定そのものを確かめており、残すと必ず失敗する。機密の内容が表示されることを固定すると、判定を強めるときの足かせになる。
  - decided_by: 利用者（推奨を採用）

## Revisions

- A1 と A3（各段を OS が解決した実パスで辿り、root_dir の外の段も辿る）を A6（字面で辿れる範囲で判定し迂回は塞がない）で置き換えた。第 2 ラウンドの前に利用者が、diff・merge を完遂できることを最優先とし、機密の置き方は利用者の責任とする方針を示したため。
- A4（確かめられない段があれば隠す）を A7（機密でないとみなして内容差を表示する）で置き換えた。理由は同じ。
- [root_dir の symlink の修正の記録の A4](./2026-09-30-diff-root-symlink.md#A4) を A8 で撤回し、A7 で置き換えた。
