# エージェントに削除・権限の変更・子の一覧を足し、接続断と経路の選び方を筋の通るものにする

## Context

品質レビュー 1 回目の T2（指摘 ssh_agent-10・routes-4・ssh_agent-8・merge_sync-6）を直すにあたり、承認済みの [2026-10-05-quality-ssh.md の A2](./2026-10-05-quality-ssh.md#A2) は、sudo=true のサーバの削除・権限の変更・子の一覧を、エージェントに操作を足すまでの間エラーにする暫定案だった。
調べると、この暫定案では sudo のサーバで --delete・symlink の置き換え・rollback・新しいファイルの権限付けが止まり、diff はディレクトリをファイルとして扱う。
利用者は 2026-10-11 に「そもそもマージツールとしておかしくない挙動をするようにしてください。整合性が取れない対応をしないでください」と指示し、暫定案をやめて本対応を今回入れることになった。
あわせて、結果の分からない書き込みを SSH で繰り返す件（ssh_agent-10）、接続断のときの経路の切り替え、互換の分岐の扱いを、既存の同期ツール（rsync・Unison）の慣例に合わせて決めた。
問いと答えは shoryo の topic "agent-ops" の Round 1〜6 にある。

Position: 決定は A1〜A40 で出揃い、IR に反映した。A20〜A30 は IR の下書きのレビュー（shoryo の Round 7）で、A31〜A34 は突き合わせ（collation）で、利用者の決定から導いて書き出した。A35〜A37 は計画の前の調べで分かったことを shoryo の Round 8 で決めた。A38・A39 は、実装で A24 の「送れなかった」を決まって見分けられないと分かり、shoryo の Round 9 で決めた。

## Agreements

- A1 削除・権限の変更・子の一覧は、エージェントがつながっていれば、sudo の有無によらずエージェントの操作（Remove・Chmod・ListDir）で行う。エージェントを使えないときだけ SSH の経路で行う。A2 の暫定のエラー化はやめ、[REQ-ssh-010](../../ir/ssh/fallback.md#REQ-ssh-010) を今回作る。
  - why: sudo=true のサーバに限ると、sudo=false では書き込みはエージェント、削除・chmod・一覧は SSH という経路の混ざりが残る。読み込みや書き込みと同じ「エージェントがあればエージェント」の規則にそろえる。
  - rejected: sudo=true のサーバだけエージェントで行う
  - decided_by: 利用者（2026-10-11、shoryo q1）
- A2 エージェントとの通信の版が手元と同じでなければ、そのエージェントは使わない。sudo=true なら何も読み書きする前に接続のエラーで止め、sudo=false ならエージェントを使えないときと同じく SSH の経路で行う。古い版のための分岐（パスの確認の版の確認、ハッシュの版の確認、古い版の応答を埋める既定値、相手のほうが新しい版の受け入れ）はすべて消す。
  - why: 利用者は「互換性の分岐はこれに限らずすべて捨ててください」と答えた。接続のときに版の文字列（通信の版を含む）が違えば自動で置き直し、版が同じでもハッシュが違えば置き直す（[REQ-ssh-016](../../ir/ssh/deploy.md#REQ-ssh-016)）。置き直しに失敗したときはエージェントを起動しないので、版の確認まで届くのは、置き直しの後も接続のときに違う通信の版を答えた場合（ハッシュを照合できないまま実行した場合を含む）に限られる。
  - rejected: 版の違いは受け入れ、足した操作だけ版で分ける
  - decided_by: 利用者（2026-10-11、shoryo q2 のメモと q5）
- A3 このツールの古い版との互換の分岐はすべて捨てる。この単位ではエージェントの版の互換（A2）を捨てる。設定の使われなくなったキー（[REQ-config-030](../../ir/config/filters.md#REQ-config-030)・[REQ-config-031](../../ir/config/filters.md#REQ-config-031)。捨てると知らないキーになるので、未実装の [REQ-config-039](../../ir/config/loading.md#REQ-config-039) の実装を含む）、バックアップのセッションの古い探し方（[REQ-backup-043](../../ir/backup/sessions.md#REQ-backup-043)）と古い置き場の除外（[REQ-backup-016](../../ir/backup/storage.md#REQ-backup-016)）、--ref の別名 --reference、コードの中の互換の名残は、このすぐ後の別の単位で捨てる。
  - why: 利用者だけが使うツールなので互換を持つ理由がない。エージェント以外の分は設定の読み込み・バックアップ・CLI という別の場所の変更で互いの影響もなく、一つのブランチに混ぜるとレビューと確認の範囲が広がる。
  - rejected: 互換を捨てる作業を全部この単位でやる
  - decided_by: 利用者（2026-10-11、shoryo q2 のメモと q6）
- A4 つなぐ先のサーバの道具の違いを吸収する分岐（ln -s -T がないときの書き方、dd の oflag=nofollow や status=none がないとき、コマンド長の上限、古い SSH のアルゴリズムの設定、sha256sum がないときの shasum、fish のログインシェル）は、互換の分岐に数えず残す。
  - why: 利用者は「古いサーバで使うので必要」と答えた。これらはこのツールの古い版との互換ではない。
  - rejected: 古いサーバの分岐も捨てる
  - decided_by: 利用者（2026-10-11、shoryo q7）
- A5 書き込み・symlink の作成・削除・権限の変更の最中に接続断が起きたら、どの経路でもその回の処理を止める。そのファイルは結果が分からない失敗として failed に出し、同じ変更を繰り返さない。手を付けなかった残りのファイルは書かずに、手を付けていないことが分かる失敗として failed に出す。終了コードは 2。別の経路に切り替えて続けない。接続断でない 1 ファイルの失敗は、今までどおり failed に出して残りを続ける。
  - why: 利用者は「既存の同期ツールに従う」「これも慣例に従ったほうが良さそう」と答えた。rsync と Unison は接続が切れるとその回をエラーで終え、別の経路に切り替えず、1 ファイルの失敗は報告して続ける（Claude の知識による。動かして確かめてはいない）。手を付けなかったファイルを failed に並べるのは、このツールが JSON で 1 ファイルずつ結果を出すためで、rsync にはない。
  - rejected: 切れたファイルだけ失敗にして残りは続ける
  - decided_by: 利用者（2026-10-11、shoryo q3 のメモと q8）
  - superseded_by: [A38](#A38)
- A6 書き込みは今までどおり書き込み先をその場で書き換える（[REQ-merge-039](../../ir/merge/concurrency.md#REQ-merge-039)、[2026-10-05-ssh-strict-exec.md の A11](./2026-10-05-ssh-strict-exec.md#A11)）。途中で切れたファイルは途中までの中身が残り、書く前に取ったバックアップから rollback で戻す。
  - why: 一時ファイルに書いて名前を変える方式は A11 で、差し替えの危険と所有者・ハードリンクが変わることを理由にやめている。rsync も root でないと所有者を保てず、同じ書き方をする --inplace という指定がある。
  - rejected: 一時ファイルに書いて名前を変える
  - decided_by: 利用者（2026-10-11、shoryo q9）
- A7 削除・権限の変更・子の一覧は、ローカル・SSH・エージェントの三経路で同じ結果にする。基準は今のローカルの振る舞いで、ローカルと SSH で違う点は A11〜A15 で個別に決めた。途中の symlink は、ローカルと SSH と同じく root_dir の外を指していても辿る。
  - why: A1 で同じサーバでもエージェントか SSH のどちらかで動くことになったため。今のエージェントの書き込みが root_dir の外を指す途中の symlink を拒む件（FLAG-merge-012）は、新しい三つの操作には持ち込まない。
  - rejected: 今の SSH の振る舞いに合わせる
  - decided_by: 利用者（2026-10-11、shoryo q10）
- A8 接続断とは、要求を送り始めた後に応答を受け取れなかったことをいう。エージェントでは要求を送った後の切断・EOF・読み込みの時間切れ（分けて送る大きな書き込みの途中を含む）、SSH ではコマンドの終わりの状態を受け取れなかったこと。相手が失敗の応答を返したことや、コマンドが 0 以外で終わったことは接続断ではない。
  - why: A5 の「その回を止める」と「1 ファイルの失敗は続ける」を分ける境目が要る。書けたか分からないものだけを止める側に入れる。
  - rejected: 経路の失敗はすべて止める
  - decided_by: 利用者（2026-10-11、shoryo q11）
- A9 A5 は merge・sync（--delete を含む）・rollback のすべてに当てる。
  - why: リモートに変更を加えるのはこの三つで、コマンドによって接続断の扱いを変えない。
  - rejected: merge と sync だけに当てる
  - decided_by: 利用者（2026-10-11、shoryo q12）
- A10 どのコマンドでも、エージェントの読み込みや走査の途中で接続断が起きたら、エージェントを起動し直して、その操作を一度だけやり直す。それでも失敗したらその回の処理を止める。回の途中で SSH の経路に切り替えない。
  - why: SSH の読み取りを一度だけやり直す [REQ-ssh-003](../../ir/ssh/reconnect.md#REQ-ssh-003) と同じ規則をエージェントにも当て、経路による差と回の途中の経路の混ざりをなくす。status と diff のように読むだけのコマンドも同じ規則にする。
  - rejected: 読み込みの接続断ですぐ止める、SSH に切り替えて続ける、読むだけのコマンドは SSH に切り替えて続ける
  - decided_by: 利用者（2026-10-11、shoryo q13・q20）
- A11 子の一覧は「ディレクトリではない」と「一覧を取れなかった」を区別して返す。「ディレクトリではない」は、通常ファイル、ディレクトリでないものへの symlink、リンク切れの symlink、ないパスの四つで、diff は今までどおり種類に合わせて扱う。読めないディレクトリ・接続断・時間切れのように、ディレクトリかもしれないのに中身が分からないものは「一覧を取れなかった」とし、diff はそのパスと理由を errors に出して終了コード 2 を返す。三経路で同じにする。
  - why: 今の diff は一覧の失敗をすべて「ディレクトリではない」と読み、本当の理由が出ない。子の一覧の経路を作り直すので、同じ場所の握りつぶしも一緒に直す。
  - rejected: 子の一覧の失敗の握りつぶしを別の単位にする、ディレクトリ以外はすべて失敗にする
  - decided_by: 利用者（2026-10-11、shoryo q4・q22）
- A12 三つの操作は、".." の要素を含むパスと絶対パスを、どの経路でも I/O の前に拒否する。文言は ".." なら "path traversal not allowed: パス"、絶対パスなら "absolute subpath not allowed: パス"。末尾の "/" は除いたパスとして扱う。
  - why: 今のローカルは字面で正規化して root_dir の中に収まれば実行し、SSH は拒否していた。承認済みの判断 D2（[REQ-merge-007](../../ir/merge/symlink.md#REQ-merge-007) の文言）に合わせ、A7 の基準の例外とする。末尾の "/" はローカルに合わせる。
  - rejected: 字面で正規化して受け付ける、末尾の "/" 付きを拒否する
  - decided_by: 利用者（2026-10-11、shoryo q21・q16。仮決めのまま送られた）
- A13 権限の変更に 0o777 を超える値（setuid・setgid・sticky を含む）が来たら、どの経路でも付けずにエラーにする。
  - why: 今は SSH だけが拒否し、ローカルはそのまま付けていた。マージで特別な権限が付くことを経路によらずなくす。
  - rejected: そのまま付ける
  - decided_by: 利用者（2026-10-11、shoryo q14）
- A14 三つの操作の失敗は、どの経路でも、操作・パス・原因が分かる英語の文言にする。文字列そのものは決めない（A12 の拒否は除く）。テストは三つが含まれることだけを確かめる。
  - why: rollback の failed のように文言が利用者に見えるが、今はローカルの chmod の失敗にパスがないなど経路でばらばら。一字一句そろえると原因の細かい情報が落ちる。
  - rejected: 一字一句同じ文言にする
  - decided_by: 利用者（2026-10-11、shoryo q15。仮決めのまま送られた）
- A15 子の一覧の各項目は、権限を特別なビットを含む権限のビット（0o7777 の範囲）、更新時刻をナノ秒まで、リンク先を読んだ文字列そのままで持つ。読めないリンクは "???" で埋めず、その一覧を A11 の「一覧を取れなかった」にする。三経路で同じにする。
  - why: 今はローカルが st_mode 全体と秒に切り捨てた時刻を持ち、読めないリンクを "???" で埋め、SSH はリンク先の前後の空白を削っていた。情報を落とさない側にそろえ、[REQ-scan-015](../../ir/scan/listing.md#REQ-scan-015) の既定値で埋めない趣旨に合わせる。
  - rejected: ローカルに合わせる
  - decided_by: 利用者（2026-10-11、shoryo q17。仮決めのまま送られた）
- A16 名前に TAB や改行を含む子を SSH の一覧が正しく読めない件は、品質の台帳に足し、SSH の走査と一覧の出力の読み方をまとめて直す別の単位で扱う。
  - why: SSH の走査全体も同じ読み方をしている可能性が高く（推測）、一覧だけ直すと読み方が二通りになる。エージェントの一覧はこの影響を受けない。
  - rejected: この単位で子の一覧の分だけ直す
  - decided_by: 利用者（2026-10-11、shoryo q18）
- A17 子の一覧の exclude の当て方がローカルと SSH で違う件（"vendor/**" を SSH は深い階層の "a/vendor" にも当て、ローカルは root_dir の直下にだけ当てる）は、品質の台帳の iv-1 と同じ単位で exclude の規則として全経路をそろえる。この単位では、エージェントの一覧はローカルと同じ当て方にする。
  - why: 走査の exclude の経路差（iv-1）と同じ規則の話で、一覧だけ先に直すと直り方がずれる。
  - rejected: この単位で子の一覧の exclude だけそろえる
  - decided_by: 利用者（2026-10-11、shoryo q19）
- A18 エージェントの通信の版を 6 に上げ、リリースで配置済みのエージェントを置き直すことは IR に書かない。
  - why: 利用者に見える振る舞いではない。見える振る舞い（版が違えば使わない）は A2 として IR に書く。
  - decided_by: Claude（kotowari の IR の範囲の規則による）
- A19 sudo=true のサーバで、エージェントを外さない種類の一時的なエラー（読み込みの時間切れなど）のときに通常権限の SSH に回る今の動きは、A8 の接続断として A5・A10 で扱い、SSH に回さない。
  - why: [REQ-ssh-009](../../ir/ssh/sudo.md#REQ-ssh-009) の「通常権限の SSH 経路に切り替えない」の穴で、A5・A10 から導ける。
  - decided_by: Claude（A5・A8・A10 から導いた）

- A20 一度やり直した読み取りがまた `接続断` になったら、SSH とエージェントのどちらの経路でも、その回の処理を止める。[REQ-ssh-003](../../ir/ssh/reconnect.md#REQ-ssh-003) の「再び失敗したら失敗を報告する」をこの意味に書き換える。
  - why: A10 は SSH と同じ規則をエージェントに当てる決定だったが、REQ-ssh-003 は一つのファイルの失敗として続けるとも読め、IR が経路の差を作っていた。接続が戻らないなら続けないという A5 と同じ考えにそろえる。
  - rejected: どちらの経路も、そのファイルの失敗として続ける
  - decided_by: 利用者（2026-10-11、shoryo q23）
- A21 A5・A10・A20 の「その回」は、一つの書き込み先（status・diff では一つのコマンド）への一回の処理をいう。書き込み先が複数ある sync で一つの書き込み先との接続断が起きたときは、その書き込み先への処理だけを止め、ほかの書き込み先は [REQ-merge-015](../../ir/merge/multi-target.md#REQ-merge-015) のとおり続ける。
  - why: 利用者は「これも既存の同期ツールの慣例に従ったほうが良いか」と尋ね、Ansible のように接続できなくなった先だけを外して残りを続ける慣例（Claude の知識による）と REQ-merge-015 に合う案を選んだ。
  - rejected: sync 全体を止める
  - decided_by: 利用者（2026-10-11、shoryo q24）
- A22 --with-permissions で読み込み元の権限に 0o777 を超えるビット（setuid・setgid・sticky）があるときは、権限を写さず、[REQ-merge-037](../../ir/merge/permissions.md#REQ-merge-037) と同じく中身は書いたことと特別なビットのために写さなかったことが分かる error で failed に出し、終了コード 2 を返す。
  - why: A13 で特別な権限を付けないと決めた。黙って 0o777 で切って写す今の動きは握りつぶしになる。
  - rejected: 特別なビットを落として写し、警告を出す
  - decided_by: 利用者（2026-10-11、shoryo q25）
- A23 子の一覧で、symlink のリンク先か更新時刻を読めないときは、走査と同じく既定の値で埋めずにエラーで止める（[REQ-scan-015](../../ir/scan/listing.md#REQ-scan-015)）。A15 の「読めないリンクはその一覧を取れなかったものにする」をこの意味に改める。読めないディレクトリは A11 のとおり errors に出して続ける。
  - why: パスを指定しない diff の走査は止まり、ディレクトリを指定した diff は続く、という差ができていた。diff は走査方式によらず同じ規則で比べる。
  - rejected: 走査も一覧も errors に出して続ける（承認済みの REQ-scan-015 を書き換えることになる）
  - decided_by: 利用者（2026-10-11、shoryo q26）
- A24 前の操作の後に接続が使えなくなっていて、変更の要求を送れなかったときは、`接続断` と同じくその回の処理を止める。送れなかったファイルと残りのファイルは、手を付けていない失敗として failed に出し、終了コード 2 を返す。別の経路には切り替えない。
  - why: A8 の定義は送り始めた後のことだけで、送る前から切れている場合が抜けていた。送っていないので結果ははっきりしているが、接続が使えないと分かった時点で止めるのが rsync の慣例と合う。
  - rejected: 一度つなぎ直して、その変更を行う
  - decided_by: 利用者（2026-10-11、shoryo q27）
  - superseded_by: [A38](#A38)
- A25 読み込みの `接続断` で merge・sync・rollback が途中で止まったときも、A5 と同じ形で結果を出す。済んだファイルはそのまま結果に出し、読み込みに失敗したファイルは理由付きで failed に、残りは手を付けていない失敗として failed に出し、終了コード 2 を返す。
  - why: 止まった理由が読み込みでも変更でも、どこまで済んだかを JSON から読めるようにする。
  - decided_by: 利用者（2026-10-11、shoryo q28。仮決めのまま送られた）
- A26 中身を書いた後の権限の変更が `接続断` になったときは、中身は書いたことと権限の変更の結果が分からないことの両方が分かる error で failed に出し、A5 のとおりその回を止める。
  - why: [REQ-merge-037](../../ir/merge/permissions.md#REQ-merge-037)（中身は書いた）と A5（結果が分からない）のどちらの error になるかが決まっていなかった。
  - decided_by: 利用者（2026-10-11、shoryo q29。仮決めのまま送られた）

- A38 書き込み・symlink の作成・削除・権限の変更の最中に `接続断` が起きたら、どの経路でも同じ変更を繰り返さず、別の経路にも切り替えず、同じ経路で一度だけつなぎ直して（エージェントは起動し直し、SSH はつなぎ直し）、そのファイルの今の状態を読んで確かめる。書き込みと symlink の作成は、書こうとしたものと同じなら「書けた」、書く前と同じ（書く前になかったなら、ない）なら「書いていない」、どちらでもなければ「書きかけ」とする。削除は、なければ「消せた」、あれば「消していない」とする。権限の変更は、読んだ権限で「変えた」か「変えていない」とする。中身を書いた後の権限の変更で切れたときは、中身は書いたことと、確かめた権限の結果の両方が分かる error にする。前の操作の後に接続が使えなくなっていて要求を送れなかったときも、同じく確かめて出し、「送れなかった」を別に見分けない。つなぎ直しか確かめる読み込みが失敗したときだけ、そのファイルを「結果が分からない」で出す。確かめた後も、その回（A21）の処理は止める。「書けた」「消せた」「変えた」ファイルは済んだファイルとして結果に出し、それ以外は確かめた結果が分かる error で failed に出す。手を付けなかった残りのファイルは変更せずに、手を付けていないことが分かる error で failed に出し、終了コード 2 を返す。何も起きないときの往復は増やさない。接続断でない 1 ファイルの失敗は、今までどおり failed に出して残りを続ける。error の文言は A34 と同じく IR で決めず、テストは確かめた結果の区別が読めることだけを確かめる。
  - why: 利用者は 2026-10-11 に「結果不明はマージツールとしてまずい。とはいえ速度は犠牲に出来ない」と答えた。実装で測ると、エージェントが終わった後でも、クライアントは閉じた知らせを受け取る前に次の要求を送ってしまい、A24 の「送れなかった」と A8 の「送ったが応答がない」はタイミングで入れ替わった。切れた後に一度だけ読んで確かめれば、どちらも同じ「書いていない」になり、何も起きないときの速さも変わらない。読み込みは両方の経路にあるので、通信の版は変えない。止めること・繰り返さないこと・経路を切り替えないことは A5 のまま（rsync・Unison の慣例）。
  - rejected: 変更の前に毎回エージェントに生存を確かめる（Ping）、今のまま「結果が分からない」で出す
  - decided_by: 利用者（2026-10-11、shoryo q35）
- A39 A38 で確かめた結果が「書きかけ」（書く前とも書こうとしたものとも違う。別の誰かが変えた場合を含む）のときは、書き方はその場で書き換えるまま（A6）にして、そのことと、バックアップを取っていればその場所を failed の error に出す。自動では書き戻さない。
  - why: その場で書き換える書き方では、途中で切れたファイルに途中までの中身が残る。書き戻すのも変更なので、切れた直後に重ねない。バックアップは設定で有効なときだけ取る（backup.enabled）。
  - rejected: 一時ファイルに書いて名前を変える方式に変える（所有者・ハードリンクが変わることと差し替えの危険という、A6 でやめた理由が戻る）
  - decided_by: 利用者（2026-10-11、shoryo q36）

- A40 バックアップが無効な rollback では、書き戻す前に、書き戻す先にある通常ファイルのハッシュを一回の要求でまとめて取り、A38 の確かめの「書く前」に使う。ハッシュは保存しない（[REQ-backup-028](../../ir/backup/rollback-path.md#REQ-backup-028) のまま、内容は退避しない）。これは A38 の「何も起きないときの往復は増やさない」の例外で、増える往復は rollback 一回につき一回だけにする。
  - why: バックアップが無効な rollback だけは書く前の中身を製品が持たず、接続断のときに「書いていない」と「書きかけ」を見分けられないと実装で分かった。利用者は、結果不明を許す案とファイルごとに読む案ではなく、まとめて一回ハッシュを取る案を選んだ。
  - rejected: この構成だけ「結果が分からない」を許す、書き戻すファイルごとに中身を読む
  - decided_by: 利用者（2026-10-11、会話での質問への答え）
