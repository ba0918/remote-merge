# 品質レビュー 1 回目の判断のうちツリーの走査に関わるもの

## Context

2026-10-05 の品質レビュー 1 回目（main c90cc54）で、ツリーの走査の結果がローカル・SSH・エージェントの経路によって違い、欠けた一覧を完全な一覧として返す場合があることが分かった。
欠けた一覧は「片側だけにある」と判定され、--delete で削除の対象になりうる。
利用者は 2026-10-05 に判断 D1〜D32 をすべて推奨どおり採用した（「推奨ではじめて」）。
この記録はそのうち走査の数え方・symlink・名前・時間切れ・読めないディレクトリの判断を扱う。include と exclude の値の扱いは [2026-10-05-quality-config.md](./2026-10-05-quality-config.md) に置く。

## Agreements

- A1 走査の件数の上限は、どの経路でもファイルと symlink だけを数え、ディレクトリを数えない（D4）。
  - why: [REQ-scan-003](../../ir/scan/limits.md#REQ-scan-003) は「ファイル件数」の上限とし、エージェントはそのとおり数えるが、ローカルと SSH はディレクトリも数えるため、同じツリーで経路により打ち切られていた（指摘 status_scan-3）。ディレクトリだけが大量にあるツリーでは上限が効かず走査が長くなる。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D4 を推奨どおり採用）
- A2 エージェントの経路の走査も、ディレクトリを指す symlink を辿って配下を列挙する。循環はデバイス番号と inode 番号で検出し、不完全な一覧として報告する（D5）。
  - why: [REQ-scan-002](../../ir/scan/directory-links.md#REQ-scan-002) のとおりにする。エージェントの経路だけ配下を列挙せず、left_only と right_only が出ていた（指摘 status_scan-4）。エージェントの走査が増え、root_dir の外を指すリンクの配下も読む。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D5 を推奨どおり採用）
- A3 UTF-8 として読めない名前のファイルは、読めない名前として報告し、置換文字に置き換えた名前を一覧に載せない（D9）。
  - why: 置き換えた名前では読めず、別の名前と衝突しうる（指摘 routes-19）。その名前のファイルは比較と merge の対象にならない。報告の出し方は [A6](#A6) で決めた。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D9 を推奨どおり採用）
- A4 SSH の経路の走査の時間切れは [ssh] timeout_sec から決め、時間切れのエラーは接続の時間切れと区別できる文言にする（D10）。
  - why: 120 秒に固定され、接続の時間切れと読める "SSH connection timed out (120s): サーバ名" を出していた（指摘 status_scan-11・config_cli-8）。接続の時間切れと同じ値を使うので、短く設定した利用者の大きいツリーの走査は失敗しうる。文言そのものは [A7](#A7) で実装者に委ねた。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D10 を推奨どおり採用）
- A5 走査の途中に読めないディレクトリがあるとき、どの経路でも走査全体をエラーにし、終了コード 2 を返す。root_dir がないか読めないときは、どの経路でも走査の時点で、リモートは "Remote root_dir not found: サーバ名:パス"、ローカルはそれに対応するエラーを出す。symlink のリンク先の文字列や更新時刻の読み取りの失敗も既定の値で埋めずにエラーにする。include の起点がないときだけは include の判断（[2026-10-05-quality-config.md の A1](./2026-10-05-quality-config.md#A1)）の警告して飛ばす扱いにする（D18）。
  - why: ローカルと SSH は既にエラーで止まるが、エージェントだけ欠けた一覧を完全な一覧として返していた（指摘 status_scan-1・ssh_agent-15・routes-6・ssh_agent-12）。読めないディレクトリを飛ばす案は、[REQ-scan-005](../../ir/scan/limits.md#REQ-scan-005) の不完全な一覧から書き込まない趣旨と合わない。ローカルの文言は [A7](#A7) で実装者に委ねた。
  - decided_by: 利用者（2026-10-05、品質レビューの判断 D18 を推奨どおり採用）
- A6 [A3](#A3) の UTF-8 として読めない名前のファイルは、[2026-10-05-quality-cli.md の A5](./2026-10-05-quality-cli.md#A5) の読めないファイルと同じく errors に出し、コマンドは終了コード 2 を返す。errors を持たない merge と sync は、そのファイルをそのパスの failed の項目として出す（E7）。
  - why: A3 は報告の出し方（エラーか警告か、終了コード）を決めていなかった。読めないファイルと同じに扱うと、比べられなかったファイルがあることを終了コードで見落とさない。merge と sync の出力には errors がないので、その二つでは失敗したファイルを出す既存の failed に出す。
  - decided_by: 利用者（2026-10-05、詳細 E7 を推奨どおり採用。merge と sync での出し先は、E7 と E8 の方針に沿う補足として後から書き足した）
- A7 SSH の経路の走査の時間切れのエラー（[A4](#A4)）と、ローカルの root_dir がないか読めないときのエラー（[A5](#A5)）と、merge と sync が UTF-8 として読めない名前のファイルを failed に出すときの理由（[A6](#A6)）の文言は IR で決めない。実装者が分かる英語の文言を書き、テストはその文言を固定しない（E8）。時間切れのエラーが接続の時間切れと区別できることは A4 のとおり求める。
  - why: これらの判断は文言を決めていなかった。利用者は、決めていない文言を IR に固定せず、実装に委ねることにした。A6 の failed の理由の文言は、同じ E8 の方針の補足として後から書き足した。
  - decided_by: 利用者（2026-10-05、詳細 E8 を推奨どおり採用）
