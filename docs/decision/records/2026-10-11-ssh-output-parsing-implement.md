# 名前とリンク先を読んだとおりに載せる単位の実装で決めたこと

## Context

[2026-10-12-ssh-output-parsing.md](./2026-10-12-ssh-output-parsing.md) の A2 は、エージェントの走査も「ローカルと SSH と同じく」symlink のリンク先を読めないときにエラーで止まると決めた。実装の時点で、ローカルの再帰の走査（`crates/remote-merge-engine/src/local/mod.rs` の `walk_single_root`）はリンク先を読めないとき "???" で埋めて一覧に載せており、止まっていなかった。エージェントの走査だけを止めると、ローカルとエージェントで結果が分かれる。

## Agreements

- A1 ローカルの再帰の走査も、symlink のリンク先を読めないときは "???" で埋めずに、不完全な走査のエラーで止める。計画が変えてよいファイルに入っていない `crates/remote-merge-engine/src/local/mod.rs` を変え、契約テストで確かめる。
  - why: [REQ-scan-015](../../ir/scan/listing.md#REQ-scan-015) は、どの経路もリンク先を読めなければ既定の値で埋めずにエラーで止まると既に決めている。ローカルを直さないと、エージェントの走査を止めたことでローカルとエージェントの結果が分かれる。直さない選択は、承認済みの要件に反する経路差を残すことになり、実質の選択肢にならない。文言は IR が決めておらず、エージェントと SSH の走査の不完全な一覧のエラーにそろえた。
