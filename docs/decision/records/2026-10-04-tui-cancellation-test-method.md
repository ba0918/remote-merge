# TUIマージ取消の観測方法

## Context

通常ファイルと機密ファイルのマージ取消を、実際の確認画面と宛先ファイルで検査する。
プロセスの終了だけでは、取消によって確認画面が閉じたことを直接観測できない。
PTYの出力を読まない待機は、実子プロセスが出力を書き終える前に詰まる条件を再現できる。
今回の試行では取消後の描画が差分更新となり、完成した文言が連続した出力バイトにはならなかった。
過去の取消テスト失敗の原因を、この再現だけで確定したとは扱わない。

## Agreements

- A1 通常・機密ファイルの取消テストは、実PTYの確認画面、取消前後の宛先内容、取消後の状態、独立した終了確認を検査する。
  - why: [REQ-tui-002](../../ir/tui/operations.md#REQ-tui-002) の確認と拒否時の書き込み禁止を保ち、プロセス生存を画面状態の代用にしない。[既存の移行表](../../testing/ignored-test-migration.md) の取消行が要求する実確認と宛先保護も維持する。
  - decided_by: ユーザーが承認したテスト方法改善の範囲内で実装者が具体化し、独立品質レビュー後に親担当が受け入れた。
- A2 PTYの出力は、一つのworkerが既存expectrlのセッションを所有して読み続け、後続の照合に必要なバイトを保持する。
  - why: 実子プロセスが1 MiBを書き終えてから進行ファイルを作る回帰テストで、呼出元が照合していない待機中も出力を消費する必要を検査できる。独自の端末パーサ、二重reader、黙った出力切捨てを避ける。
  - decided_by: 実装者。独立品質レビューと親担当が現行の有限producer・fixture TUIの範囲を受け入れた。
- A3 取消は既存の状態ダンプを読み、確認状態を観測してからnを送り、取消メッセージとダイアログ消失を確認する。
  - why: 実ログでは変更されたセルだけが別々のカーソル位置に書かれていた。連続した文字列の照合や断片を許す正規表現ではなく、実アプリが描画後に保存する状態で取消を観測する。状態ダンプのフィールド構成や英語文言を新たな製品要件にする判断ではない。
  - decided_by: 親担当が実ログの調査に基づき方式を承認し、実装者が適用した。
- A4 fixtureごとにキャッシュを隔離し、JSONの完成を上限15秒で待つ。PTYの照合期限もログwrapperを設定した後に15秒とする。
  - why: 一つの子プロセスが所有する新しい保存先と確認前後の遷移によって、別の実行の状態を取消の根拠にしない。観測先は子プロセスの環境と既存dirsのプラットフォーム別実装に合わせ、macOS・iOSでは所有HOME下のLibrary/Caches、その他の対象Unixでは所有XDG_CACHE_HOMEを使う。親プロセスの個人環境で保存先を解決しない。状態の欠落・未完成JSONは待機し、その他の読取りエラーは即時に報告する。expectrlのログwrapperが既定の期限でセッションを再構築するため、wrapperの前の期限設定だけでは足りない。[REQ-testing-009](../../ir/testing/methods.md#REQ-testing-009) に沿って観測対象に合う検査方法を選ぶ。
  - decided_by: 実装者。独立品質レビューと親担当が受け入れた。
- A5 このテストutilityの受入範囲は、今回の有限出力producerと現行fixture TUIに限る。
  - why: workerのjoin、読み出せる間のdrain、未照合バイトの保持には無制限producerでの上限保証がない。有限の実試行と既存依存の制御フローを根拠に現行用途を受け入れたが、任意コマンドの無制限出力や無条件の終了時間保証を検証したものではない。これは今回の受入範囲の記録であり、新たな製品方針ではない。
  - decided_by: 独立品質レビュアーの限定付きPASSを親担当が受け入れた。
- A6 作業ツリーの置き場である .agents/worktrees/ だけをGitの無視対象に追加する。
  - why: 宣言された作業場所で並行作業を隔離し、作業ツリーの内容を成果物として誤って取り込まない。個人設定の変更や .agents/ 全体の除外を避ける。
  - decided_by: ユーザーが一行の追加を承認した。
