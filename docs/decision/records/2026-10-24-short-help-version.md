# サブコマンドなしの起動の例外に、短い形の -h と -V を含める

## Context

[REQ-cli-076](../../ir/cli/safety.md#REQ-cli-076) は、サブコマンドを指定しない起動を、使い方を標準エラーに出して終了コード 2 で止め、--help と --version だけをこの扱いから除いている。
引数を読む部品は --help と --version に短い形の -h と -V を用意しており、今の製品ではサブコマンドなしの -h と -V も、--help と --version と同じものを標準出力に出して終了コード 0 で終わる（下の Verification）。
[REQ-cli-018](../../ir/cli/results.md#REQ-cli-018) は「--help か -h」「--version か -V」と書いているのに、REQ-cli-076 の字面は短い形に触れていなかった。
この記録は、REQ-cli-076 の例外に短い形を含めたことと、その根拠を残す。

Position: REQ-cli-076 の例外の文に -h と -V を足し、契約テストで短い形も確かめる（A1）。振る舞いは変えない。

## Agreements

- A1 サブコマンドを指定しない起動の扱いから除く --help と --version には、短い形の -h と -V を含める。REQ-cli-076 の例外の文を「--help か -h と、--version か -V」にし、crates/remote-merge/tests/contract/cli_usage.rs の契約テストで短い形も確かめる。コードは変えない。
  - why: 今の製品で、HOME と XDG の場所を空の一時ディレクトリにしてサブコマンドなしの -h と -V を動かすと、--help と --version と同じバイト列（1,195 バイトの使い方と、34 バイトの版）を標準出力に出し、標準エラーは空のまま終了コード 0 で終わり、診断ログの場所にも作業ディレクトリにも HOME にも何も書かない（下の Verification）。[tui-disposition の A24](./2026-10-04-tui-disposition.md#A24) が --help と --version を除いたのは、使い方と版を求める指定だからで、短い形は同じ指定の別の綴りである。REQ-cli-076 の字面のままだと、サブコマンドなしの -h と -V は終了コード 2 で止まるはずの起動に当たり、今の振る舞いと食い違う。REQ-cli-018 も --help と -h、--version と -V を同じに扱っている。
  - rejected: 短い形をサブコマンドなしの起動の扱いに入れ、-h と -V を終了コード 2 で止める（同じ指定の綴りの違いで結果を変える理由がなく、REQ-cli-018 とも食い違う）。
  - decided_by: ユーザー（-h と -V を例外に足す推奨を採った。例外の文の言い回しは書き手が書いた）

## Rejected

- R1 短い形の -h と -V を、サブコマンドなしの起動の扱いに入れて終了コード 2 で止める。
  - why: 同じ指定の綴りの違いで結果を変える理由がなく、--help と -h、--version と -V を同じに扱う REQ-cli-018 とも食い違うから。

## Verification

- cargo build で作った製品を、HOME・XDG_CACHE_HOME・XDG_CONFIG_HOME・XDG_DATA_HOME をそれぞれ空の一時ディレクトリにし、空の作業ディレクトリで、ほかの環境変数を渡さずに動かした。
  - `-h` と `--help`: 終了コード 0、標準出力は使い方（1,195 バイト、二つは同じバイト列）、標準エラーは空。
  - `-V` と `--version`: 終了コード 0、標準出力は版の一行（34 バイト、二つは同じバイト列）、標準エラーは空。
  - 四つとも、診断ログの場所（XDG_CACHE_HOME）は作られず、作業ディレクトリと HOME は空のまま。
- 契約テストに足した短い形は、コードを変えずに最初から通る。この記録は今の振る舞いを仕様に書くもので、振る舞いを変えないからである。
