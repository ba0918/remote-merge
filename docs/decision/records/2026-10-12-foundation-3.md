# 土台の段 3: 経路を事実の集め方と一つの型の失敗にする

## Context

[土台の作り直し](./2026-10-12-foundation.md) の段 3 である。経路（ローカル・SSH・エージェント）は、パスの確認・子の一覧・大きさ・読み込み・ハッシュを、それぞれ自分の規則で書いている。SSH はパスを辿る手順を POSIX sh で書き直し、失敗を文字列と既定値で返す。操作の失敗は型で決まっておらず、「ない」「読めない」「権限がない」を呼び出し側が操作ごとに読み直している。エージェントを使うか SSH に切り替えるかも、判断が一か所にない。[foundation A10](./2026-10-12-foundation.md#A10) のとおり、実装の前に、段 3 が扱う IR（パスの確認・経路ごとの操作・経路の選び方・接続断・リモートの道具）を経路によらない文に書き直す。段 2 で後回しにした「どのサーバで動くか」（[foundation A8](./2026-10-12-foundation.md#A8)。BusyBox の find だけのサーバ）もここで決める。

Position: 段 3 の方針（D1〜D12・D14・D18〜D20）と IR の書き直しを決めた。D13 で利用者に返した判断は、BusyBox の扱いを D8 に、REQ-merge-039 を D18 に、配置・起動できないときの警告を D19 に決めた。実装は [段 3 の計画](../../plans/foundation-3.md) で進める。

## Agreements

- D1 操作の失敗は、一つの型の七つの種類のどれかにする。ない（パスの最後の要素がない）・ディレクトリでない（途中の要素がディレクトリでない、またはディレクトリを求めた操作の相手がディレクトリでない）・権限がない・上限を超える（大きさが読み込みの上限を超える）・道具がない（操作に要る道具がリモートにない。道具の名前を持つ）・I/O（それ以外の失敗。OS の理由かリモートが返した理由の文字列を持つ）・接続断（[用語](../../ir/CONTEXT.md) の `接続断`。送れなかったか、応答を受け取れなかったかを持つ）。操作の結果は成功の値かこの型の失敗かで返し、Option・既定値・文字列で失敗を表さない。利用者に見える失敗の文言は、この型から一か所で作る（[REQ-paths-016](../../ir/paths/operations.md#REQ-paths-016)・[REQ-paths-020](../../ir/paths/operations.md#REQ-paths-020)）。`remote_merge::cli::*` の `execute_*` の形と出力の型は変えず、出力の失敗の理由の文字列にこの型を訳す。
  - why: [foundation A2](./2026-10-12-foundation.md#A2) の決めた種類をそのまま型にする。呼び出し側が操作ごとに意味を解釈し直していたことが、「読めない」を「ない」や「同じ」にする誤りと経路差の元だった。出力の型を変えないのは [foundation A6](./2026-10-12-foundation.md#A6) の物差しを保つためである。
  - decided_by: 利用者（[foundation A2](./2026-10-12-foundation.md#A2)・[foundation A6](./2026-10-12-foundation.md#A6) から導いた。自走の指示により書き下ろした）
- D2 三つの経路は、自分の結果を D1 の型に訳すだけにし、訳した後の扱い（止めるか続けるか、利用者にどう示すか）は経路の外の一か所で決める。訳し方は次のとおりとする。ローカルとエージェント（エージェントはリモートのマシンの上のローカルである）は同じ関数で OS の誤りを訳し、NotFound（ENOENT）をない、ENOTDIR をディレクトリでない、PermissionDenied（EACCES・EPERM）を権限がない、それ以外を OS の理由を持つ I/O にする。エージェントは訳した種類をそのまま通信で運ぶ（D9）。SSH は、リモートのスクリプトが一つのパスごとに種類の目印を出し、手元がそれを読む。目印は、シェルの `[ -e ]`・`[ -L ]`・`[ -d ]`・`[ -r ]`・`[ -x ]` で決まるものはそれで決め、決まらないとき（テストが偽で理由が分からないとき）は `ls -d` の C ロケールの文言の終わり（"No such file or directory"・"Not a directory"・"Permission denied"、それ以外）で決める。要る道具が `command -v` で見つからないときは道具がないにする。上限を超えるは経路が作らず、経路が答えた大きさと上限から一つの純粋な関数が決める。接続断は、エージェントでは要求を送れなかった・送った後の切断・EOF・読み込みの時間切れ・応答のフレームを読めない・要求と合わない種類の応答、SSH ではコマンドの終わりの状態を受け取れずにチャンネルが閉じたこと・終わりの状態を受け取ったのに答えの形が壊れている（目印が欠ける・問いと合わない）ことにする（読めない応答を接続断にすることは D20）。
  - why: 種類の規則を経路の数だけ書くと経路差の元になる（foundation A3）。`ls -dL` の文言の終わりが "No such file or directory" かどうかは、確かめた findutils の各版のサーバと BusyBox で同じに分かれる（[リモートの道具の違い](../../remote-tools.md)）。"Permission denied" と "Not a directory" は C ロケールの OS の文言で、まだサーバごとに確かめていない。揃わないと分かったら、計画の止まる条件で返す。
  - decided_by: 利用者（[foundation A2](./2026-10-12-foundation.md#A2)・[foundation A3](./2026-10-12-foundation.md#A3) から導いた。自走の指示により書き下ろした）
- D3 エージェントを使うか SSH にするかは、一つの純粋な関数で決める。入力は、サーバの sudo の指定、`[agent] enabled`、配置先の検査の結果（[REQ-ssh-014](../../ir/ssh/deploy.md#REQ-ssh-014)・[REQ-ssh-017](../../ir/ssh/deploy.md#REQ-ssh-017) に当たったか）、配置と起動の結果（起動できた・配置できない・起動できない）、接続のときに答えた通信の版が手元と同じか（[REQ-ssh-021](../../ir/ssh/fallback.md#REQ-ssh-021)）である。出力は、エージェントを使う・SSH を使う（示す警告を添える）・使わずに止める（接続のエラー、終了コード 2）の三つである。表は [TBL-ssh-001](../../ir/ssh/fallback.md#TBL-ssh-001)、要件は [REQ-ssh-024](../../ir/ssh/fallback.md#REQ-ssh-024) とする。sudo=true のサーバで `[agent] enabled` が false のときも、エージェントを使えないときと同じく止める。
  - why: 判断が経路と操作の数だけ書かれていると、一か所を直しても別の場所で切り替えの条件が違ってくる（[foundation A3](./2026-10-12-foundation.md#A3)）。sudo=true で `[agent] enabled` が false のときに止めることは、今の動き（[adopt-config-values A11](./2026-09-28-adopt-config-values.md#A11) が記録した、接続するときの "sudo = true requires agent to be enabled." のエラー）と [REQ-ssh-005](../../ir/ssh/fallback.md#REQ-ssh-005) の「使えないときは止める」が同じ向きなので、表に書き出した。
  - decided_by: 利用者（[foundation A3](./2026-10-12-foundation.md#A3) から導いた。自走の指示により書き下ろした）
- D4 経路はサーバごとに、そのサーバに初めてつなぐときに D3 の関数で一度だけ選ぶ（[REQ-ssh-010](../../ir/ssh/fallback.md#REQ-ssh-010)）。選んだ後は、操作の失敗（D1 のどの種類でも）を理由に選び直さない。接続断は [REQ-ssh-003](../../ir/ssh/reconnect.md#REQ-ssh-003)・[REQ-ssh-022](../../ir/ssh/reconnect.md#REQ-ssh-022) のとおり同じ経路でつなぎ直し（エージェントは起動し直す）、それ以外の失敗はその操作の失敗として呼び出し側に返す。起動し直せないときも SSH には切り替えずに止める。
  - why: 段 2 で走査の失敗を TreeFailed として運び、エージェントの故障と見分けて SSH に回さないようにした（[段 2 C11](./2026-10-12-foundation-2.md#C11)・[段 2 C15](./2026-10-12-foundation-2.md#C15)）。ファイル一つの失敗で経路を替えると、同じコマンドの中でファイルごとに経路が変わり、sudo の有無やリンクの扱いが混ざる。[agent-operations A10](./2026-10-11-agent-operations.md#A10)・[agent-operations A38](./2026-10-11-agent-operations.md#A38) も回の途中で切り替えないと決めている。
  - decided_by: 利用者（[段 2 C11](./2026-10-12-foundation-2.md#C11) と [agent-operations A10](./2026-10-11-agent-operations.md#A10) から導いた。自走の指示により書き下ろした）
- D5 SSH のパスの確認は、段 1 の純粋な手順（ローカルとエージェントが使うもの）に、まとめて尋ねた事実を渡す形にする。一回の問いは、確かめる途中のすべてのパスについて、手順がまだ辿っていない要素の事実を、"/" に近い方から順に尋ねる。各要素の事実は、種類（symlink・ディレクトリ・それ以外・ない）、symlink ならリンク文字列、ディレクトリなら検索できるか、ないか入れないなら D2 の目印である。スクリプトは、パスごとに symlink・ない・ディレクトリでない・検索できないに当たったところでそのパスの残りを尋ねない。手順は答えを辿り、symlink のリンク文字列を差し込んだパスだけを次の問いに回す。問いの回数は、辿る symlink の段の数に一を足したものまでになる。一回のコマンド行は、引数の長さの上限の半分（CentOS 5 の ARG_MAX 128KB から 64KB）を超えないように分ける。名前の長さ・つないだ長さ・回数の上限・UTF-8 でない部分は手順の側で決め、スクリプトは決めない。リンク文字列を読む readlink は symlink に出会ったときだけ使い、ないときは [REQ-paths-009](../../ir/paths/routes.md#REQ-paths-009) の道具がないにする。
  - why: [foundation A5](./2026-10-12-foundation.md#A5) と [段 1 B4](./2026-10-12-foundation-1.md#B4) が決めた形である。複数のパスを一回にまとめないと、merge の --dry-run が書き込む予定のパスを一つずつ確かめるときに、ファイルの数だけ往復が増える。
  - decided_by: 利用者（[foundation A5](./2026-10-12-foundation.md#A5)・[段 1 B4](./2026-10-12-foundation-1.md#B4) から導いた。自走の指示により書き下ろした）
- D6 子の一覧（[REQ-paths-017](../../ir/paths/operations.md#REQ-paths-017)）は、段 2 の走査の集め方を深さ一つにしたもので生の項目を集め、exclude と項目の値は走査と同じ規則の関数で決める。SSH は一回の find で集め、ローカルとエージェントは段 2 のこのマシンの集め方を使う。子の一覧のためだけの find の書き方とその出力の読み方は持たない。
  - why: 子の一覧は走査の一段であり、別の集め方を持つと、段 2 で消した経路ごとの規則の複製が子の一覧に残る（[foundation A3](./2026-10-12-foundation.md#A3)・[段 2 C6](./2026-10-12-foundation-2.md#C6)）。
  - decided_by: 利用者（[段 2 C6](./2026-10-12-foundation-2.md#C6) から導いた。自走の指示により書き下ろした）
- D7 大きさ・読み込み・ハッシュは、複数のパスをまとめて尋ね、答えはパスごとに成功の値か D1 の失敗を持つ。読み込みの要求は大きさの上限を運び、経路は大きさを答えて、上限を超えるものの中身を送らない。上限を超えるかは D2 のとおり一つの純粋な関数が決める。SSH は一回のコマンド行を D5 と同じ長さで分ける。ハッシュは sha256sum、なければ shasum -a 256、どちらもなければ [REQ-ssh-022](../../ir/ssh/reconnect.md#REQ-ssh-022) のとおり中身を読む。大きさは stat -L -c %s、stat が -c を受け付けなければ ls -ldn で尋ねる。エージェントは今の上限（一度に 2000 件、フレーム 16MB、中身は 4MB ずつ）でまとめる。まとめた問い全体が接続断になったときは、[REQ-ssh-003](../../ir/ssh/reconnect.md#REQ-ssh-003) のとおりまとめに入っていたパスをすべて同じ失敗にする。
  - why: [foundation A5](./2026-10-12-foundation.md#A5) のとおり、一つずつ尋ねると SSH の往復で使えない速さになる。代わりの道具は [リモートの道具の違い](../../remote-tools.md) で確かめたものだけを使う。
  - decided_by: 利用者（[foundation A5](./2026-10-12-foundation.md#A5) から導いた。自走の指示により書き下ろした）
- D8 エージェントを使わずにリモートを扱うときに要る道具を [TBL-ssh-002](../../ir/ssh/compatibility.md#TBL-ssh-002) に書き、そのサーバの条件を要件にする（[REQ-ssh-025](../../ir/ssh/compatibility.md#REQ-ssh-025)・[REQ-ssh-026](../../ir/ssh/compatibility.md#REQ-ssh-026)）。走査と子の一覧には、`-printf` と `-exec … {} +` を受け付ける find（GNU findutils 4.2.27 以降で確かめた）が要る。BusyBox の find だけのサーバでは、エージェントを使わないときの走査と子の一覧を、道具がない（find が -printf を受け付けない）誤りで止め、ほかの道具で推し量った一覧を返さない。エージェントを使えるサーバでは、BusyBox でもエージェントで扱う。誤りの文には、要る道具（-printf と `-exec … {} +` を受け付ける find）と、エージェントを使えばそのサーバを扱えることを入れる。D13 で利用者に返したこの件は、ここで決めた。
  - why: BusyBox の find（1.37.0 で確かめた）は -printf を受け付けず、段 2 の走査（[段 2 C14](./2026-10-12-foundation-2.md#C14)）は -printf と -exec … {} + で生の項目と確かめの記録を集める。ls や stat の出力から一覧を作る別の集め方を持つと、名前の TAB・改行・リンク先の扱いを経路ごとに書き直すことになり、foundation A3 に反する。エージェントは道具を使わないので、BusyBox のサーバでも同じ結果を返せる。今も BusyBox の find の走査は find の誤りで止まっており、変わるのは誤りの文言が足りない道具と代わりの手段を示すようになることだけである。
  - decided_by: Claude（対応する道具の範囲を広げると第二の集め方が要り、段 2 の集め方を一つにする方針（C6）に反するため。自走の指示により決めた）
- D9 エージェントの通信の版を 12 に上げ、操作の応答は成功の値か D1 の失敗の種類（I/O は OS の理由の文字列を持つ）を運ぶ。複数のパスの応答はパスごとに運ぶ。走査の応答（[段 2 C11](./2026-10-12-foundation-2.md#C11) の版 11 の形）は変えない。配置済みの版 11 のエージェントは、[REQ-ssh-016](../../ir/ssh/deploy.md#REQ-ssh-016) のとおり次の接続で置き直す。
  - why: [foundation A9](./2026-10-12-foundation.md#A9)・[段 1 B7](./2026-10-12-foundation-1.md#B7)・[段 2 C11](./2026-10-12-foundation-2.md#C11) が、失敗の種類は段 3 で版 12 として運ぶと決めている。今の通信は失敗を文字列で返し、CLI がファイル一つの失敗とエージェントの故障を見分けられない。
  - decided_by: 利用者（[段 2 C11](./2026-10-12-foundation-2.md#C11) から導いた。自走の指示により書き下ろした）
- D10 パスの確認が経路によらないこと（[REQ-paths-008](../../ir/paths/routes.md#REQ-paths-008)）から、SSH の二つの例外（"cannot read" に当たる失敗を存在しないことと見分けない、権限以外の理由で入れないディレクトリも "permission denied" にする）を外す。SSH も D2 の目印で "cannot read" と "permission denied" を見分ける。macOS の OS の PATH_MAX による "cannot read" は、経路ではなく OS の限界なので [FLAG-paths-004](../../ir/paths/FLAGS.md#FLAG-paths-004) に移す。[path-resolution A52](./2026-10-06-path-resolution.md#A52) の例外はこれで置き換える。
  - why: 振る舞いを変える書き直しである。[path-resolution A52](./2026-10-06-path-resolution.md#A52) は、SSH の確認が cd の成否で検索権限を決め、sh から errno を取れないことを例外の理由にしていた。D5 では検索権限を `[ -x ]` で、入れない理由を `ls -d` の文言で決めるので、その理由がなくなる。経路の差を IR に残すのは道具の限界で揃えられないと確かめたものだけにする（[foundation A10](./2026-10-12-foundation.md#A10)・[段 2 C1](./2026-10-12-foundation-2.md#C1)）。揃えられないと分かったら、計画の止まる条件で返す。
  - decided_by: 利用者（[foundation A10](./2026-10-12-foundation.md#A10) から導いた。自走の指示により書き下ろした）
- D11 `接続断` の用語を、経路の名前を挙げずに、要求を送り始めた後にその結果を受け取れなかったこと（結果を運ぶ通信が途中で切れた・壊れたことを含む）と書き直す。経路ごとの見分け方は D2 に置く。接続断の後に読み取りを一度だけやり直す規則は、[REQ-ssh-003](../../ir/ssh/reconnect.md#REQ-ssh-003) を経路によらない一つの規則にし、[REQ-ssh-023](../../ir/ssh/reconnect.md#REQ-ssh-023) はやり直しも別の経路に切り替えないことの要件にする。[REQ-ssh-022](../../ir/ssh/reconnect.md#REQ-ssh-022)・[REQ-ssh-004](../../ir/ssh/reconnect.md#REQ-ssh-004) からも経路の名前を外す。
  - why: REQ-ssh-003 と REQ-ssh-023 は、同じ規則を SSH とエージェントで二度書いていた。用語の定義に経路ごとの見分け方を書くと、IR が経路の数だけ読み方を持つ。受け取ったものを要求への応答として読めなかったことを接続断に含めるのは振る舞いを変える書き直しで、理由は D20 による。
  - decided_by: 利用者（[foundation A10](./2026-10-12-foundation.md#A10) から導いた。自走の指示により書き下ろした）
- D12 経路の名前を挙げて同じことを繰り返す文は、操作ごとに一つの「経路によらない」要件（[REQ-paths-008](../../ir/paths/routes.md#REQ-paths-008)・[REQ-paths-013](../../ir/paths/operations.md#REQ-paths-013)）にまとめ、個々の要件から「ローカル・SSH・エージェントのどの経路でも」を外す。段 3 で外すのは、パスの確認・経路ごとの操作・経路の選び方・接続断・読み込みの上限（[REQ-cli-079](../../ir/cli/size-limit.md#REQ-cli-079)）・書き込み先の操作（[REQ-merge-038](../../ir/merge/concurrency.md#REQ-merge-038)・[REQ-merge-040](../../ir/merge/concurrency.md#REQ-merge-040)・[REQ-merge-041](../../ir/merge/concurrency.md#REQ-merge-041)）の文である。REQ-merge-038 の、dd が "oflag=nofollow" を受け付けないときだけ残る競合は、道具の限界なので [FLAG-merge-021](../../ir/merge/FLAGS.md#FLAG-merge-021) に移す。コマンドの入口の検査（[REQ-cli-078](../../ir/cli/diff-output.md#REQ-cli-078)・[REQ-merge-007](../../ir/merge/symlink.md#REQ-merge-007)）、新しいディレクトリの権限（[REQ-merge-012](../../ir/merge/permissions.md#REQ-merge-012)）、diff のディレクトリの扱い（[REQ-cli-096](../../ir/cli/directory-paths.md#REQ-cli-096)）の「どの経路でも」は、振る舞いを分けておらず、その要件を扱う段 4・5 で外す。how_to_verify に書かれた今の単体テストの場所は、実装でテストが動いたときに付け替える。
  - why: [段 2 C1](./2026-10-12-foundation-2.md#C1) と同じ扱いである。同じ規則を要件ごとに繰り返す書き方は、経路ごとに実装を書く構造を写していた。段 3 の範囲の外の要件まで書き換えると、段 4・5 の合格の基準を先に動かすことになる。
