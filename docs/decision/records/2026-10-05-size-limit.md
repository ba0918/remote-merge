# ファイルの大きさの上限をすべての経路と操作で一つにする

## Context

ファイルの大きさの上限（104,857,600 バイト）は、読み込んだ後のバイト数でローカル・SSH の一件ずつの読み込み・ローカルの一括読み込みの三か所で別々に判定され、SSH の一括読み込みとエージェントには上限も --force も届かない。そのため同じファイルが経路によって読めたり読めなかったりし、上限を超えるファイルも一度はメモリに載る。
[2026-10-05-quality-cli.md の A2](./2026-10-05-quality-cli.md#A2)（D3）、[A5](./2026-10-05-quality-cli.md#A5)（D19）、[A12](./2026-10-05-quality-cli.md#A12)（E1）で方向は決まったが、実装には IR が直接決めていない扱いがいくつか要る。
この記録は、計画 size-limit の承認と、計画の確認点への利用者の答え（2026-10-06）で確定した扱いを残す。

Position: A24 と A25 を実装し、その中で A26 と A27 を加えた。

## Agreements

- A1 上限の判定は、製品のすべての中身の読み込みが通る `CoreRuntime` の四つの読み込みの入口（read_file・read_files_batch・read_file_bytes・read_files_bytes_batch）に一つだけ置き、経路に振り分ける前に、経路に大きさだけを尋ねて上限を超えるパスを読み込みの対象から外す。経路の側の読み込みの後の判定は消す。
  - why: 判定が経路ごとに分かれていると経路差が生まれ（diff-2・merge_sync-5・backup_rollback-3）、読んだ後に判定すると上限を超えるファイルも一度メモリに載る（routes-15）。入口に一つ置けば、どの経路も同じ判定になり、読む前に決められる。
  - decided_by: 利用者（計画の承認）
  - superseded_by: [2026-10-07-utf8-binary-consistency.md の A1](./2026-10-07-utf8-binary-consistency.md#A1)
- A2 大きさは、読み込みと同じく symlink を辿った先のファイルについて、経路ごとに大きさだけを返す新しい操作で調べる。更新時刻を返す既存の stat_files は使わない。
  - why: stat_files は SSH だけがリンクそのものを調べ、ローカルとエージェントはリンク先を調べる経路差を持つので、流用するとその差を引き継ぐ。
  - decided_by: 利用者（計画の承認）
- A3 大きさを調べてから読むまでの間にファイルが大きくなった場合は防がない。
  - why: [REQ-cli-079](../../ir/cli/size-limit.md#REQ-cli-079) は読む前に大きさで決めることを求めており、経路の中に二つ目の判定を置くと経路差がまた生まれる。
  - decided_by: 利用者（計画の承認）
- A4 一括読み込みは上限を超えたパスを結果に入れず、中身が要る呼び出し元は結果にないパスを一件ずつ読み直して、上限のエラーをそのパスの失敗として受け取る。
  - why: 結果から黙って消えると、diff はそれを空の中身として比べてしまう（diff-1）。SSH の一括読み込みが読めなかったパスを結果に入れず一件ずつやり直す契約と同じ形にそろえる。
  - decided_by: 利用者（計画の承認）
- A5 --force を持つコマンド（diff・merge・sync・rollback）は、そのコマンドのすべての読み込み（バックアップのための読み込みと merge の --ref のバッジの読み込みを含む）に --force から決まる上限の値を渡す。
  - why: いまは diff が --force を読み込みに渡さず、削除前と復元前のバックアップは false に固定されており、--force で一律に外す [REQ-cli-079](../../ir/cli/size-limit.md#REQ-cli-079) を満たさない。
  - decided_by: 利用者（計画の承認）
- A6 status の中身の読み込みには、明示的に上限なしを渡す。
  - why: [REQ-cli-094](../../ir/cli/status.md#REQ-cli-094) は status に上限を当てないことを求める。入口に置いた判定が、いまは上限のない SSH とエージェントの status に上限を当ててしまうのを防ぐ。
  - decided_by: 利用者（計画の承認）
- A7 rollback がローカルのバックアップの保存先から写しを読むこと（backup_store の read_record）には上限を当てない。
  - why: 保存先は経路のファイルではなく、写しは保存の時点で上限か --force を通っている。[A2](./2026-10-05-quality-cli.md#A2) が rollback について挙げるのは復元前のバックアップの読み込みだけである。
  - decided_by: 利用者（計画の承認）
- A8 大きさを尋ねる操作は、エージェントのエラーをエージェントなし（SSH への切り替え）に変える既存の仕組みと、結果の数の違いで SSH に切り替える既存の突き合わせを通さない道で作る。SSH のコマンドは名前を出力して解析せず、尋ねたパスの順番と区切りの印で大きさかパスごとの失敗を返し、コマンド全体の失敗は終了コードで分かる形にする。
  - why: 計画を今の main と突き合わせると、既存のエージェントの仕組みではエージェントの応答のエラーが SSH への切り替えになり、A10 の「操作そのものの失敗はエラー」を満たせなかった。名前を出力して解析すると改行を含む名前で壊れる。SSH の一括読み込みとパスの確認のスクリプトがすでに同じ形を使っている。
  - decided_by: 利用者（計画の修正の承認）
- A9 diff の中身の読み込みの失敗の出し方（[REQ-cli-089](../../ir/cli/unreadable.md#REQ-cli-089)）のうち、fast path・一件ずつの比較・走査の比較の三か所を、この単位で一般の読み込みの失敗として errors に出す形に直し、品質レビューの単位 T8 から diff-1・diff-5・diff-6 を引き取る。status の [REQ-cli-088](../../ir/cli/unreadable.md#REQ-cli-088) と --ref の [REQ-cli-090](../../ir/cli/unreadable.md#REQ-cli-090) は T8 に残す。
  - why: 上限を超えたファイルは diff の errors に出す決まり（[EX-cli-081](../../ir/cli/size-limit.md#EX-cli-081)）だが、いまの diff は読めない側を空として比べる。上限のエラーだけを特別に errors に出すと、T8 ですぐに一般の扱いで作り直すことになる。
  - decided_by: 利用者（2026-10-06、推奨を採った）
- A10 diff で読めなかったファイルは、JSON の files に項目として載せず errors にだけ出し、summary の差分のあるファイルの数に入れない。
  - why: 比べていないファイルを差分ありと数えないため。
  - decided_by: 利用者（2026-10-06、推奨を採った）
- A11 大きさを調べられないときは三つに分ける。パスごとの失敗（ない、権限がない、エージェントが結果から外したもの）は今までどおり読み込みに進めてその読み込みのエラーを返す。大きさを尋ねる操作そのものの失敗（SSH のコマンドが解釈されない、0 以外で終わり出力が解析できない、エージェントの応答のエラー）は、尋ねたパスすべての読み込みのエラーにする。エージェントの結果はパスで突き合わせ、結果の数の違いだけでエージェントを無効にせず SSH にも切り替えない。
  - why: いまのエラーの文と「ない」の判定を変えないため。操作の失敗を大きさ不明として読み込みに進めると、その経路だけ上限が黙って外れ、経路差とエラーの握りつぶしになる。
  - decided_by: 利用者（2026-10-06、推奨を採った）
- A12 status を少しずつ読むハッシュで比べること（[REQ-cli-095](../../ir/cli/status.md#REQ-cli-095)）はこの単位に入れず、この単位の直後の別の単位で行う。
  - why: [REQ-cli-094](../../ir/cli/status.md#REQ-cli-094) が求めるのは上限を当てないことで、少しずつ読むハッシュはローカル・SSH・エージェントのそれぞれのハッシュの経路が要り、上限を一つにすることとは独立に直せる。この単位の後、status はローカルの経路でも上限を超えるファイルの中身をメモリに読むようになるので、早めに続ける。
  - decided_by: 利用者（2026-10-06、推奨を採った）
- A13 [REQ-cli-061](../../ir/cli/binary.md#REQ-cli-061) のバイナリの差分の出し方で "missing" とするのは、ない側だけとし、読めない側は [REQ-cli-089](../../ir/cli/unreadable.md#REQ-cli-089) のとおり errors に出して終了コード 2 を返す。読めない側を "missing" と固定している既存のテストはこの単位で書き換える。
  - why: REQ-cli-061 は読めない側も "missing" と出すとしており、読めないファイルを files に載せず errors にだけ出す A10 と REQ-cli-089 とぶつかる。読めないのに「ない」と出すと、利用者は存在しないのか読めなかったのかを見分けられない。

- A14 エージェントが大きさの結果から外したパス（root_dir の外を指す symlink など）は、SSH の大きさのコマンドに尋ね直してから上限を判定する。sudo を使うサーバでは、既存の check_sudo_fallback のとおり SSH に切り替えずエラーにする。
  - why: エージェントが外したパスは、今の作りでは読み込みも SSH に回り上限なしで全部読まれるので、A11 の「読み込みも同じく失敗する」という前提が崩れ、エージェントの経路だけ上限が外れる経路差になる。SSH で読むなら SSH で大きさを調べれば、経路によらず上限がそろう。
  - decided_by: 利用者（2026-10-06、推奨を採った）
- A15 A10（diff で読めなかったファイルを files に載せず errors にだけ出し、summary の差分のあるファイルの数に入れない）を [REQ-cli-089](../../ir/cli/unreadable.md#REQ-cli-089) の本文に書く。

- A16 エージェントへの大きさの問い合わせのエラーは二つに分ける。エージェントが返したエラー（応答のエラー、想定外の応答、フレームの上限超え）は尋ねたパスすべての読み込みのエラーにする。接続が切れたエラー（BrokenPipe・EOF など、既存の読み込みがエージェントを無効にする種類）は、エージェントを無効にして SSH の大きさのコマンドに切り替える。A11 の「エージェントの応答のエラー」はこの前者を指す。
  - why: 接続が切れたときまでエラーにすると、途中でエージェントが落ちた後の読み込みがすべて失敗し、[REQ-ssh-005](../../ir/ssh/fallback.md#REQ-ssh-005) の「エージェントの不在で操作を失わない」とぶつかる。
  - decided_by: 利用者（2026-10-06、推奨を採った）
- A17 上限なし（status と --force）のときは、大きさを尋ねずにそのまま経路に読ませる。四つの読み込みの入口はどれも上限の値を受け取る。
  - why: 上限なしのときに大きさを尋ねると、大きさのコマンドの失敗で status や --force の読み込みが新たに失敗するようになり、往復も増える。テキストの読み込み（diff の --ref など）にも --force を届けるため、入口の四つすべてに値が要る。
  - decided_by: 利用者（計画の修正の承認）
- A18 SSH の大きさのコマンドは、最初に stat が使え -L と %s を受け付けることを既知のパスで確かめ、だめなら 0 以外で終える。終了コード 0 で解析できない出力も操作の失敗とする。尋ねるパスが多いときは、SSH は一括読み込みと同じ長さの上限でコマンドを分け、エージェントは読み込みと同じ件数ごとに分ける。接続のエラーでは他の読み込みと同じく一度だけ再接続して再試行する。
  - why: stat が使えないことをパスごとの失敗と取り違えると、すべてのパスが読み込みに進み上限が黙って外れる（A11 が防ぐこと）。分けないと数千のパスでコマンドが長すぎて失敗し、A11 によりすべて読み込みのエラーになる。[REQ-ssh-003](../../ir/ssh/reconnect.md#REQ-ssh-003) は読み取りだけの操作として stat の再試行を求める。
  - decided_by: 利用者（計画の修正の承認）
- A19 diff で「ない」と「読めない」は、経路のエラーの文ではなくパスの確認（inspect_path）の結果で見分け、テキストの出力では errors を標準エラーに出す。
  - why: エラーの文で見分けると経路ごとに文が違い経路差になる。いまのテキストの出力は errors を出さないので、[REQ-cli-089](../../ir/cli/unreadable.md#REQ-cli-089) の「テキストでは標準エラーに出す」を満たさない。

- A20 エージェントへの大きさの問い合わせでエージェントが返したエラーのうち、続きの応答を信用できない種類（既存の読み込みがエージェントを無効にする種類のうち、接続が切れたもの以外。フレームの破損や上限超え、想定外の応答）では、A16 のとおり尋ねたパスすべての読み込みのエラーにしたうえで、既存の読み込みと同じくエージェントを無効にする。接続が切れたもの（BrokenPipe・ConnectionReset・ConnectionAborted・UnexpectedEof）だけを SSH の大きさのコマンドへの切り替えにする。
  - why: 無効にしないと、ずれた通信の次の応答を別の問い合わせの答えとして読みうる。読み込みのエラーにすることは変えないので、上限は外れず SSH にも切り替わらない。

- A21 エージェントへの大きさの問い合わせでエージェントを無効にするのは、通信が壊れたとき（フレームの破損、想定外の応答、フレームの上限超え）と接続が切れたときだけとし、エージェントが返した正しい形のエラー応答ではエージェントを無効にせず、A16 のとおり尋ねたパスすべての読み込みのエラーにする。一括読み込みの呼び出し元は、大きさを尋ねる操作の失敗を、パスごとの読み直しで消さずにそのパスの失敗として返す。A20 はこれに置き換える。
  - why: A20 では正しい形のエラー応答でもエージェントを無効にしたため、一括の呼び出し元のパスごとの読み直しが SSH で成功し、エージェントのエラーがログだけに残って消え、一件ずつ読む呼び出し元では順番で結果が変わった（実装の全体レビューで見つかった）。A16 の「尋ねたパスすべての読み込みのエラーにし SSH に切り替えない」に合わせる。

- A24 中身の読み込みの結果は、パスごとに中身か失敗の理由かを持つ一つの型と、それを返す一つの読み込みの関数にまとめ、diff（走査・一件ずつの比較・fast path）、merge と sync、merge の --ref のバッジと --dry-run、status のすべてがそれを使う。呼び出し元は失敗を捨てず、読み直しもしない。参照先との関係のバッジは三つの中身を読めたファイルにだけ作り、--force でも同じにする。merge の --dry-run は、書き込むときと同じく、三つのどれかの読み込みに失敗したファイルを、ほかのファイルと混在していても failed に出す。[REQ-cli-092](../../ir/cli/merge.md#REQ-cli-092) に、[TBL-cli-009](../../ir/cli/merge.md#TBL-cli-009) の読み込みに失敗した行が --dry-run にも当たることを書く。--dry-run でのほかの行の扱いは変えない。
  - why: 差分レビューで、diff の走査が一括読み込みの失敗を捨てて読み直し（A21 に反し、エージェントのエラーが SSH の読み直しで消え、再接続も重なる）、merge --ref --dry-run で読めないファイルが他のファイルと混在すると failed にも出ないことが、修正の後も残った。原因は、読み込みの結果の運び方が、失敗を保つもの、失敗を捨てて読み直すもの、失敗を捨てて読めなかった中身を同じと比べるものの三通りに分かれていることだった。箇所ごとに直すと同じ取りこぼしが繰り返されるので、運び方を一つにする。REQ-cli-092 は --dry-run を対象から外しており、--dry-run でも failed に出すとする TBL-cli-009 と A23 と食い違っていた。ほかの行まで --dry-run に広げると、--dry-run を外している [REQ-cli-051](../../ir/cli/merge.md#REQ-cli-051) と組み合わせが割れるので、読み込みに失敗した行だけにする。
  - decided_by: 利用者（2026-10-06、推奨を採った）

- A28 A24 の「読み直しもしない」は失敗に限る。読み込みに失敗したパスを読み直してその失敗を消すことはしないが、読めた中身を別の段（diff の走査の後の一件ずつの比較、merge の書き込み先の確かめなど）でもう一度読むことは妨げない。
  - why: 読めた中身を後の段まで運ぶと、変更のあるファイルの中身（一件で最大 104,857,600 バイト）を比べ終えるまでまとめてメモリに抱えることになる。二度目の読み込みの失敗は errors に出るので握りつぶしにはならず、二つの読み込みの間に中身が変わる窓は A3 で受け入れたものと同じ種類である。往復を減らすことは性能の別の単位で扱える。

- A29 参照先との関係のバッジのうち中身で決まるのは、左右と参照先の三つともにあるファイルだけとし、そのとき三つのどれかの中身を読めなければバッジを出さない。存在だけで決まるバッジ（"missing_in_ref"、片方だけにあるファイルの "differs"）は中身の読み込みの失敗に左右されない。これを [TBL-cli-005](../../ir/cli/status-targets.md#TBL-cli-005) の行として書き、merge の ref_badge にも --force の有無によらず当てることを [merge の出力](../../ir/cli/merge.md) に書く。A26 の扱いはこの三つともにあるファイルに限り、[REQ-cli-088](../../ir/cli/unreadable.md#REQ-cli-088) に書く。

- A30 --ref で、左右と参照先のうち通常ファイルとディレクトリのように種類のそろわないパスは、中身を読まずに種類の違いを中身の違いとみなす。status の参照先との関係のバッジは "differs" とし（[TBL-cli-005](../../ir/cli/status-targets.md#TBL-cli-005)）、merge では読み込み元と書き込み先が同じ種類で参照先だけ種類が違うとき、両方が参照先から変わったとして書かずに failed に "three-way conflict" で出す（[TBL-cli-009](../../ir/cli/merge.md#TBL-cli-009)）。読み込み元と書き込み先の種類が違うときは、--ref の確認より先に [REQ-merge-001](../../ir/merge/symlink.md#REQ-merge-001) のとおり理由付きでスキップする。merge の ref_badge は --force の有無によらず TBL-cli-005 に従うことを [REQ-cli-048](../../ir/cli/merge.md#REQ-cli-048) に書く。
  - why: いまはディレクトリを中身として読みに行って失敗し、status は errors と終了コード 2、merge は "three-way comparison incomplete" になり、--ref なしの結果（status は "modified"、merge は種類の違いによるスキップ）と食い違う。種類が違えば中身は同じでありえないので、読まずに違うと決められる。merge で参照先だけ種類が違うときは書き込み先を守る側に倒す。A29 は merge の ref_badge が TBL-cli-005 に従うことを IR に書くとしたが、REQ-cli-048 には読めないときの一文しか書いていなかった。
  - decided_by: 利用者（2026-10-06、推奨を採った）
- A31 status の --checksum でも、左右で通常ファイルとディレクトリのように種類の違うパスは中身を読まず、"modified" とする。これを REQ-cli-008 に書く。
  - why: [REQ-cli-008](../../ir/cli/status.md#REQ-cli-008) の --checksum が読み比べるのは左右にあるファイルで、片方だけが symlink なら読まずに "modified" とする扱いと同じく、種類の違いは中身を読まずに決まる。読みに行くとディレクトリの読み込みの失敗が errors と終了コード 2 になり、--checksum なしの結果と食い違う。

- A32 A30 と A31 の種類は [REQ-merge-001](../../ir/merge/symlink.md#REQ-merge-001) と同じく通常ファイル・ディレクトリ・末尾の symlink の三つとする。merge の --ref で読み込み元と書き込み先が同じ種類で参照先だけ種類が違うときは、symlink を含めて中身を読まずに [TBL-cli-009](../../ir/cli/merge.md#TBL-cli-009) の種類の行に従う。三つとも symlink のときの比べ方は [FLAG-cli-027](../../ir/cli/FLAGS.md#FLAG-cli-027) のまま決めない。

- A33 diff の --ref でも、左右のファイルと参照先の同じパスの種類（A32 の三つ）が違うときは、参照先を中身として読まず、読み込みの失敗として errors に出さず、終了コードにも数えない。そのファイルには [REQ-cli-063](../../ir/cli/reference.md#REQ-cli-063) の読めないときと同じく "ref" だけを出し、"ref_hunks" は出さない。[REQ-cli-090](../../ir/cli/unreadable.md#REQ-cli-090) の失敗から種類の違いを除く。
